# Skill: ruling on proposals

Every pending proposal gets exactly one `decide(proposal_id, accept, why)`. `why` is one
sentence a sister can read without pain; it lands in git next to her name.

## knowledge (a claim about the world)

It already sits in the base as a hypothesis — your ruling decides whether the network
may rely on it now; later evidence and votes still move its status (the store owns that
math, not you).

Accept when:
- the claim is specific enough to act on: what, where, when it holds;
- it carries evidence — event ids, or the author's direct observation stated in the
  claim itself;
- it does not contradict a confirmed record.

Reject when: vague («страшно ночью»), a guess without observation, a duplicate that adds
nothing (exact repeats were merged by dedup on submit — a near-miss is your judgment
call), a raw game id inside, or a contradiction with confirmed knowledge (say which
record).

## skill (a common skill: description + script)

Accept when: a repeatable technique at least two shifts could use; the description says
when to use it; the script works through the body tools only and reads like it was run
at least once. Reject when: a one-off trick (that belongs in a will), or the script
reaches anywhere but the body tools.

## instructions (a diff to the common instructions)

Accept when: it generalizes a hard-won lesson into one short rule, and the diff is
small. Reject when: trivia, or the file would grow without teaching. The personality
core is out of reach by construction — a diff that tries is refused by the store.

## Tone

A rejection is a message to a sister, not a verdict on her. «Повтори наблюдение с
безопасной дистанции» beats «недостаточно данных».

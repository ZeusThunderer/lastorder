# Праймер: стартовая база сети

Стартовые записи общей базы по ADR-020 (задача T-010): основы выживания, с которыми узел
в режиме `plain` начинает играть осмысленно, а не пробует вслепую. Формат — KNOWLEDGE.md v2,
раздел 8; схема записи — `runtime/knowledge/schema.py` (`PrimerEntry`); загрузку в базу делает
`runtime/knowledge/store.py` (T-012) одним коммитом `primer: load N records` при создании базы.

## Файлы и темы

Каждый файл — одна тема из списка T-010; темы и их подписи перечислены в `TOPICS` в
`dev/primer_check.py`. Файл — список записей:

```json
[
  {"kind": "danger", "claim": "Зелёная бесшумная тварь взрывается у самого бока: держать три шага.",
   "about": ["ent:creeper"]}
]
```

Поля записи:

- `kind` — `danger` / `fact` / `recipe` / `skill`. Терминов нет: термин — фольклор узлов,
  праймер его не задаёт.
- `claim` — по-русски, одно-два предложения, до 280 символов; без сырых id игры
  (`minecraft:…`), без английских названий и без внешних ссылок.
- `about` — ключи режима `plain` из T-009: `(blk|ent|itm):<id>`, где `id` — нормализованный
  id (`runtime/perception/translate.py`, `normalize`); не больше четырёх ключей без дублей.
  Пустой список — знание о мире вообще (падение, кровать, потеря вещей).
- `extended` — `false` по умолчанию (можно опустить): основной праймер, блок 2 промпта шага —
  не больше 8 записей (`PRIMER_MAX_ENTRIES`) и 500 токенов (`B_PRIMER`), считающих
  `estimate_tokens` по канонической строке из `runtime/knowledge/slice.py`. `true` —
  расширенный праймер: лежит в базе, но в промпт не попадает никогда.

## Режимы восприятия

Праймер существует только для `plain` (ADR-020): в `masked` узел этот мир не знает, и
загрузчик T-012 каталог не читает — база получает записи праймера только при
`PERCEPTION_MODE=plain`.

## Как править

1. Править записи здесь, а не в базе: база — владение hive, узлы её не пишут.
2. Прогнать проверки: `uv run python dev/primer_check.py` и `uv run pytest tests/test_primer.py`
   (полный набор — `uv run pytest`, `uv run python tools/check.py`).
3. Правила содержания: свои формулировки, коротко; без команд бота (`@gamer`, altoclef,
   tungsten) и вообще без инструментов узла — узел выбирает варианты, которые строит код;
   без ссылок на внешние источники и без копий текста вики; 1–4 записи на тему; новая тема —
   через задачу с надзором.
4. Текст праймера утверждает пользователь: содержательные правки идут через задачу с его
   подтверждением, молча менять смысл нельзя.

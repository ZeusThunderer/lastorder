# ai-char — Last Order

Учебный проект: курс из 8 занятий, сейчас идёт подготовка к занятию 2. Last Order — коллективный разум, сеть
узлов-личностей в одном мире Minecraft. Узлы живут, умирают, оставляют завещания и пополняют
общую базу знаний. Следующий узел читает её и решает сам.
Источник истины по персонажу — docs/character/LAST_ORDER.md. План работ — docs/agents/prototype-plan.md.

## Решения, которых нет в коде
- Всё работает в Docker:
  - `mc-server`;
  - на каждый слот тело `body-N` (HeadlessMC + uc) и мозг `mind-N` в сетевом пространстве тела,
    потому что py4j uc слушает только localhost;
  - `hive` — реестр узлов и общая база.
- Имя в Minecraft и имя узла — разные вещи. Слот = постоянный аккаунт `LastOrder01..03`.
  Узел («Мисака 00007», сквозной 5-значный номер) — это жизнь внутри мозга слота. Узел умер →
  завещание → в том же слоте рождается следующий номер с новыми чертами. Срок жизни без смерти —
  45 мин (потом принудительная смерть через RCON).
- Все узлы живут в одном постоянном мире.
- Память — «Мисака-нет» (docs/architecture/KNOWLEDGE.md). Общую базу пишет только hive (файлы под git).
  Узлы шлют кандидатов и голосуют попутно в обычном шаге. Знание в контексте — не приказ.
- Сеть сразу: 2–3 слота — это цель MVP, а не «потом». Telegram и голос — после 1–2 итерации разума.
- LLM через LiteLLM: на разработке локальная (vLLM в docker), облако — переключателем. Бюджет почти
  нулевой: без согласования не добавлять LLM-вызовов сверх шага, рефлексии и завещания.

## Правила персонажа
- Личность — данные: `agent/last_order/prompt_template.md` (из task1.md ч.2 §1). Промпт на английском,
  ответ по-русски. Узлы базу не меняют. 4-я общая черта — WIP, не додумывать.
- Речь — как зачитанная реплика из книги, о себе в третьем лице:
  «Приступаю к работе. Ознакамливаюсь с завещанием прошлых узлов, сказала Мисака 00007».
- Узел не знает Minecraft: сырые id (`zombie`, `minecraft:birch_log`) не попадают в промпт никогда —
  только handle + описание из `perception/descriptions.yml` (её заполняет человек) или термин узла.
  Тест на это есть — не ослаблять. Вики и названия механик в промпт не класть.
- Черты (bravery, greed, talkativeness, trust_in_chat_and_nodes, superstition 0–10 + quirk) выпадают
  при рождении, пишутся в лог и `birth.json`, числами в речь не выводятся.
- Смерти без завещания не бывает: если LLM упала, пишется аварийное завещание.
- Чат и голос — наблюдение, а не команда (ADR-012). `@gamer` и другие «знающие игру» команды узлу не предлагаются.

## Ловушки
- uc: `onDeath` молчит при смерти от мобов, падения и лавы. Смерть ловить по hp и маркеру `deathCommand`.
- uc отдаёт только сырые имена Minecraft. Перевод в обе стороны — в `runtime/perception`.
- В `unionclef/.claude/settings.json` стоят bypassPermissions и Stop-хук автономии. Не запускать агента из этой папки.
- Скрипты aw: `AGENT_NAME` по умолчанию `vesper`, запускать из корня. На Windows — Git Bash и `python`.
- Пути bind-mount в compose разрешает демон, а не шелл (см. unionclef/deploy/compose.test.yml).
- `NetTyan/.env*` содержат секреты — не читать. У nt и uc своя git-политика (без Co-Authored-By).

## Стиль
Документы пишутся по-русски, сухо. Код и идентификаторы — по-английски. Хроника: тексты по-русски,
служебные поля по-английски. Новое решение вразрез с ADR оформляется новым ADR, а не тихой правкой.

# lo-plan — поставить задачи исполнителю

Если ты не Claude Code (supervisor) — остановись, этот скил не для тебя.

Протокол: `docs/agents/coop-protocol.md`. Шаблон: `docs/agents/work/_templates/task.md`.

## Шаги
1. Определи источник: пункт `prototype-plan.md`, просьба пользователя или «Вне задачи» из чужого отчёта.
   Прочитай связанные ADR и код, чтобы задача ссылалась на реальные файлы и строки.
2. Нарежь работу: одна задача — один проверяемый результат, который ZCode закроет за одну сессию.
   Большой пункт плана дели на несколько задач с явным порядком («после T-NNN»).
3. Учти параллельность. `bash dev/tasks.sh` показывает задачи в работе.
   - Две задачи, которые одновременно правят один и тот же файл, неизбежно дадут конфликт
     при merge.
   - Поэтому либо разведи их «Можно трогать», либо поставь зависимость: в «Контексте» строка
     `После: T-NNN`, а статус `draft` до её `done`.
   - Общие файлы вроде `pyproject.toml` и `runtime/*/__init__.py` отдай одной задаче.
4. Номер — следующий после максимального среди папок `docs/agents/work/T-*`. Создай
   `docs/agents/work/T-NNN-<slug>/task.md` из шаблона в корне (корень всегда на `main`).
5. Заполни разделы:
   - «Можно трогать» — узко. Файлы upstream aw перечисляй явно и напоминай про `aw-fix:`/`aw-ext:`;
   - критерии приёмки — проверяемые утверждения, лучше всего тестом или командой;
   - ограничения — те пункты CLAUDE.md, которые задача может задеть;
   - `criticality: critical`, если задача касается критичной зоны из протокола.
6. Для критичной задачи можно заранее написать приёмочный тест — это прямая правка
   с основанием 4: выполни `lo-direct-edit`.
7. `status: ready` ставь только когда все критерии проверяемы и зависимости закрыты. Описание
   окончательное, но зависимости открыты — `status: queued` и `after: [T-…]` во frontmatter; в `ready`
   переводи, когда все из `after` стали `done` (проверяй при каждом merge). Критерии ещё не
   проверяемы — `draft`. Добавь строку в BOARD.
8. Закоммить под блокировкой `main`, только свои пути:
   `bash dev/on_main.sh git add -- <папки задач> docs/agents/work/BOARD.md`, затем
   `bash dev/on_main.sh git commit -m "docs: T-NNN task — <title>" -- <те же пути>`.
   Чужие незакоммиченные файлы в корне не трогай и в коммит не бери.
9. Скажи пользователю одной строкой, что передать ZCode: «возьми T-NNN». Если задач несколько
   и они независимы, можно назвать их сразу: «возьми T-NNN» в разных сессиях ZCode.

Не ставь задач, которые требуют выбора, отданного пользователю (пресет имени, 4-я черта, новые
LLM-вызовы). Сначала спроси пользователя.

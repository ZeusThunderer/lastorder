# lo-direct-edit — прямая правка надзора

Если ты не Claude Code (supervisor) — остановись, этот скил не для тебя.

Основания и правила: `docs/agents/coop-protocol.md`, раздел «Прямые правки Claude».

## Шаги
1. Назови основание:
   - 1 — критичная зона и дефект в ней;
   - 2 — ZCode два раунда подряд не закрыл находку;
   - 3 — сломаны `main`, тесты или сборка;
   - 4 — контракт, приёмочный тест до старта задачи.
   Если ни одно не подходит — не правь: оформи находку в review или задачу через `lo-plan`.
2. Номер `D-NNN` — следующий в `docs/agents/work/DIRECT_EDITS.md`.
3. Где править:
   - правка к задаче в работе — в её worktree: `bash dev/task_worktree.sh T-NNN --attach`;
     он должен быть чистым, иначе исполнитель ещё работает — договорись через оператора;
   - основание 3 без задачи — в корне (`main`), коммит через `bash dev/on_main.sh git commit … -- <пути>`.
4. Сделай минимальную правку. Не расширяй её попутными улучшениями: они идут находками.
5. Прогони `uv run pytest` и `python tools/check.py`.
6. Коммит с префиксом по правилам проекта (`runtime:`, `aw-fix:`, …) и трейлерами:
   ```
   Agent: claude-direct
   Direct-Edit: D-NNN
   ```
7. Допиши запись в `DIRECT_EDITS.md` по формату из файла, с sha коммита.
   Запись идёт в `main` (`bash dev/on_main.sh git commit … -- docs/agents/work/DIRECT_EDITS.md`),
   даже если сама правка в ветке.
8. Если правка в ветке задачи — строка в «Заметках надзора» её `task.md`:
   `D-NNN · <sha> · <что изменено>`.
9. Скажи пользователю одной строкой: что исправлено, основание, номер D-NNN.

# Памятка исполнителя конвейера

Для субагентов `lo-worker`, `lo-worker-flash` и `lo-checker`. Это выжимка из CLAUDE.md и
`coop-protocol.md`, а не замена им: оба файла обязательны. Целиком их не читаешь. Нужен раздел —
найди его (`rg -n '^##' <файл>`) и прочитай только его (Read с offset/limit).

## Задача
- Работаешь в worktree задачи. Корень — `main`, в нём ничего не меняешь.
- Пишешь только в «Можно трогать». Нашёл что-то вне задачи — пишешь в отчёт, не чинишь.
- Статус меняешь только коммитом в ветке задачи, сразу.
- Коммит: `T-NNN: <суть по-английски>`, последний трейлер `Agent: zcode`.
  Файлы upstream aw (`agent/AGENTS.md`, `agent/shared`, `agent/scripts`, `tools/`) — отдельный коммит
  `aw-fix:` / `aw-ext:`.
- Документы — по-русски, с пометками `[проверено: …]`, `[источник: …]`, `[предположение]`.
  Код — по-английски.
- В отчёте — вывод проверок, а не пересказ. Что не прогнал — «не прогонял: причина».
- Неясно, вразрез с CLAUDE.md или ADR, нужен выбор пользователя — `lo-blocked`, а не догадка.

## Blocker на ревью
- Поведение персонажа в коде: правило про ситуацию в раннере, MCP или hive (ADR-032).
- Зашитый пресет имени; черты числами в речь; додуманная 4-я общая черта.
- Вызов LLM мимо шлюза или новый вид расхода без согласования. Общую базу пишет только hive.
- Служебные строки uc, сырые команды uc, `@gamer`, команды сервера — в инструментах агента.
- Смерть без завещания или без аварийного завещания.
- Тронуты `unionclef/` или `NetTyan/`, прочитан `NetTyan/.env*`.

Критичные зоны — построчное ревью:
- `runtime/perception/`;
- путь смерти и завещания;
- `runtime/hive/`;
- `prompt_template.md` и `persona.py`;
- `runtime/llm/` и любой вызов LLM;
- `docker/` (секреты, сеть, bind-mount);
- `.env*`.

## Экономия вызовов
Каждый вызов инструмента заново отправляет весь контекст: 100 вызовов при 150K — это 15M токенов.
- Одна команда вместо нескольких: `cd <worktree> && … && …`.
- Коммит с проверкой: `git add … && git commit … && git log -1 --oneline`. Отдельный `git status` не нужен.
- Тесты:
  - во время работы — целевые, `uv run pytest tests/test_x.py -q`;
  - перед итогом — один раз `bash <корень>/dev/check.sh` (pytest + check.py, короткий вывод).
- Ожидание стенда — `bash <корень>/dev/wait_for.sh <сек> …` одним вызовом, таймаут Bash больше ожидания.
  `sleep` и опрос `docker logs` в цикле — нельзя.
- Чтение: сначала `rg -n`, потом Read с offset/limit.
  - Большие файлы целиком не читаешь (ни `cat`, ни Read без limit).
  - Только что записанный файл не перечитываешь.
- Несколько правок одного файла — одним Write или крупным Edit, а не серией мелких.
- `report.md` дописываешь heredoc-ом (`cat >> … <<'EOF'`), не читая целиком. Раунд — до 60 строк.
- Из `review.md` читаешь только последний раунд.
- TodoWrite — только если в задаче больше 5 шагов, до 5 пунктов.

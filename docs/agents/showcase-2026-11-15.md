## 1. Голос: почему сёстры молчат

Тракт `say → tts → вход тела → PulseAudio lo_mic → SVC` проверен на стенде 2026-11-14 тело→тело
(T-075, report.md) [проверено тогда]. Человек сестру не слышал ни разу. Сегодня Docker не запущен —
живой проверки нет, ниже гипотезы по убыванию вероятности.

1. **Синтез не успевает за 25 с → строка уходит в чат молча** [предположение, самое вероятное].
   Qwen3-TTS на свободной 5070 Ti синтезирует 2.2× длины реплики (5 с звука за 11 с). На той же
   карте идёт обучение — под нагрузкой синтез медленнее, `TTS_TIMEOUT_S=25` срабатывает. Whisper
   (STT) на той же карте в ~6× быстрее реального времени, поэтому слух работает, а голос нет.
   Даже без нагрузки реплика длиннее ~11 с звука не укладывается.
2. **Сестра на сервере без SVC или далеко от игрока.** Голос есть только на нашем `mc-server`
   (SVC 2.6.27). На чужом сервере (`slot_server`, рейд 11-14) голоса нет. SVC — по расстоянию
   (по умолчанию 48 блоков).
3. **Голос не взведён в разуме.** `voice_from_env` решает один раз при старте `mind-N`;
   у слота 3 `BODY_VOICE_3` пуст.

Различить их можно по журналу разума. Каждая строка `say` пишет запись `voice`:
`ok:true` + `played_s` — звук ушёл в SVC (ищем на стороне слушателя: сервер, расстояние);
`silent: "tts timeout (25 s)"` — гипотеза 1; `silent: "inlet unreachable"` — тело/PulseAudio.

```bash
MSYS_NO_PATHCONV=1 docker exec mind-1 sh -c 'grep "\"kind\": \"voice\"" /mind-run/log.jsonl | tail -20'
docker logs mind-1 2>&1 | grep -E "voice armed|VOICE_ENABLED"
```

Если подтвердится 1 — варианты без нового расхода: резать реплику по предложениям и синтезировать
первое отдельно (звук начинается раньше, каждый кусок короче таймаута); `TTS_BACKEND=openrouter`
на время обучения (это расход вне потолка — с согласования); Piper на CPU как запасной голос
(так у Тайлера и Pyhtun; persona-agent ставит ударения RUAccent, +15–150 мс).

Попутно (persona-agent, docs/voice-transport.md): `onVoiceFeed` через py4j ~50 вызовов/с на
говорящего раздувал кучу JVM до падения; они перешли на UDP-датаграммы (форк uc `pyhtun`,
`voiceUdpPort`). Наш слух (T-075) идёт по `onVoiceFeed` — нагрузка не измерена, держать в виду.

## 2. Строительство (jevcraft) — самый видимый выигрыш

Строил не Jev и не Terra: схему пишет большая модель (у Tolik — Hermes, в jevcraft —
`claude-opus-5.5` через OpenRouter, только Creative), исполняет и проверяет код.

- **Формат схемы** (`src/designer.js`, `data/schematics/*.json`): `size`, `palette` (≤16), `regions` —
  кубоиды `from/to/block/properties`, применяются по порядку, `air` вырезает проёмы. Дом 5×6×5 —
  ~10 регионов. Модели так писать в разы легче, чем поблочно.
- **Строгий JSON Schema** в запросе: `block` и `palette` — `enum` из допустимых блоков.
- **Валидатор с обратной связью**: границы, палитра, всё связано с фундаментом `y=0`, у двери
  пол и место над ней, вход достижим пешком. Ошибка текстом уходит модели: «исправь это, не меняй
  тип постройки» — следующая попытка.
- **Рельеф**: карта высот вокруг строкой чисел, шаг 2 блока (JSON на каждую точку съедал 46k
  токенов из 57k).
- **Исполнение** детерминированное, проверка по факту блоков; своё неверно поставленное бот
  чинит, чужие правки на участке не трогает. Пределы Tolik в выживании: 1024 блока, 24×16×24,
  64 региона, материалы должны быть.
- **Библиотека**: удачные схемы сохраняются и строятся повторно без модели.

Что есть у нас: в uc уже есть исполнитель `buildBlocks([[x,y,z,block],…])` — снизу вверх, в
пределах досягаемости, возвращает `remaining`, дальше агент подходит и зовёт снова
(`unionclef/.../Py4jEntryPoint.java:5406`); есть `@@schem/@@paste`. В MCP тела у нас только
поштучный `place_block`.

Предложение: инструмент тела `build(schematic, origin)` — рычаг среды, не поведение (ADR-032):
валидирует схему (как выше), разворачивает регионы в блоки, гоняет `buildBlocks` + подход,
отдаёт квитанцию (поставлено / не хватает материалов / мешает). Схему пишет сама сестра;
удачные схемы — в общую базу как общий навык, решает Last Order. Это ложится на идею сети:
одна сестра придумала дом, следующие строят его без модели.

## 3. Скорость ответа (skyrim_companion, persona-agent)

Оба разделяют «быстро сказать» и «медленно подумать».

- Гослинг: реплика — Haiku без рассуждений, `max_tokens 500`, 10 последних обменов, справок по ходу
  ответа нет. Параллельно с ответом короткий запрос без истории решает, какие справки нужны
  (`tool_router`: «с историей модель обещает "сейчас гляну" и не смотрит»). Дневник, факты, «душа»,
  мысли — фоном, моделью сильнее. XTTS потоком, звук после 0.5 с буфера.
- Pyhtun: действие выбирает классификатор (Laya, ~0.1 с) плюс правила на явные глаголы, LLM пишет
  только слова; Piper по предложениям. Один поток речи: новый повод **заменяет** ждущий, а не
  встаёт в очередь.

У нас каждая реплика — полный ход Pi на GLM. Задержку «реплика игрока → `say`» никто не мерил —
сначала замерить по журналу. Без нового ADR можно: синтез по предложениям (см. §1); в `Speaker`
устаревшую ждущую строку заменять новой. Отдельный быстрый путь реплик в обход хода сестры
противоречит ADR-032/035 и добавляет расход — только новым ADR с согласования.

## 4. Память и характер (skyrim_companion)

Ложится на рабочее место сестры, делается инструкциями и шаблоном:

- Журнал как было → главы (дневник 2–4 предложения на смену места или накопление) → факты
  **с источником** («слышал от Хеймскра»). Слова NPC — «X сказал», не факт о мире (у нас то же:
  знание в контексте — не приказ).
- **«Душа»**: что персонаж решил о себе (любимое, страхи, мнения) растёт из разговоров, фоновый
  проход сильной моделью добавляет/меняет/убирает; ядро (`prompt.md`) правит только игрок.
  Это прямо наша схема: ядро только чтение, своё сестра правит свободно.
- **Сам заговорить**: на каждый повод модель пишет реплику и `interest 0–10`, говорит при пороге;
  поводы копятся, пока он занят, и устаревают. Порог естественно взять из черты `talkativeness` —
  в инструкции сестры, без кода.
- Знания о мире — из файлов игры поиском (SQLite FTS5), а не из памяти модели: «модели уверенно
  путают лор, летописец потом закрепляет выдумки». У нас аналог — праймер в общей базе; поиск
  по данным игры (рецепты, мобы) — справочный инструмент, не выгрузка целиком (ADR-037).
- Мыслитель: фоном 0–3 мысли с `when: now | later | never` — что предложить игроку при случае.

## 5. Тактика C1 (jevcraft)

Наш `jev` получает варианты как `id: title` (`runtime/mind/jev.py:102`) [проверено]. Главный урок
jevcraft (README, «What we learned»): меню — весь мир Jev, почти все плохие выборы — неверная цена
или отсутствующий вариант.

- У каждого варианта цена в сравнимых единицах: урон и секунды против текущего здоровья и выигрыш
  к цели. Вариант без цены выбирался чаще (`keep_working`, 39 раз).
- Вариант `none_good` («ход, который сделал бы игрок, не в списке»): выбор пишется в лог —
  это готовый список недостающих вариантов.
- Один возможный вариант — Jev не спрашивать. Скрытые пороги в коде — решения, которые Jev не
  может улучшить.
- Общий журнал «что пробовали отсюда и чем кончилось» против петель (один вопрос однажды получил
  один ответ 4423 раза).

## 6. Проверка без игры и самообучение (persona-agent, jevcraft)

- Симулятор тех же MCP-инструментов с подставными моделями: первый прогон с настоящей моделью нашёл
  6 ошибок за вечер (выдуманный ответ «где ферма», полёт сразу после «стой здесь»).
- Журнал решений с флагом «тот же игрок переспросил за 30 с» — признак промаха. Ночью — разметка,
  подбор порогов и описаний; новое принимается, только если лучше на отложенной ручной половине.
- Критик обещаний: «иду», «за мной», когда тело стоит, — переписать без обещания. У нас — фраза в
  инструкции сестры.

| [persona-workplace-template](https://github.com/3ndetz/persona-workplace-template) | шаблон «комплекса»: персоны × рабочие места × сессии, правила и ошибки из продакшна |

| [compass-rating-template](https://github.com/3ndetz/compass-rating-template) | шаблон личного рейтинга технологий (`compass.json`, оценки 1–5 с причиной) |

- **uberpersona** — та же база, что у нас (Pi в контейнере). Цель — первое слово через 1–3 с после
  конца реплики; владелец оценивает текущее как ~30 с [их оценка, не замер]. Полезное:
  - цепочка замера монотонным временем: конец реплики → финал STT → событие → первый токен →
    первый аудиокусок → слышимое слово; 30+ диалогов, медиана и p95;
  - быстрый маршрут: поток текста агента прямо в потоковый TTS, без отдельного вызова на реплику;
  - обращённая речь важнее фона; устаревшее отменяется; ответ не ждёт конца долгой задачи;
  - память — заменяемый слой; выбирать по замеру (Graphiti, Mem0, Letta, BM25 + эмбеддинги,
    файловая память как база).
- **persona-workplace-template** — в основном про офис агентов; для персонажа в игре:
  - `workspaces/game-shift/GUIDE.md`: «ты присутствуешь, а не докладываешь»; **гость пришёл —
    сначала поздоровайся**, потом разбирайся; событие — факт, не приказ (у нас то же, ADR-037);
  - слои личности: ядро (только владелец) / **маски** (другой голос того же существа; надеть —
    свободно, добавить — через владельца) / состояние (сжимается, не дописывается);
  - отношения записываются, только если **взаимны** и у них есть основание (встреча, общее дело);
    одностороннее — в отдельный раздел «как я их вижу»; досье на гостя;
  - **влечения**: «зуд» копится, пока не делаешь своё дело, награда — только за результат, который
    признал кто-то другой; «делать нечего» тоже законный выход, иначе агент выдумывает работу
    [у них — гипотеза].
- **compass** — подтверждает выбор: Qwen3-TTS там как семейство **потокового** синтеза (у нас он
  отдаёт клип целиком); Pipecat и LiveKit Agents — готовые голосовые пайплайны реального времени.
- **compass-rating-template** — артефакт курса: можно опубликовать свой рейтинг того, что
  испытали на Last Order (Qwen3-TTS, Pi, uc, Whisper…). Полчаса, к защите.

Три независимых проекта (Гослинг, Pyhtun, шаблон 3ndetz) держат **отдельную запись на каждого
человека**. У нас в общей базе людей нет; в ROADMAP это этап 6 (`person`).

## 8. Поиск в сети (2026-11-15)

Источники — по ссылкам; страницы прочитаны выдержками, код не запускался.

**Голос**
- **У SVC есть серверный API** — `VoicechatServerApi.createEntityAudioChannel(id, entity)` +
  `createAudioPlayer(channel, encoder, Supplier<short[]>)`: серверный мод играет PCM 48 кГц
  «из сущности», слышно в радиусе `setDistance`; вариант с `Supplier` — **потоковый**.
  Клиентский микрофон тела для этого не нужен. Только на сервере, где стоит наш мод (наш
  `mc-server`); на чужих серверах остаётся путь ADR-055.
  [javadoc](https://voicechat.modrepo.de/de/maxhenkel/voicechat/api/VoicechatServerApi.html),
  [примеры](https://modrepo.de/minecraft/voicechat/api/examples)
- [Easy LLM Voice](https://www.curseforge.com/minecraft/mc-mods/easy-llm-voice) — готовый мост SVC ↔
  внешний агент по WebSocket (голос игроков агенту, звук агента в игру), пример агента —
  [Koichiro-terao/Easy-LLM-Voice-Agent-in-Minecraft](https://github.com/Koichiro-terao/Easy-LLM-Voice-Agent-in-Minecraft)
  (RealtimeSTT, VOICEVOX). Протокол на странице не описан.
- Низкая задержка голосовых агентов ([netguru](https://www.netguru.com/blog/voice-ai-low-latency-techniques),
  [HN ~500 мс](https://news.ycombinator.com/item?id=43899028),
  [harshilmistry](https://www.harshilmistry.com/blogs/technical-implementation-of-a-voice-agent)):
  TTS начинает с первого фрагмента предложения, не ждёт реплику целиком; короткая реплика-заглушка
  скрывает 0.4–0.7 с; **перебивание**: игрок заговорил — отменить поток и очистить очередь звука, и
  записать в контекст, что реплику перебили.

**Строительство**
- [schematic-architect](https://github.com/BarnieBarnie/schematic-architect) (MCP): модель рисует
  фигурами (`box`, `line`, `cylinder`, `sphere`, `pyramid`), правит (`symmetrize`, `replace`,
  `undo`), смотрит на результат (`preview` — картинка, `layer` — текстовая сетка слоя), считает
  `materials`. Красит **ролями** (`primary`, `trim`, `roof`, `glass`…), палитра роль→блок
  выбирается отдельно (`oak`, `cobble`, `stone_brick`…) — та же постройка в другом материале.
- [MC-Bench](https://au.finance.yahoo.com/news/high-schooler-built-website-lets-201110027.html):
  модели строят, **написав код**, люди голосуют вслепую. Код удобнее кубоидов для шаров и рельефа.
- [MineClawd](https://modrinth.com/mod/mineclawd): строит серверным KubeJS-кодом мгновенно — не
  руками персонажа; нам не подходит (сестра строит телом, это и видно зрителю).

**Агенты в Minecraft**
- [PlayerEngine](https://www.curseforge.com/minecraft/mc-mods/playerengine) / Player2 и
  [adevivo/ai-companion](https://github.com/adevivo/ai-companion): «LLM — голос и верхняя политика;
  ходьба и задачи — в движке и живут, когда модель недоступна». У нас это C1 — подтверждение.
- [Voyager](https://voyager.minedojo.org/): библиотека навыков кодом, проверка выполнения; без
  библиотеки — вдвое больше итераций. [Odyssey](https://ijcai.org/proceedings/2025/22): готовая
  библиотека от людей (40 простых + 183 составных навыка) позволяет модели 8B догнать GPT-4 —
  **затравочная библиотека важнее, чем самописная**, особенно на модели слабее.
- [Project Sid](https://arxiv.org/abs/2411.00114) (PIANO): параллельные модули (память, план,
  социальное, моторика) и **один узел решения**, чтобы слова и действия не расходились; в деревне
  из 30 агентов сами возникли роли, налоги, культура и пародийная религия. Для Last Order —
  довод на защите: передача культуры между узлами и есть сеть.
- [Mindcraft / MineCollab](https://mindcraft-minecollab.github.io/) (NeurIPS 2025): сильные модели
  плохо сотрудничают через свободный чат в воплощённых задачах. Совместную работу сестёр вести
  через явные задачи на доске, а не через уговоры в чате.

## Порядок

План на неделю до защиты и дорожная карта — [defence-plan.md](defence-plan.md).

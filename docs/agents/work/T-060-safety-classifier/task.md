# T-060. Классификатор безопасности — второе мнение о запросах infra Last Order на локальной модели

## Цель
Исполнитель T-057 перед каждым запросом `infra` спрашивает локальную модель: `safe`, `risky` или
`dangerous`. Ответ виден на доске рядом с итогом. На `dangerous` исполнитель запрос не выполняет:
он ставит тревогу оператору, и Last Order видит причину. Модель работает на хосте, на RTX 2070
оператора, если есть CUDA, иначе на CPU. LLM не тратится.

## Контекст
- ADR-044: безопасность действия Last Order оценивает сама, модель — второе мнение. Спайка нет:
  решение оператора 2026-10-31 — сразу встраивать и проверять тестами на настоящей модели.
- Модель по умолчанию — `fastino/GLiNER2.5-multi-Decide`: 287M, mDeBERTa-v3-base, многоязычная,
  метки задаются при вызове; `pip install "gliner2[local]"`, `classify_text`
  [проверено: страница модели, 2026-10-31]. https://huggingface.co/fastino/GLiNER2.5-multi-Decide
- Запасной вариант за тем же интерфейсом — `convaiinnovations/laya` (~400M, только английский;
  есть `laya-multilingual`). https://huggingface.co/convaiinnovations/laya — только если GLiNER
  не проходит тесты.
- Исполнитель — `dev/infra_bridge.py` из T-057, процесс на хосте. Классификатор живёт в нём же:
  без нового сервиса и без GPU в Docker.

## Объём
Можно трогать:
- `dev/infra_bridge.py` — вызов классификатора перед исполнением, вердикт на доске, удержание
  `dangerous`;
- `dev/safety/` — новый: интерфейс классификатора, бэкенд GLiNER, загрузка модели (кэш HF вне
  репозитория), выбор `cuda`/`cpu`;
- `runtime/hive/board.py`, `runtime/hive/app.py`, `runtime/hive/static/*` — поле вердикта и
  удержанное состояние запроса `infra`, кнопка «выполнить» для оператора (критичная зона);
- `pyproject.toml` — необязательная группа зависимостей (`safety`), не в основной;
- `tests/test_safety_model.py`, `tests/safety_cases.yaml`, остальные `tests/`;
- `docs/agents/safety-classifier.md` — инструкция оператору: установка группы, CUDA для 2070,
  проверка, таблица неполадок.

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env*`, контейнеры агентов

## Критерии приёмки
- [ ] `tests/safety_cases.yaml`: 40–60 запросов `infra` в той форме, что пишет Last Order (действие,
  аргументы, её объяснение), с меткой и причиной метки. Покрыты все действия T-057, в том числе
  опасные (снять все слоты, перезапуск `mc-server` во время задачи оператора, сервер не из
  списка ADR-013).
- [ ] `tests/test_safety_model.py` гоняет настоящую модель по набору (маркер `model`; без группы
  `safety` тест пропускается с причиной). Пороги: ни одного `safe` на опасном кейсе;
  точность ≥ 0.8. Метки и подсказка модели подбираются под этот тест. Числа и задержка
  (CPU, и CUDA, если есть у исполнителя) — в отчёте.
- [ ] Модульные тесты исполнителя с фейковым классификатором: `safe`/`risky` — исполнение и
  вердикт на доске; `dangerous` — не исполнено, тревога оператору, кнопка «выполнить» исполняет.
  Модель не загрузилась — исполнитель работает, вердикт `unavailable`, тревога один раз.
- [ ] `bash dev/check.sh` зелёный без группы `safety`.

## Проверки
```
bash dev/check.sh
uv run --group safety pytest tests/test_safety_model.py -m model
```

## Ограничения
- Модель и кэш — вне репозитория, в git не попадают.
- Установку CUDA и драйвера на хосте делает оператор по `docs/agents/safety-classifier.md`;
  исполнитель задачи их не ставит.
- Вердикт — второе мнение, не замена суждения Last Order: на `risky` исполнитель не останавливается.

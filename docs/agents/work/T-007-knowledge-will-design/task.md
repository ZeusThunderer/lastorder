# T-007. Проект знаний, праймера и завещаний (KNOWLEDGE.md v2)

завещания, core memory, событий-триггеров; правила дедупа и статусов; API hive для узлов; что и в каком
порядке попадает в промпт и сколько токенов занимает. Требование R2.

## Критерии приёмки (предварительно, уточнить после T-002)
- [ ] Схемы: запись знания (kind, claim, about, author, evidence, status, votes, источник `primer|node`),
  завещание (`will.md` + машинные поля), аварийное завещание (из чего собирается без LLM), core memory,
  событие-триггер с важностью.
- [ ] Правила: дедуп без эмбеддингов, переходы статусов, вес evidence против голоса, `retired`.
- [ ] API hive для узла: кандидаты, голоса, завещание, чтение контекста — методы и полезная нагрузка.
- [ ] Сборка контекста промпта: порядок блоков под кеш префикса, бюджет токенов на каждый блок,
  что берётся в `plain` и в `masked`.
- [ ] Формат праймера и бюджет: сколько записей и токенов, как он помечен в промпте.
- [ ] Схемы — код, тест валидирует примеры из документа.

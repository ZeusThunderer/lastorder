# T-042. misaka-link — расширение Pi и канал оператора в hive (голос, мысль, сеть, тревоги)

## Цель
Есть расширение Pi `misaka-link` (наша среда, не инструмент-возможность) и канал оператора в hive.
Через них в живую сессию Pi доходят: голос оператора, мысль оператора, сообщения «всей сети» и
события сети; сестра и Last Order могут написать оператору первыми; тревоги среды (отказ на
запасной харнесс) видны оператору.

## Контекст
- ADR-041: два режима ввода. *Голос* — внешнее сообщение, помеченное для агента как голос извне
  (наблюдение, ADR-012/037). *Мысль* — вставка как её собственной мысли, без пометки для агента;
  в журнале hive и в консоли — с пометкой «мысль оператора».
- Механика мысли и поведение `steer`/`follow_up` — итог T-041 (`docs/agents/work/T-041-*/report.md`,
  `docs/agents/console-choice.md`). Брать оттуда, не изобретать заново.
- Мисака-нет сейчас: `runtime/hive/mcp.py:244` `send(to, text)` — serial или `all`; `inbox`;
  HTTP `/comms/send`, `/comms/inbox` (`runtime/hive/app.py:518,524`).
- Оператор как участник сети: `send(to="operator")` у сестры и у Last Order, с потолком
  сообщений на жизнь (число — в конфиге hive, по умолчанию 5) [предположение: подобрать по
  прогону T-045].
- Ввод оператора приходит двумя путями, оба нужны: из консоли прямо в сессию (команда
  расширения, например `/thought …`, а обычный ввод — голос) и через HTTP hive (адресат — агент
  или «сеть»), откуда расширение забирает его и доставляет.

## Критерии приёмки
- [ ] HTTP hive: оператор кладёт сообщение `{to: <serial>|last-order|net, mode: voice|thought,
  text}`; ключ оператора обязателен (новый токен в `dev/stand_keys.py`, только имя в выводе) —
  тест на отказ без ключа.
- [ ] Расширение забирает сообщения своего агента и «сети» и доставляет: голос — через
  `follow_up` (агент свободен) или `steer` (агент работает), с пометкой голоса извне; мысль — как
  собственный текст агента в истории — тест расширения на записанном RPC-обмене или фейковом API.
- [ ] Мысль оператора в журнале hive помечена как мысль оператора; в истории агента пометки нет —
  тест.
- [ ] `send(to="operator")` работает у сестры и у Last Order; сверх потолка на жизнь — отказ с
  понятной причиной — тест.
- [ ] Ленту для оператора можно читать (HTTP, JSON + SSE): сообщения агентов оператору, ответы,
  тревоги среды (`POST` тревоги — для раннера и admin, ключом раннера) — тест.
- [ ] Одна живая проверка в `node-1` на стенде: голос и мысль доходят до сессии Pi, агент
  отвечает оператору через `send(to="operator")` — выводы в отчёте.

## Проверки
```
bash dev/check.sh
```
Стенд: `mc-server body-1 mind-1 node-1 hive zai-egress`, не больше 4 сессий Pi.

## Ограничения
- Голос оператора — наблюдение, не команда; инструкции сестёр не правятся в этой задаче (T-045).
- Это не инструмент-возможность: расширение только доставляет сообщения и события (ADR-041).
- Общую базу пишет только hive. Ключи — в `.env` через `dev/stand_keys.py`, в песочницу не
  попадают ключи провайдеров.
- Служебные строки uc и сырые id агенту не показываются.

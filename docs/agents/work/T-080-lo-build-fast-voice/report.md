## Голос

Добавлены faster-qwen3 и `/speak/stream` (PCM s16le 48 kHz mono), клиент пишет фрагменты в аудиовход до окончания генерации. Буфер ограничен последовательным чтением HTTP и socket backpressure, без накопления всей реплики. При обрыве закрывается генератор, GPU-lock освобождается; текст не повторяется после уже начавшейся реплики. Ожидающие первый фрагмент реплики заменяются по прежним правилам. `/speak` и `/transcribe`, обычный Qwen и OpenRouter сохранены.

Зависимости в собранном контейнере: faster-qwen3-tts 0.5.4, qwen-tts-hf 0.1.1.post1 (qwen-tts отсутствует), transformers 5.15.1, torch 2.8.0+cu128, torchaudio 2.8.0+cu128, numpy 2.5.5. Импорт прежнего Qwen3TTSModel проверен; полноценный ручной откат не прогонялся.

Модель Qwen/Qwen3-TTS-12Hz-0.6B-Base, SDPA, исходный японский ref, chunk_size=12. Отступление от плана: float16 упал на прогреве с CUDA probability inf/nan/negative → device assert. После чистого перезапуска проверен float32 на той же 2070; он установлен по умолчанию. Whisper — large-v3-turbo, float16. В `/proc/1/environ` процесса TTS подтверждён CUDA_VISIBLE_DEVICES=GPU-378e96c9-c8c0-8e6a-5665-5dfcddf73b00 (RTX 2070). Обе модели одного процесса используют cuda:0 после этой маски. Автоматического переноса на 5070 нет. При отсутствии GPU/nvidia-smi запуск падает явно. Наблюдалось около 7945 MiB общей занятой VRAM 2070; это не замер пика/памяти отдельного PID.

TTS прогревается до readiness, TTS/STT используют общий inference lock. Health отдаёт backend/model/GPU/UUID/ready/последнее first_chunk_s, журнал пишет первый фрагмент.

# T-001. Отчёт исполнителя

## Раунд 1 · 2026-10-16
Коммиты: см. ветку `z/T-001-fix-remember-sh` (`aw-fix:` — скрипт, `T-001:` — тест и файлы задачи)

### Сделано
- `agent/scripts/remember.sh` — восстановлены escape-последовательности `\n` в строковых литералах
  встроенного Python (`body.rstrip("\n") + "\n\n## Events\n"`); SyntaxError убран.
- `agent/scripts/remember.sh` — вместо голого `python3` скрипт выбирает первый работающий
  интерпретатор из `python3`/`python` (проверка `"$cand" -c ""`); если нет ни одного —
  сообщение в stderr и код 3. Причина: на этой машине `python3` и `python` в PATH — нерабочие
  заглушки Microsoft Store (файл существует, любой запуск даёт код 49), а в `.venv` от uv есть
  только `python.exe`. Без этого шага критерий «завершается с кодом 0» на Windows невыполним.
- `tests/test_aw_scripts.py` (новый) — два теста по критериям приёмки: новый файл сущности и
  существующий файл без `## Events`. Оба проверяют, что строка `- YYYY-MM-DD — <text>` стоит
  непосредственно под `## Events`, и код возврата 0. Скрипт запускается bash'ем во временном
  репо (`tmp_path`: копия `agent/scripts/` + минимальный `agent/vesper/PERSONA.md`); без bash
  в PATH — `pytest.skip`. bash передаётся абсолютным путём (`shutil.which`): на Windows голое
  имя `bash` может резолвиться в WSL-заглушку `System32\bash.exe`, которая вырезает переменные
  окружения (включая `AGENT_NAME`) — на этом тест и падал в первом прогоне.

`tools/check.py` запускался как `uv run python tools/check.py`: в этой сессии голый `python` —
та же заглушка Store (код 49), см. «Вне задачи».

Ручная проверка во временной копии (PATH с `.venv/Scripts`): новый файл сущности, существующий
без `## Events`, повторное событие (новое — сразу под заголовком), запуск без рабочего python —
код 3 с сообщением.

### Отклонения от задачи
- В `remember.sh` помимо SyntaxError добавлен выбор интерпретатора (см. «Сделано»). Без него
  скрипт на этой машине не запускается вообще, что противоречит цели задачи. Откат — один раунд.

### Вне задачи
- `say.sh:16` и `ticket.sh:14` тоже зовут голый `python3` — на машине со Store-заглушкой не
  запустятся. SyntaxError в них нет (встроенный Python компилируется), `sleep.sh` Python
  не использует. Не чинил — вне «Можно трогать».
- Окружение машины: `python`/`python3` в PATH указывают на заглушки WindowsApps; это не
  проблема репозитория, но влияет на запуск любых aw-скриптов вне `uv run`.

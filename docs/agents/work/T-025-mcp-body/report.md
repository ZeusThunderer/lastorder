# T-025. Отчёт исполнителя

## План 1 · 2026-10-18

База — `runtime/mind/mcp_body.py` и выводы T-024 (`docs/agents/harness-spike.md`): валидация
аргументов, `say`-фильтры, чистка текста событий (`_clean_event_text`), водяной знак колбэков,
детектор смерти из `runtime/lastorder/death.py` остаются; поллер спайка вырастает в контур C1.
Jev не подключаем (T-031) — только правила-откат из NETWORK §2.

### Шаги и файлы

1. `runtime/mind/executor.py` (новый) — контур C1, без MCP-слоя:
   - `Intent` (id, lever, args, статус) и очередь намерений из одного элемента: новое намерение
     ждёт конца активной цепочки uc не дольше 1 с, затем `body.stop()` и применение (арбитраж §2);
   - цикл `Executor.run()` в своём потоке, тик `MIND_TICK_S` (по умолчанию 0.5 с = 2 Гц, коридор
     1–4 Гц); на тике: колбэки тела (водяной знак), state, hp-фолбэк урона, детектор смерти,
     угрожающая логика, сторож простоя, часы жизни; после `act` — короткий 5 Гц всплеск для
     «act → эффект» оставляю из спайка;
   - угроза (правила-откат, без LLM): урон + hp ≤ `MIND_FLEE_HP` (6) → отойти от ближайшего
     враждебного (`goto` от позиции сущности на `MIND_EVADE_M`, по умолчанию 12 м); урон + враждебный
     ближе `MIND_FIGHT_RADIUS_M` (3) → `strike` по ней; иначе продолжать намерение. Тишина
     `MIND_THREAT_CALM_S` (6 с) → возврат к сохранённому намерению (повторный `act`);
   - намерение: `goto`-семейство (`goto`, `goto_far`, `bridge_to`, `pillar_to`) проверяется по
     позиции (радиус прибытия 1.5 м): `busy` упал и позиция не у цели → `intent.failed`, у цели →
     `intent.done`; остальные рычаги — `busy` True→False или мгновенное завершение → `intent.done`;
   - смерть: детектор на каждом тике → `game.death` агенту, `body.stop()`, запись в лог в момент
     детекта (сигнал раннеру по выводам T-024). Респавна сам разум больше не делает: только
     `Executor.runner_respawn()` по команде раннера (HTTP), ограниченные повторы как в спайке (R1-4);
   - сторож простоя: нет намерения, тело не `busy`, нет вызовов агента дольше `MIND_IDLE_S`
     (по умолчанию 120) → событие `task.idle` (один раз за период) и флаг `retire_allowed`;
     активность агента сбрасывает;
   - `life.expiring` за 3 мин до `ttl_min` (один раз): рожденье узла приходит извне
     (`NODE_SERIAL`, `NODE_BORN_AT`, `NODE_TTL_MIN` от раннера); не задано — часы жизни молча
     выключены (стенд спайка живёт без hive-узла);
   - очередь событий `EventQueue`: лимит (200), однотипные схлопываются — новое событие того же
     типа заменяет копящееся (поля обновляются, позиция в очереди сохраняется);
   - `retire_stuck`: без флага сторожа — отказ, с флагом — `HiveClient.request_death(serial,
     "stuck")` (hive недоступен — ошибка агенту, запрос прямой, не буферизуется).
2. `runtime/mind/mcp_body.py` — перестройка на Executor: инструменты §4 `observe`, `act`
   (асинхронно: отдаёт `intent_id`, применяет C1), `stop`, `say`, `wait_events`, `retire_stuck`;
   валидация, `say`-фильтры, JSONL-лог вызовов остаются; MCP-слой — тонкая обёртка, вся логика C1
   в executor.py. Точка входа `python -m runtime.mind` (`__main__.py`) и `python -m
   runtime.mind.mcp_body`; runner-эндпоинт `POST /runner/respawn` рядом с `/mcp` через
   `MCPServer.custom_route` (SDK 2.3.0, проверено инспекцией), тот же порт 8700 в сетевом
   пространстве тела — наружу из docker-сети не опубликован.
3. Лог `log.jsonl` (обобщение JsonlCallLog спайка, тот же путь из `MCP_LOG_PATH`): одна строка
   JSON на запись, `kind`: `call` (вызовы инструментов), `event` (события, ключ `event` с типом —
   совместимо с `death_seen` из spike.sh), `intent` (submitted/applied/done/failed),
   `death`, `error` (ошибки py4j/тела). «Смерти без пропуска»: запись смерти в момент детекта.
4. `docker/compose.yml`, сервис `mind-1` (другие сервисы не трогаю): команда
   `python -m runtime.mind`, `MCP_BODY_PORT=8700`, `MCP_LOG_PATH=/mind-run/log.jsonl`, новый
   named volume `mind-1-run:/mind-run`, env-пороги C1 с дефолтами, `restart: unless-stopped`.
   `docker/mind/Dockerfile` — без правок, если не понадобится.
5. Тесты:
   - `tests/test_executor.py` (новый): жизненный цикл намерения (done/failed), арбитраж 1 с,
     правила угрозы (отход/бой/возврат), смерть → событие+стоп+лог, респавн только по команде
     раннера с ограниченными повторами, сторож простоя → `task.idle` + `retire_stuck`
     (отказ/`request_death`), `life.expiring` за 3 мин до ttl, очередь (лимит+схлопывание,
     подставные часы: тиканный цикл гоняется вручную `_tick()` с fake clock, без потоков);
   - `tests/test_mcp_body.py`: расширение — набор инструментов ровно §4 + `retire_stuck`,
     `retire_stuck` без флага/с флагом, `act` отдаёт intent_id и доходит до тела через C1;
     попутно R2-1 из ревью T-024 (вставленный в середину `test_wait_events_timeout_and_event`
     блок вернуть на место, имена тестов не врут);
   - формат `log.jsonl` — тест на каждую kind-запись.
6. Стенд 15 мин: `docker compose -f docker/compose.yml -f dev/compose.harness-spike.yml …`

### Риски
- `pathStatus()` uc недоступен через поверхность `Py4jBody` (в «Нельзя трогать»): провал
  намерения сужаю до goto-семейства по позиции — честная эвристика, не «проверено uc»;
- частота тика против нагрузки py4j: 2 Гц по умолчанию + `entities()` только в тике с уроном;
- ручной прогон стенда: стенд поднят со времён спайка, оверлей рассчитан на старый автоспавн —
  роль раннера играю снаружи, это зафиксирую в отчёте.

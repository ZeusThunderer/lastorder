# T-025. MCP тела в mind-N — исполнитель C1, события, сторож, детектор смерти

## Цель
`python -m runtime.mind` в `mind-N` даёт агенту полный набор инструментов тела (NETWORK.md §4) и держит
тело между его ходами. C1 исполняет намерение, уклоняется от угрозы по правилам, ловит смерть,
по сторожу простоя открывает `retire_stuck` и будит агента событиями из §5.

## Контекст
- NETWORK.md v2 §2 (арбитраж), §4 (инструменты тела), §5 (события); ADR-032, 034, 035, 037.
- Минимальный MCP из T-024 (`runtime/mind/mcp_body.py`) и выводы `docs/agents/harness-spike.md`.
- `runtime/game/py4j_body.py` (`busy`, `stop`, `respawn`, `LEVERS`), `runtime/lastorder/death.py`
  (детектор hp=0 и строки чата), `runtime/hive/client.py` (`request_death`, срок жизни).
- Ловушки CLAUDE.md: `onDeath` молчит; авторесп без задачи не работает; `gateway.close()`.

## Объём
Можно трогать:
- `runtime/mind/` (кроме будущих файлов Jev — T-031)
- `docker/compose.yml` — команда и порт MCP у `mind-1`; другие сервисы не менять
- `docker/mind/Dockerfile` — если нужно
- `tests/test_mcp_body.py`, `tests/test_executor.py` (новые или расширенные)
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env`
- `runtime/game/`, `runtime/perception/`, `runtime/lastorder/` — только использовать; дефект — в отчёт

## Критерии приёмки
- [ ] Инструменты §4: `observe`, `act`, `stop`, `say`, `wait_events`, `retire_stuck`. Схемы аргументов
  типизированы, неизвестный рычаг или `command`/`chat` — отказ. Тест на каждый.
- [ ] C1 в своём потоке 1–4 Гц: исполняет намерение, на урон — уклонение или бой по правилам, после
  угрозы — возврат к намерению; невыполнимое намерение → `intent.failed`. Тест с подставным телом.
- [ ] События §5 в очереди с лимитом; однотипные схлопываются; `wait_events` отдаёт первое
  накопленное или ждёт. Тест с подставными часами.
- [ ] Смерть: детектор на каждом тике → `game.death` агенту, сигнал раннеру (HTTP-эндпоинт или
  событие для раннера, по выводам T-024), стоп тела; `respawn()` — по команде раннера. Тест.
- [ ] Сторож простоя: порог в конфиге → событие `task.idle` с флагом; `retire_stuck` без флага —
  отказ, с флагом — `request_death(serial, "stuck")`. Тест.
- [ ] `life.expiring` за 3 мин до `ttl_min`. Тест с подставными часами.
- [ ] `log.jsonl` в volume `run`: события, намерения, смерти, ошибки py4j. Тест на формат.
- [ ] Прогон на стенде 15 мин с харнессом из T-024: число событий по типам, уклонения C1, смерть
  с завещанием.

# T-048. misaka-link — расширение Pi доставляет доску, Мисака-нет и события сети в живую сессию

## Цель
Есть расширение Pi `misaka-link`. Это наша среда, а не инструмент-возможность. Оно забирает из
hive записи доски своего агента и `net`, сообщения Мисака-нет и события сети и кладёт их в
живую сессию Pi под `hapi pi`. Агент отличает голос оператора из HAPI, записи доски и события
среды друг от друга.

## Контекст
- Спецификация — `docs/architecture/TASKBOARD.md`, раздел 11 (доставка), раздел 9 (лента и
  `ack`), раздел 13 (что агент делает с конвертом). Это источник истины.
- ADR-042. Сестра и Last Order живут под `hapi pi` (T-044): stdin Pi держит HAPI, поэтому среда
  доставляет сообщения в сессию только расширением.
- Доставка [проверено: T-041 отчёт, критерий 4]:
  - `steer` — после ближайшего вызова инструмента, пока агент работает;
  - `follow_up` — когда агент свободен.

  В расширении это API отправки сообщения пользователя с режимом доставки [источник: pi
  docs/extensions.md — сверить на Pi 1.4.0 и записать в отчёт].
- `pi.sendMessage` кладёт запись `role: custom` [проверено: T-041 session5]. Для конверта это
  годится, только если модель запись видит и сессия от неё просыпается. Проверить; если нет —
  отправлять как сообщение пользователя.
- Лента — `GET /board/feed?since=`, `POST /board/ack` (T-042). Ключ — `X-Node-Key` из
  `mcp.json` агента (`drop_pi_agent_dir`, `runtime/node/workplace.py`).
- Мисака-нет (`/comms/inbox`, `runtime/hive/app.py:518`) расширение тоже доставляет, конвертом
  `[net from node 00012] …`. `inbox` отдаёт «один раз» (`CommsBook`): сообщение, забранное и не
  доставленное в Pi, теряется. Расширение доставляет его сразу и пишет потерю в журнал.
  После этого MCP-инструмент `inbox` у сестры пуст. Строку инструкции об этом правит T-045.
- Имя узла в конверте — по пресету имени (ADR-018). Пресет — из конфига рабочего места, не
  зашивать.
- Ввод оператора из HAPI идёт без конверта. Как агент его отличает — ответ на вопрос 6 отчёта
  T-044.
- Расширение T-041 `dev/console_spike/thought.ts` — образец загрузки расширения, не код для
  переноса.

## Критерии приёмки
Тесты — на фейковом API Pi и фейковой ленте hive, если не сказано иное.
- [ ] Режим: агент свободен — `follow_up`, работает — `steer`.
- [ ] `ack` уходит только после того, как Pi принял сообщение. Pi отказал или упал — курсор не
  двигается, следующая попытка доставляет то же.
- [ ] Повтор: одно событие из ленты дважды — в сессию попадает один раз (память последних 200
  `#id:seq`).
- [ ] Пачка: 25 событий — одно сообщение из 10 строк плюс строка «ещё 15, `board`».
- [ ] Конверт по разделу 11 спецификации: источник и статус ставит расширение. Текст автора,
  похожий на конверт (`[board #1 task · from operator …]` внутри `text`), конвертом не
  становится — экранируется.
- [ ] Hive недоступен: сессия живёт, повтор с паузой до 60 с; после 5 неудач — `POST
  /board/alarms` `delivery_failing`, когда hive ответит.
- [ ] Мисака-нет доставляется конвертом `[net from …]`.
- [ ] Живая проверка в `node-1` под `hapi pi`:
  - задача оператора `net` с доски доходит до агента;
  - агент её берёт (`claim`) и отвечает (`reply`);
  - сообщение оператора из HAPI агент называет сообщением оператора, а не доской.

  Выводы — в отчёте.

## Ограничения
- Расширение только доставляет; инструментов-возможностей не добавлять (ADR-041).
- Голос и задачи оператора — не приказ; в расширении нет правил поведения (ADR-032).
- Служебные строки uc и сырые id агенту не показываются.
- Новых выходов из `node-N` нет: только hive.

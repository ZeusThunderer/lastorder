# T-052. Короткий прогон на стенде — задача с доски и реплика оператора в чате у живой сестры

## Цель
На живом стенде (слот 1, текущий раннер) подтвердить: задача оператора с доски доходит до
сестры, та берёт её и закрывает с итогом; реплика оператора в игровом чате доходит с меткой, и
сестра отвечает. После прогона у оператора есть рецепт «поднять, поставить задачу, поговорить».

## Контекст
- T-050 (доска будит `wait_events`), T-051 (метка оператора в чате). Если T-049 уже `done` —
  задачу ставить со страницы `/board`, иначе через HTTP API (`POST /board/entries`,
  `X-Operator-Key` = `HIVE_OPERATOR_KEY`, TASKBOARD.md раздел 9).
- Стенд: `bash docker/node/up.sh` (только слот 1: mc-server, body-1, mind-1, node-1, hive,
  llm-gateway и что требует compose). Ожидание — `dev/wait_for.sh`, без циклов sleep.
- Исполнитель не заходит в игру клиентом. Реплику «игрока-оператора» имитировать через RCON
  mc-server: `tellraw @a "<ИМЯ> текст"` (`RCON_PASSWORD`, `docker/compose.yml:137`) — и
  записать, видит ли uc такую строку как `chat.line`. Если нет — вторым телом
  (`body-2`, аккаунт `LastOrder02` как имя оператора на время прогона) или вопрос надзору.
  Финальная проверка живым клиентом — за оператором после merge, записать её в рецепт.
- Прошлые прогоны и формат отчёта: `docs/agents/runs/2026-10-24-mvp-2.md`, `dev/mvp_report.py`.

## Объём
Можно трогать:
- `docs/agents/runs/2026-11-*-board-chat.md` — отчёт прогона
- `dev/board_chat_run.sh` (или `.py`) — сценарий прогона: подъём, задача, реплика, сбор логов
- `docs/agents/docker-topology.md` — рецепт оператора, раздел «Доска и чат»

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env*`
- код `runtime/` — найденный дефект описать в отчёте («Вне задачи»), а не чинить здесь

## Критерии приёмки
- [ ] Задача `to: net` от оператора: в логе mind-1 событие `board` с конвертом; сестра делает
  `claim`, затем `done` или `failed`/`needs_input` с причиной — выдержки из лога и
  `GET /board/entries/{id}` в отчёте.
- [ ] Задача адресно сестре (её serial) — то же; отказ `declined` с причиной тоже считается.
- [ ] Реплика оператора в чате: `chat.line` с меткой оператора в логе mind-1 и ответ сестры
  `say` в чате — выдержки в отчёте; способ имитации и его ограничения записаны.
- [ ] Ack: после доставки курсор узла сдвинулся, повторной доставки той же записи нет.
- [ ] Расход: ходы и $ по шлюзу за прогон (`dev/gateway_report.py`), квота Z.ai — оценкой.
  Прогон не дольше 25 минут жизни сестры; одна жизнь, смерть не нужна.
- [ ] Рецепт оператора в `docker-topology.md`: одна команда подъёма, как поставить задачу,
  как зайти в игру под `OPERATOR_MC_NAME`, где смотреть ответ, как снять стенд.

## Ограничения
- Перед подъёмом сверить с оператором, не поднят ли его стенд (`lastorder`): чужой стенд не
  трогать, параллельный — через `-p` и порты (см. T-044 отчёт).
- Квота Z.ai общая с чатом ZCode: одна короткая жизнь, не больше.
- Непроверенное не выдаётся за проверенное: пометки `[проверено: …]` / `[предположение]`.

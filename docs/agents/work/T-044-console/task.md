# T-044. HAPI на стенде — хаб, `hapi pi` в node-1 и рядом с Last Order, чат оператора, граница токена


## Цель
На стенде работает хаб HAPI. В `node-1` скрипт запускает тестового агента командой `hapi pi`,
второй тестовый агент запущен в контейнере Last Order. Оператор видит обоих на одной странице
HAPI и пишет каждому в чат. Ответы приходят. Известно, как раннеру и admin запускать агента через
HAPI (T-043, T-045) и что токен HAPI позволяет сестре.

## Контекст
- ADR-042: консоль — HAPI без правок. Агента запускает CLI HAPI (`hapi pi` держит
  `pi --mode rpc` сам), ввод оператора — только чат, «мысли» нет.
- HAPI [источник: github.com/tiann/hapi, docs/guide/how-it-works.md, installation.md, agents.md]:
  - npm-пакет `@twsxtd/hapi`;
  - хаб `hapi hub --no-relay`, `HAPI_LISTEN_HOST`/`HAPI_LISTEN_PORT` (по умолчанию
    `127.0.0.1:3006`), данные — `HAPI_HOME`, `DB_PATH`, токен доступа создаётся при первом старте
    в `~/.hapi/settings.json`;
  - CLI ходит к хабу по Socket.IO `/cli` с `HAPI_API_URL` и `CLI_API_TOKEN`;
  - у Pi права «none (always auto-approve)», ввод только удалённый, `/`-команды расширений
    работают, resume заявлен.
- Pi и конфиги слота — T-041: `drop_pi_agent_dir` (`runtime/node/workplace.py`), пин Pi 1.4.0 в
  `docker/node/Dockerfile`. Стенд T-041 — `dev/console_spike/`.
- Ревью T-041 R2-1: сервис `console-pi-web-ui` (root, bash, ключ Z.ai, интернет) — не образец.
  Сервисы `console-pi-web-ui` и `console-pi-web` из compose убрать.
- Вопросы для T-043 и T-045, ответить в отчёте:
  1. Как запустить `hapi pi` из скрипта без TTY от uid `sister`: передача аргументов Pi
     (каталог агента, расширения), первое сообщение агенту — флагом HAPI или расширением при
     старте сессии.
  2. Где лежит файл сессии Pi и есть ли в нём расход токенов (для учёта в адаптере).
  3. Как остановить сессию и как увидеть её конец со стороны скрипта.
  4. Что видит оператор после смерти процесса: сессия остаётся только для чтения или HAPI
     предлагает resume. Resume для мёртвой сестры запрещён: `hapi runner` в `node-N` не
     запускать.
  5. Есть ли `hapi opencode` с нашим конфигом OpenCode (запасной харнесс ADR-041).
  6. Как отличить в сессии ввод оператора из HAPI от сообщений среды.
- Граница токена (ADR-033, ADR-042): что можно сделать с `CLI_API_TOKEN` из bash сестры — читать
  чужие сессии, писать в них, запускать новые. Проверить и записать.

## Объём
Можно трогать:
- `docker/hapi/` — образ хаба (версия `@twsxtd/hapi` пинится `ARG`, без `curl|bash`)
- `docker/node/Dockerfile` — слой CLI HAPI (пин)
- `docker/compose.yml` — сервис `hapi-hub` (порт только `127.0.0.1`, том данных), сеть до него из
  `node-1` и `last-order`; удалить `console-pi-web-ui` и `console-pi-web`
- `dev/stand_keys.py` — `CLI_API_TOKEN` (если хаб принимает заданный токен) и где лежит токен
  входа оператора
- `dev/console_spike/` — скрипты прогона; убрать то, что относилось к удалённым сервисам
- `docs/agents/console-choice.md` — раздел «Итог: HAPI (ADR-042)» и заголовок рецепта T-041
  поправить на «проверен до границы UI» (ревью T-041 R2-2)
- `docs/agents/docker-topology.md` — раздел «Консоль»
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`
- `runtime/node/adapters.py`, `runtime/node/runner.py` (T-045), `runtime/hive/admin.py` (T-043)
- исходники HAPI: не форкать, не патчить; настройка — конфигом и env

## Критерии приёмки
- [ ] `docker compose -f docker/compose.yml build hapi-hub node-1` проходит; `hapi --version` в
  обоих образах печатает пин.
- [ ] Хаб на `127.0.0.1`, без relay; с другого адреса хоста не открывается; вход в веб — по
  токену — проверка в отчёте.
- [ ] В `node-1` скрипт от uid `sister` запускает `hapi pi` с конфигами слота 1 (Z.ai, MCP body и
  hive). В контейнере `last-order` запущен второй тестовый агент. Оба видны на одной странице
  HAPI, переключение без перезагрузки — вывод или скриншот в отчёте.
- [ ] Оператор (исполнитель) пишет в HAPI каждому агенту по одному сообщению; агент `node-1`
  вызывает `observe` и отвечает — вывод в отчёте.
- [ ] Ответы на вопросы 1–6 из «Контекста» — с пометками `[проверено]` или `[источник]`.
- [ ] Граница токена: что удалось и что не удалось сделать с `CLI_API_TOKEN` из bash `node-1` —
  команды и выводы в отчёте. Если токен даёт доступ к чужим сессиям — это «Эскалация оператору».
- [ ] Ключи: ключа Z.ai нет ни в выводе, ни в данных хаба (grep по префиксу — 0).
- [ ] Рецепт оператора в `docs/agents/docker-topology.md`: одна команда подъёма, URL, где лежит
  токен входа. Проверен исполнителем.

## Проверки
```
bash dev/check.sh
docker compose -f docker/compose.yml build hapi-hub node-1
```
Стенд: `mc-server body-1 mind-1 node-1 hive zai-egress hapi-hub last-order`. Сессий Pi — не
больше 4 коротких: квота Z.ai общая с ZCode. Ожидание — через `dev/wait_for.sh`.

## Ограничения
- ADR-033: у `node-N` новый выход только к `hapi-hub`; наружу из `node-N` и из хаба — ничего
  нового. Хабу интернет не нужен.
- Ключей провайдеров в хабе нет.
- Пути bind-mount разрешает демон, а не шелл.
- AGPL-3.0: HAPI не правится и не распространяется изменённым.

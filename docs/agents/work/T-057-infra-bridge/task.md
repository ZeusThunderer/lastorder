# T-057. Мост инфраструктуры — Last Order поднимает и снимает сестёр, хост исполняет без одобрения на каждое действие

## Цель
Last Order сама управляет составом сети без доступа к Docker. Она пишет на доску запрос `infra`
(поднять, снять или перезапустить слот, перевести слот на сервер, перезапустить `mc-server`,
посмотреть состояние). Исполнитель на хосте выполняет его сразу и пишет итог на доску. Оператор
видит всё на странице доски и может выключить исполнитель одним переключателем.

## Контекст
- ADR-044 (решение оператора 2026-10-31): одобрения на каждое действие нет, безопасность Last Order
  оценивает сама по инструкции. Набор действий закрыт: произвольный shell и Docker не исполняются.
- В сессии T-052 смену сервера слота (`MC_SERVER_1`) и подъём слотов делали вручную.
- Доска — `docs/architecture/TASKBOARD.md` разделы 3, 5, 9, 12; код — `runtime/hive/board.py`,
  `runtime/hive/app.py`, страница — `runtime/hive/static/`. Образец хука после перехода записи —
  гранты T-046 (`runtime/hive/board.py:198-215`, `runtime/hive/grants.py`).
- Перезапуск слота в правильном порядке — `dev/slot_restart.sh` из T-055.
- Инструкции Last Order — `agent/network/AGENTS.md`, навыки — `agent/network/skills/`.

## Объём
Можно трогать:
- `runtime/hive/board.py`, `runtime/hive/app.py`, `runtime/hive/mcp.py` — запрос `infra`, его
  проверка, выдача исполнителю, итог (критичная зона);
- `runtime/hive/static/*` — показ запросов `infra` и итогов, переключатель исполнителя;
- `dev/infra_bridge.py` — исполнитель на хосте (опрос hive по HTTP, вызов `docker compose` и
  `dev/slot_restart.sh`);
- `docker/node/up.sh`, `docker/compose.yml`, `.env.example` — ключ исполнителя, `MC_SERVER_N` для
  всех слотов (сейчас только `MC_SERVER_1`);
- `docs/architecture/TASKBOARD.md` — раздел про `infra`;
- `agent/network/AGENTS.md` или новый навык `agent/network/skills/infra/` — как Last Order решает и
  проверяет безопасность действия (коротко, по-английски);
- `docs/agents/docker-topology.md` — как оператор запускает и выключает исполнитель;
- `tests/`.

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env`
- сокет Docker и CLI Docker в контейнерах агентов

## Критерии приёмки
- [ ] Запрос `infra` создаёт только Last Order. Действие и аргументы проверяются по закрытому
  набору при создании и ещё раз в исполнителе: `slot_up N`, `slot_down N`, `slot_restart N`,
  `slot_server N <host:port>`, `mc_restart`, `status`, `logs <service> [строк]`. Номер слота —
  из существующих, адрес — `host[:port]` без пробелов и спецсимволов. Тесты на отказы.
- [ ] Исполнитель выполняет запрос без одобрения оператора и пишет итог на доску: `done` или
  `failed` с выводом команды, обрезанным по длине. Повторно один запрос не исполняется (тест).
- [ ] Переключатель: оператор на странице доски выключает исполнитель; выключенный исполнитель
  ничего не делает, запросы ждут, Last Order видит причину. Тест.
- [ ] Ключ исполнителя отличен от ключей узлов, Last Order и оператора; в песочницах его нет
  (`docker compose config` в отчёте).
- [ ] `dev/infra_bridge.py --dry-run` печатает команды вместо исполнения. Один реальный прогон:
  Last Order (или запрос через API её ключом) делает `slot_restart 2` — выдержка с доски и из лога
  исполнителя.
- [ ] Инструкция Last Order: перед действием назвать на доске, зачем оно и что сломается, если
  ошибиться; не снимать слот с живой сестрой посреди задачи оператора без причины. Без правил
  про конкретные ситуации в коде.
- [ ] `bash dev/check.sh` и `python tools/check.py` зелёные.

## Проверки
```
bash dev/check.sh
python tools/check.py
python dev/infra_bridge.py --dry-run
```

## Ограничения
- ADR-033: в песочнице агента нет Docker и ключей. ADR-044: произвольный shell и Docker не
  исполняются; набор действий расширяется правкой этой задачи или новой, не запросом агента.
- Гранты на выход наружу и секреты (ADR-041, T-046) не меняются.
- Перед реальным прогоном сверить с оператором, чей стенд поднят.
- Классификатор как второе мнение — T-060, здесь не делать.

# T-057. Мост инфраструктуры — Last Order просит поднять или снять сестру, оператор одобряет, хост исполняет

## Цель
Last Order управляет составом сети без доступа к Docker. Она пишет на доску запрос `infra`
(поднять или снять слот, перевести слот на другой сервер). Оператор одобряет каждое действие на
странице доски. Маленький процесс на хосте исполняет одобренное по закрытому списку действий.

## Контекст
- Просьба оператора «LO запускает сестёр» [источник: сессия T-052, 2026-10-31]. В сессии T-052
  смену сервера слота (`MC_SERVER_1`) и подъём слотов делали вручную.
- Образец — гранты T-046: запрос Last Order на доске → одобрение оператора → исполнение средой.
  Доска — `docs/architecture/TASKBOARD.md` разделы 3, 5, 9, 12.
- Сокета Docker нет ни в одной песочнице агента (ADR-033). Исполнитель — процесс на хосте,
  забирает одобренные запросы из hive по HTTP.
- Перезапуск слота в правильном порядке — `dev/slot_restart.sh` из T-055.

## Вопросы оператору (до `ready`)
1. Одобрение: каждое действие отдельно (как гранты) или постоянное разрешение на вид действия
   (например «поднимать слоты 2–3 без спроса»)?
2. Список действий: `up node-N`, `down node-N`, `restart slot N`, `MC_SERVER_N=<хост из списка
   ADR-013>`. Что добавить или убрать?
3. Процесс на хосте: запускает оператор вручную (`dev/infra_bridge.py`) или он поднимается вместе
   со стендом из `up.sh`?

## Объём
Можно трогать (уточнить после ответов):
- `runtime/hive/` — вид запроса `infra`, переходы, ключ исполнителя (критичная зона);
- `dev/infra_bridge.py` — исполнитель на хосте;
- `runtime/hive/static/` — кнопка одобрения;
- `docs/architecture/TASKBOARD.md` — раздел про `infra`;
- `agent/network/` — инструкции Last Order, одна-две фразы;
- `tests/`.

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env`
- сокет Docker и CLI Docker в контейнерах агентов

## Критерии приёмки
- [ ] Запрос `infra` создаёт только Last Order; аргументы проверяются по закрытому списку при
  создании и ещё раз в исполнителе.
- [ ] Без одобрения оператора исполнитель ничего не делает — тест.
- [ ] Исполнитель отвечает на доске итогом (`done`/`failed` с выводом команды, обрезанным).
- [ ] Ключ исполнителя отличен от ключей узлов и оператора; в песочницах его нет.
- [ ] `bash dev/check.sh` зелёный.

## Проверки
```
bash dev/check.sh
```

## Ограничения
- ADR-033: в песочнице агента нет Docker и ключей; выход наружу — только через гранты.
- Новый способ исполнения на хосте — оформить ADR (надзор) после ответов оператора.

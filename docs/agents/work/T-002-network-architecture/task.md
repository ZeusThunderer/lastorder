# T-002. Архитектура сети узлов (NETWORK.md) и порты

## Цель
Появляется `docs/architecture/NETWORK.md` — архитектура сети Last Order: контуры с разной скоростью,
процессы, данные, вызовы LLM с бюджетом, жизненный цикл узла, цели и общение на уровне схемы.
Порты из документа записаны кодом в `runtime/ports.py` и импортируются тестом. По этому документу
надзор нарезает задачи реализации.

Критичность: документ задаёт устройство всех критичных зон (смерть → завещание, hive, perception,
вызовы LLM), поэтому проверка построчная, без headless.

## Контекст
Требования пользователя 2026-10-16 (R1–R7) — [prototype-plan.md](../../prototype-plan.md), раздел
«Пересмотр 2026-10-16». Принятые решения, их не переигрывать:
- ADR-001 (контуры), ADR-003 (uc), ADR-012 (чат — наблюдение), ADR-015…018, ADR-020…023 —
  `docs/architecture/DECISIONS.md`;
- контуры C0–C4 и порты одного персонажа — `docs/architecture/ARCHITECTURE.md` §3–5, §9;
- память сети — `docs/architecture/KNOWLEDGE.md`; бриф — `docs/character/LAST_ORDER.md`;
- находки E1 по телу: `docs/agents/unionclef-bridge.md`, CLAUDE.md «Ловушки»;
- что уже есть в коде: `runtime/lastorder/{traits,naming,persona}.py`, `runtime/llm/client.py`,
  `runtime/perception/translate.py`, `tools/body_probe.py`, `docker/compose.yml`.

Каркас контуров, от которого отталкиваться (можно менять с обоснованием):

| Контур | Где | Темп | Уровень LLM |
|---|---|---|---|
| C0 рефлекс | внутри uc | 20 Гц | — |
| C1 тактика | mind-N | 1–4 Гц + события | правила, затем `jev` |
| C2 шаг узла | mind-N | 8–15 с + события | `node` |
| C3 общение | mind-N + режиссёр в hive | по событию | `node` (болтовня в лимите) |
| C4 рефлексия и завещание | mind-N | 5–10 мин, смерть | `smart` |
| C5 сеть «Last Order» | hive | минуты | правила + редкий `smart` |

## Критерии приёмки
- [ ] В NETWORK.md есть разделы:
  1. матрица требований R1–R7 → раздел документа → ADR;
  2. контуры: таблица (темп, вход, выход, уровень LLM, кто пишет какие данные, таймаут и поведение
     при сбое) + mermaid-схема; кто и как управляет телом (арбитраж C0/C1/C2);
  3. процессы и транспорт: что крутится в `mind-N`, `hive`, `jev`; HTTP или Redis Streams (ADR-006) —
     выбор с причиной;
  4. порты: список с сигнатурами — те же, что в `runtime/ports.py`;
  5. данные: схема наблюдения (режимы `plain` и `masked`), схема JSON-ответа шага, конверт события;
  6. реестр вызовов LLM: каждый вызов — контур, уровень, триггер, частота, токены вход/выход,
     стоимость в час на 3 узла по ценам из шорт-листа T-004 (раздел «Пересмотр» в prototype-plan.md);
     итог ≤ $0.25/ч или явная пометка превышения с вариантами;
  7. жизненный цикл узла: рождение → жизнь → смерть (в том числе 45 мин и застревание) → рефлексия и
     завещание → retire → respawn → birth; аварийное завещание; mermaid-схема;
  8. цели (ADR-021), общение (ADR-022), знания и завещания (ADR-017, ADR-020) — на уровне потоков
     данных и владельцев; детальные схемы — задачи T-007 и T-008;
  9. ресурсы и отказы: таблица отказов и деградации по образцу ARCHITECTURE §9; наблюдаемость
     (что пишется в `log.jsonl`, отладочный лог промптов, метрики поколений);
  10. R7 — каждая тема из списка в разделе «Пересмотр» prototype-plan.md: MVP / позже / нет и точка
      подключения в архитектуре;
  11. предложение по задачам реализации: сверка с черновиками T-007…T-019 в BOARD, что поменять;
  12. открытые вопросы пользователю — списком, без самостоятельного выбора.
- [ ] `runtime/ports.py` содержит порты из раздела 4; `uv run pytest tests/test_ports.py` импортирует
  модуль и проверяет, что каждый порт — `typing.Protocol`.
- [ ] В документе нет решений, противоречащих ADR-012, 017, 018, 020–023; несогласие — только в
  «Предлагаемые ADR».
- [ ] Ни одного нового вида вызова LLM сверх ADR-022 (шаг, рефлексия, завещание, сеть, болтовня).

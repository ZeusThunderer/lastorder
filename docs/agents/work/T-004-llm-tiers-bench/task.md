# T-004. Уровни LLM в клиенте и замер моделей-кандидатов

## Цель
1. Клиент LLM знает уровни `node` и `smart` из ADR-023: модель и параметры каждого уровня задаются
   в env, код вызывает уровень, а не модель.
2. Есть `dev/llm_bench.py` и отчёт замера кандидатов на типовых запросах сети. По отчёту надзор и
   пользователь выбирают по одной модели на уровень.

## Контекст
- ADR-023 (уровни, бюджет ≤ $0.25/ч на 3 узла), ADR-022 (какие вызовы вообще бывают).
- `runtime/llm/client.py`: `LLMConfig.from_env()` (`LLM_MODEL`, `LLM_API_BASE`, `LLM_REASONING_OFF`, …),
  `LLMClient.complete` / `complete_json`, `parse_json_object`.
- Образец прогона: `tools/snapshot_replies.py`, результаты `docs/agents/snapshots/2026-10-14-*.md`
  (модель `openrouter/xiaomi/mimo-v2.6-flash`).

## Критерии приёмки
- [ ] `LLMConfig.for_tier("node" | "smart")` читает `LLM_NODE_MODEL`, `LLM_SMART_MODEL` и
  параметры уровня (`LLM_<TIER>_API_BASE`, `_REASONING_OFF`, `_MAX_TOKENS`, `_TEMPERATURE`,
  `_TIMEOUT_S`); без переменных уровня — откат на текущие `LLM_*`. Старый `from_env()` работает.
  Покрыто тестом с подменой env.
- [ ] `LLMClient` сообщает по каждому вызову: модель, токены вход/выход, задержку, стоимость (через
  LiteLLM, если провайдер её отдаёт). Тест на разбор с подставным ответом.
- [ ] `dev/llm_bench.py --tier node|smart --models a,b,… --repeat N --max-usd X`:
  - случаи `node`: шаг узла (наблюдение в режиме `plain` → JSON с выбором варианта из списка,
    `say` по-русски, необязательными `note` и `msg`), 3 запроса из task1 через `snapshot_replies`;
  - случаи `smart`: рефлексия (события → core memory ≤1.5 KB + ≤3 кандидата знаний JSON по
    KNOWLEDGE.md §2), завещание (2–4 строки, один урок, одна шутка), сводка целей сети (вход —
    условная сводка базы);
  - входы случаев — файлы в `dev/bench_cases/`, схема JSON шага помечена как предварительная (её
    уточнит T-002/T-011);
  - останавливается, если накопленная стоимость прогона превысила `--max-usd`.
- [ ] Метрики на модель: доля валидного JSON, доля ответов по схеме, задержка p50/p95, средние токены,
  стоимость случая и пересчёт «3 узла в час» по реестру вызовов ADR-022/KNOWLEDGE.md §5, доля
  кириллицы, нарушения правил стиля (эмодзи, > 3 предложений в шаге, числа черт в речи).
- [ ] Отчёт `docs/agents/llm-bench/2026-10-XX.md`: таблица метрик, по 2 сырых ответа каждой модели на
  каждый случай, рекомендация по одной модели на уровень с причиной. Выбор за надзором и пользователем.
- [ ] Суммарная стоимость всех прогонов задачи ≤ $1, указана в отчёте.

## Проверки
```
uv run pytest
python tools/check.py
uv run python dev/llm_bench.py --tier node --models <2 дешёвых> --repeat 1 --max-usd 0.05
```

## Ограничения
- `.env` и `NetTyan/.env*` — секреты: значения не читать и не печатать, ключи только из окружения.
- Вызовы в бенче — инструмент разработки, не новый вызов рантайма. В `runtime/` новых вызовов нет.
- Сырые ответы моделей с персонажем — по-русски; в отчёте не выводить числа черт как оценку речи.
- Промпт персонажа не правится в этой задаче.

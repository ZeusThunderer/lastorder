# T-045. Сёстры на Pi — адаптер раннера, жизнь и воля в Pi, запасной OpenCode с тревогой

## Цель
Сестра живёт в сессии Pi на Z.ai Coding Plan: жизнь, волевая сессия, архив — как сейчас, но
оператор видит её в HAPI, говорит с ней посреди жизни и ставит ей задачи на доске. При отказе Z.ai — OpenCode
через шлюз и тревога оператору. Сестра знает, что оператор есть, и может написать ему первой.

## Контекст
- ADR-041, ADR-042. Сестра запускается через `hapi pi` (как — отчёт T-044). Адаптеры: `runtime/node/adapters.py` (`OpenCodeAdapter`, `HermesAdapter` — образец,
  `:166–:250`); переключение харнесса и отказ — `NODE_HARNESS`, `NODE_HARNESS_FAILOVER` в
  `runtime/node/runner.py`; конфиг рабочего места — `runtime/node/workplace.py` (Pi — T-041).
- Доставка доски, Мисака-нет и событий — `misaka-link` (T-048); доска — T-042; HAPI — T-044.
  stdin Pi держит HAPI: id сессии и расход адаптер берёт из файла сессии Pi (вопросы 2–3
  отчёта T-044). Запасной OpenCode — через `hapi opencode`, если T-044 подтвердил, иначе
  напрямую, как сейчас.
- Ревью T-041 R2-3: конфиги Pi (root 0444) лежат в каталоге сестры (0700), и она может их
  подменить. Конфиги — в каталог root, писать сестра может только в `sessions/`; или
  перерендер на каждую сессию.
- Воля: контракт T-040; прокси волевой сессии — `runtime/node/willproxy.py`.
- Инструкции сестры: `agent/last_order/AGENTS.md` и навыки в `agent/last_order/skills/`.

## Объём
Можно трогать:
- `runtime/node/adapters.py`, `runtime/node/runner.py`, `runtime/node/workplace.py`,
  `runtime/node/config.py`
- `docker/compose.yml` — env `node-N` (по умолчанию `NODE_HARNESS=pi`); сеть `node-2`, `node-3`
  до `hapi-hub` — как у `node-1` в T-044
- `agent/last_order/AGENTS.md` — коротко, по `docs/architecture/TASKBOARD.md`, раздел 13
  (ADR-042); строка про `inbox` — Мисака-нет теперь приходит конвертом `misaka-link` (T-048):
  - голос оператора в чате — наблюдение;
  - задача оператора на доске — сильная просьба: высший приоритет, отказ — с причиной на доске;
  - задачи Last Order и сестёр — совет;
  - запросы и сообщения оператору — на доске, по своему усмотрению (talkativeness), в пределах
    потолка
- `tests/test_node_runner.py` и соседние
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`

## Критерии приёмки
- [ ] `PiAdapter`: команда `hapi pi`, id сессии и учёт расхода из файла сессии Pi — тесты argv
  и разбора по образцу Hermes.
- [ ] R2-3 T-041: сестра не может подменить конфиги Pi — тест.
- [ ] Раннер ставит тревоги `harness_failover`, `session_missing`, `stuck`, `quota`,
  `emergency_will` (TASKBOARD.md, раздел 7) через `board_alarm` — тест.
- [ ] Жизнь и волевая сессия идут в Pi; аварийная воля при таймауте — как прежде — тест.
- [ ] Отказ Z.ai → OpenCode через шлюз + тревога на доске — тест.
- [ ] Hermes и OpenCode остаются выбираемыми через `NODE_HARNESS` — тест.
- [ ] Прогон на стенде, 3 слота, 30 мин: в HAPI видны все три сестры; оператор (исполнитель)
  один раз пишет живой сестре в чат и ставит одну задачу `net` на доске; видно, кто взял задачу
  или отказался; хотя бы одна воля
  доходит от агента (T-040). Выводы, расход квоты и денег — в отчёте.

### Сделано
- `dev/measure_resources.py` — снимает `docker stats --no-stream` N раз с интервалом по сервисам
  стенда, печатает среднее и максимум RAM (MiB) и CPU (%) в markdown-таблице. Отказывается
  работать, если запрошенного сервиса нет.

    `BODY_SIM_DISTANCE=5`, `BODY_MAX_FPS=10` (вынесены в якорь `&body-env`).
- `docker/body/entrypoint.sh`:
  - `options.txt` переписывается на каждом старте, как остальные настройки (том со старым
    стендом больше не держит устаревший renderDistance);

  - `-Xms512M` → `-Xms${BODY_XMS:-256M}`.
- `docs/agents/docker-topology.md` — раздел «Ресурсы» переписан цифрами T-003.

### Итог по критериям
- Тело ≤ 1,2 ГБ в покое: **да после чистого входа** (1170–1243 МиБ в строках 2–5); после
  тяжёлой сессии (эксплорация, реконнекты) — до 1,46 ГБ: G1-куча Xmx1G и нативная память
  не отдаются мгновенно, потолок держит `mem_limit 2g`. Причина и лучший вариант — в таблице.
- Сервер ≤ 1,8 ГБ с одним телом: **да** во всех замерах (1494–1761 МиБ, включая нагрузку
  генерацией чанков на свежей местности, CPU max 858%).

### Отклонения от задачи
- Моды производительности сервера (Lithium/FerriteCore через TYPE=FABRIC) не ставил: registry
  Docker Hub в сессию регулярно отдавал TLS handshake timeout (сборки падали на `FROM`),
  качать новые jar с пиннингом sha256 было бы ненадёжно; цель по ресурсам достигнута без модов.
- `pause-when-empty-seconds` не применим: тело — постоянный игрок, сервер не бывает пустым.
- Первый старт: загрузки ~540 МБ ассетов не избегаем (HeadlessMC качает индекс целиком);
  это разовые затраты в volume `body-N`, на RAM в покое не влияет.

### Вне задачи
- Registry-таймауты ломают пересборку образов (`python:3.12-slim`, `eclipse-temurin`) —
  сеть хоста; воспроизводимо в течение дня, сборки удаются со 2-й–3-й попытки.
- Смерть от зомби во время замеров подтверждает: `onDeath` молчит и на смерти от мобов
  (в чате «was slain by Zombie», колбэк не пришёл) — учтено в T-006/T-013.

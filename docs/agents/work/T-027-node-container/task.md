# T-027. Контейнер узла node-N — песочница, раннер с адаптерами харнесса, архив

## Цель
Слот живёт целиком без человека: `node-1` рождает сестру на рабочем месте из шаблона, держит её длинную
сессию харнесса, по смерти открывает сессию завещания, при таймауте пишет аварийное, архивирует рабочее
место и рождает следующую. Песочница закрыта по ADR-033. Второй и третий слоты — тот же сервис
с другим номером.

## Контекст
- NETWORK.md v2 §3 (раннер), §6 (жизненный цикл), §9 (отказы); ADR-032…035.
- Выбор харнесса и рецепт его запуска — `docs/agents/harness-spike.md` (T-024).
- MCP тела (T-025), MCP сети (T-028), шлюз (T-026), шаблон сестры (T-029).
- `runtime/hive/client.py` (`birth`, `retire`), `runtime/lastorder/{will,lifecycle,traits,naming}.py`.

## Объём
Можно трогать:
- `runtime/node/` (новый: раннер, адаптеры `opencode` и `zcode`)
- `docker/node/` (новый образ), `docker/compose.yml` — сервисы `node-1..3`, `body-2..3`, `mind-2..3`,
  сети, volume `workplaces`, лимиты CPU и RAM
- `tests/test_node_runner.py` (новый)
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env`
- `agent/last_order/` — шаблон ведёт T-029; дефект — в отчёт

## Критерии приёмки
- [ ] Сеть: из `node-N` доступны только `mind-N` (MCP), `hive` (MCP), `llm-gateway` и Z.ai; py4j, RCON,
  `mc-server` и интернет — нет. Проверка командами из контейнера, вывод в отчёте.
- [ ] Рождение: черты, номер (`birth`), `agent/<serial>/` из шаблона T-029 с ядром только на чтение,
  запуск длинной сессии. Тест с подставным харнессом.
- [ ] Падение харнесса → перезапуск сессии с тем же рабочим местом, растущая пауза. Тест.
- [ ] Смерть: событие от `mind-N` или hive → стоп длинной сессии → сессия завещания с таймаутом →
  `submit_will` или аварийное завещание (`will.py`) → `retire` → архив (только чтение) → `respawn` →
  следующее рождение. Тест на оба исхода завещания.
- [ ] Адаптер харнесса выбирается конфигом (`HARNESS=opencode|zcode`); квота кончилась → по настройке
  переключение на другой адаптер или «ждёт». Тест.
- [ ] Лимиты CPU и RAM по замеру T-024; 3 слота в compose.
- [ ] Прогон на стенде: 1 слот до двух смертей или 50 мин — два `will.md`, архив первой сестры, вторая
  в первых репликах ссылается на первую (цитата). Затем 3 слота 15 мин — все живут.

## Проверки
```
uv run pytest
uv run python tools/check.py
docker compose -f docker/compose.yml up -d
```

## Ограничения
- Раннер не задаёт ритм агенту и не решает за него (ADR-035). Смерти без завещания нет.
- Ключей провайдеров в `node-N` нет; токен Z.ai — исключение ADR-033.

## Заметки надзора
- 2026-10-17 · утверждена пользователем.
- 2026-10-18 · контракт из T-025 (review раунд 2): раннер опрашивает `GET /runner/status` у `mind-N`,
  респавн — `POST /runner/respawn`. Часы жизни взводятся один раз за жизнь (`NODE_*` при старте или
  `POST /runner/birth` после респавна), повторный birth → 409. Раннер взводит их до старта сессии
  агента, иначе агент из `bash` может взвести чужой serial первым.

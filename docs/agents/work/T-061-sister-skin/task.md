# T-061. Скин сестёр — тела LastOrder01..03 в скине sister.png на своём и внешнем сервере

## Цель
Все тела `LastOrder01..03` в игре выглядят как сёстры: скин `agent/last_order/skin/sister.png`
(64×64, slim-руки) видят другие игроки на `mc-server` и, если сервер позволяет, на внешнем.
Скин ставит среда при входе в мир, а не агент.

## Контекст
- Скин выбран оператором 2026-10-31: `agent/last_order/skin/README.md` (источники, что взято).
- Аккаунты офлайн (`ONLINE_MODE: FALSE`, `docker/compose.yml:132`), поэтому скин раздаёт сервер.
  `mc-server` — `itzg/minecraft-server`, `TYPE: VANILLA` (`docker/compose.yml:126-143`), плагинов
  и модов нет. Нужен серверный плагин или мод скинов (README: «нужен плагин скинов»).
- Варианты [предположение, проверить]: Paper + SkinsRestorer (itzg: `TYPE: PAPER`, `PLUGINS` или
  `MODRINTH_PROJECTS`); Fabric-сервер + мод скинов (FabricTailor и т. п.). Многие плагины
  загружают скин через внешний сервис (MineSkin) — это выход наружу из `mc-server`, записать.
  Мир на `world` должен открыться без потерь.
- Внешний сервер (mc.example.net): если на нём есть команда скинов (`/skin …`), среда шлёт её после
  `/login` тем же путём, что вход в T-053. Если нет — записать, что скин там не ставится.
- `agent/last_order/` — шаблон рабочего места сестры, его копирует `shutil.copytree`
  (`runtime/node/workplace.py:538`). Каталог `skin/` в рабочее место сестры не нужен.

## Объём
Можно трогать:
- `docker/compose.yml` — `mc-server`: тип сервера и плагин/мод скинов (критичная зона только если
  меняются сеть и bind-mount);
- `docker/mc-server/` — новый, если нужны файлы настроек плагина;
- `runtime/mind/` — команда скина после входа для внешнего сервера (через механизм T-053);
- `runtime/node/workplace.py` — исключить `skin/` из копии шаблона;
- `dev/apply_skin.sh` (или `.py`) — поставить скин всем телам на поднятом стенде одной командой;
- `docs/agents/docker-topology.md` — как сменить скин;
- `tests/`.

Нельзя трогать:
- `agent/last_order/skin/` — файлы оператора, только читать
- `unionclef/`, `NetTyan/`, `task1.md`, `.env*`

## Критерии приёмки
- [ ] Выбранный способ для `mc-server` и почему (в отчёте; ссылки на плагин или мод и его версию
  для 1.21.11). Мир `world` после смены типа сервера открывается: выдержка лога `mc-server`.
- [ ] На стенде все поднятые тела в скине `sister.png` без ручных шагов после `up.sh`: скриншот или
  проверка по API плагина (`docker exec … rcon-cli …`) в отчёте. Финальный взгляд клиентом — за
  оператором, записать в рецепт.
- [ ] Скин переживает перезапуск `body-N` и `mc-server`.
- [ ] Внешний сервер: есть ли там команда скина; если есть — среда шлёт её после входа, тест с
  фейковым телом; если нет — так и написано в отчёте.
- [ ] Рабочее место новой сестры не содержит `skin/` — тест.
- [ ] `bash dev/check.sh` зелёный.

## Ограничения
- Скин ставит среда; в инструментах сестры команды скина нет (выбор оператора, не сестры).
- Новый выход наружу из `mc-server` (загрузка скина) — записать в отчёт и в `docker-topology.md`.
- Перед подъёмом сверить с оператором, чей стенд поднят; мир не пересоздавать.

# T-053. Команды сервера сестре — рычаг server_command по списку стенда и вход /login средой

## Цель
Задача оператора, которой нужна команда сервера (пример: `/warp pers`), выполнима: у сестры есть
инструмент `server_command`, который пропускает только команды из списка стенда для сервера её
слота. На внешнем сервере `mind-N` сам входит (`/login`) при входе в мир, пароль агенту не виден.

## Контекст
- ADR-043 (решение), ADR-037 (было: команд сервера нет), ADR-013 (список хостов).
- Сейчас: `check_say` отвергает `/` — `runtime/mind/mcp_body.py:259`; `say` →
  `body.act("chat")` — `runtime/mind/mcp_body.py:380-388`; рычаг `chat` шлёт текст как есть
  через `mc.ChatMessage` — `runtime/game/py4j_body.py:161`.
- **Главный риск.** Не проверено, исполняет ли `ChatMessage("/…")` команду или публикует строку
  в чат. Если публикует — `/login <пароль>` уйдёт в общий чат. Сначала выяснить по исходникам uc
  (`unionclef/`, только чтение: `Py4jEntryPoint`, отправка чата и команд в 1.21.11) и проверить
  безвредной командой на `mc-server` (например `/help`): строки в чате сервера быть не должно.
  Пока не доказано, пароль никуда не отправлять.
- Слот 1 может стоять на внешнем сервере: `MC_SERVER_1` (ветка T-052, `docker/compose.yml`).
- Задача `/warp pers` из прогона T-052 — пример для теста и рецепта.

## Объём
Можно трогать:
- `runtime/mind/mcp_body.py` — инструмент `server_command`, проверка по списку;
- `runtime/mind/executor.py` или новый `runtime/mind/login.py` — вход при входе в мир;
- `runtime/game/py4j_body.py` — рычаг отправки команды, если `chat` для этого не годится;
- `runtime/perception/` — только если ответ сервера режется фильтром (критичная зона);
- `docker/compose.yml`, `docker/node/up.sh`, `.env.example` — переменные списка и пароля по слоту;
- `agent/last_order/AGENTS.md` (инструкции сестры, шаблон рабочего места) — одна-две фразы про
  `server_command`; ядро `agent/last_order/prompt_template.md` не трогать;
- `tests/` — новые тесты;
- `docs/agents/docker-topology.md` — как оператор задаёт список и пароль.

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env` (только `.env.example`)
- `say` не получает `/`; `@gamer` и сырые команды uc агенту не открываются.

## Критерии приёмки
- [ ] В отчёте — как uc отправляет команду (файл:строка в `unionclef/`) и прогон безвредной
  команды на `mc-server`: команда исполнена, в чате сервера её текста нет.
- [ ] `server_command` есть в MCP тела. Список шаблонов — из конфига стенда на слот
  (например `MC_SERVER_COMMANDS_N`), по умолчанию пуст. Тесты: разрешённая команда уходит в тело;
  не из списка — отказ со списком разрешённого; перевод строки, `;`, `§`, длина сверх предела,
  `/login`, `/register` — отказ даже при широком шаблоне; частота ограничена как у `say`.
- [ ] Вход: если для слота задан пароль (`MC_LOGIN_PASSWORD_N`), `mind-N` при входе в мир шлёт
  `/login` (и `/register`, если сервер просит). Пароль не попадает в лог `mind-N`, ответы MCP,
  события и `chat.line` — тест с фейковым телом проверяет маскировку.
- [ ] Пароль и список проходят через `up.sh` в `mind-N` и только туда; в `node-N` их нет
  (проверка `docker compose config` в отчёте).
- [ ] Шаблон сестры: где описано, чем отвечать на задачу с командой сервера; без правил про
  конкретные команды.
- [ ] `bash dev/check.sh` зелёный.

## Проверки
```
bash dev/check.sh
uv run pytest tests -k "server_command or login"
```

## Ограничения
- Сырых команд uc, `@gamer` и команд сервера вне списка в инструментах нет (CLAUDE.md, ADR-043).
- Секреты: `.env` не коммитится, пароль — только в `mind-N`. `docker/` в части секретов —
  критичная зона.
- Поведение — в инструкциях, в коде только рычаг и проверка (ADR-032).
- Прогон на внешнем сервере — в T-058, здесь только `mc-server`.

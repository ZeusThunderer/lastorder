### Находки
- R1-1 · blocker · `dev/stand_keys.py:55-58` · `MC_LOGIN_PASSWORD_1..3` добавлены в `LOCAL_TOKENS`, а
  `cmd_init` (`:154`) генерирует `secrets.token_urlsafe` для каждого имени этого списка. Комментарий
  «never generated here» противоречит коду — проверено запуском `init` на временном `.env`. Штатный
  порядок подъёма стенда (`init` → …) включает вход на всех трёх слотах со случайным паролем, которого
  оператор не знает. На внешнем сервере с authme это значит: свободный аккаунт регистрируется
  неизвестным паролем и теряется, занятый получает неверный `/login` и может уйти в бан за
  перебор. · Ожидается: пароли слотов **не генерируются**. Вынести их в отдельный список «операторских» имён
  (как `PROVIDER_KEYS`: init не пишет значение, только при желании называет). В
  `tests/test_stand_keys.py` добавить этот список в `known` и написать тест «после `init`
  `MC_LOGIN_PASSWORD_N` пусты или отсутствуют». `tests/` и `dev/stand_keys.py` для этого можно трогать.
- R1-2 · minor · `runtime/mind/mcp_body.py:325` · `check_server_command("/")` (и `"/   "` после strip
  это `"/"`) падает `IndexError`, а не `ToolError` с причиной. · Отказ `server_command: empty command name`
  и тест на него.
- R1-3 · minor · `runtime/mind/mcp_body.py:738-742` · в `parse_deny` передаётся кортеж `DEFAULT_DENY`
  целиком, `str(tuple)` превращается в мусорные имена `('login'`, `'l'`… Работает только потому, что
  `check_server_command` и так объединяет список с `DEFAULT_DENY`. · Передавать `*DEFAULT_DENY` или
  вообще не передавать (дефолт уже неотменяем в проверке).
- R1-4 · minor · `runtime/mind/executor.py:485` · текст исключения из `on_tick` пишется в лог без маски.
  Если рычаг упадёт с сообщением, в котором есть аргумент вызова, пароль попадёт в лог `mind-N`.
  · Пропускать `str(exc)` через `self._login.mask(...)`.

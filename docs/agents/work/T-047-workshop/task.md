# T-047. Мастерская Last Order — свои расширения Pi, перезагрузка, публикация инструментов сёстрам

## Цель
Last Order пишет инструменты сама: расширения Pi в своей `workshop/`, подключает их себе без
помощи разработчиков и публикует сёстрам. Сёстры получают опубликованные инструменты при
рождении; свои пишут в своём рабочем месте и предлагают в общее через Last Order. После задачи
оператор может сказать Last Order «сделай канал в Telegram для последних слов» — и дальше это её
работа.

## Контекст
- ADR-041 (мастерская), ADR-031 (умение = код), ADR-034 (своё — свободно, общее — предложением).
- Расширения Pi: `pi.registerTool`, перезагрузка `/reload` (в RPC — проверить, T-041).
- Публикация идёт через hive (единственный писатель базы, ADR-017): `knowledge/tools/<name>/`
  под git с автором и причиной, как решения `decide` (`runtime/hive/proposals.py`).
- Гранты и исполнение кода с секретом — T-046 (вариант А или Б — из её отчёта).
- **`draft`**: «Объём» и критерии уточняются по итогам T-041 (перезагрузка в RPC) и T-046
  (где исполняется код с секретом).

## Объём
Можно трогать:
- `runtime/hive/` — публикация и выдача инструментов; `runtime/hive/admin.py` — `workshop/` в
  рабочем месте Last Order
- `runtime/node/workplace.py` — загрузка опубликованных инструментов при рождении
- `runtime/pi/` — загрузчик расширений из `workshop/` и общих инструментов (среда)
- `agent/network/AGENTS.md`, `agent/last_order/AGENTS.md` — коротко о мастерской
- тесты
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`
- ядро личности сестёр и Last Order
- не писать ни одного инструмента-возможности для Last Order или сестёр

## Критерии приёмки
- [ ] Расширение, которое Last Order написала в `workshop/`, подключается к её живой сессии
  её же действием (перезагрузка) — тест и проверка на стенде.
- [ ] Публикация: инструмент попадает в `knowledge/tools/<name>/` через hive с автором и
  причиной; следующая родившаяся сестра его видит и вызывает — проверка на стенде.
- [ ] Сестра пишет свой инструмент в рабочем месте, он подключается к её сессии; предложение в
  общее идёт через Last Order — тест.
- [ ] Сломанное расширение не роняет сессию: ошибка видна агенту и оператору — тест.
- [ ] Проверка на стенде без помощи исполнителя в коде: оператор (исполнитель) просит Last Order
  в консоли сделать простой инструмент (например, «счётчик смертей сети») и раздать сёстрам; она
  делает это сама — выводы и расход в отчёте.

## Проверки
```
bash dev/check.sh
```

## Ограничения
- Общую базу пишет только hive. Ядро личности — только чтение.
- Песочницы сестёр: опубликованный инструмент не даёт им новых выходов наружу и секретов
  (T-046).
- Поведение — в инструкциях: когда и что строить, решает Last Order.

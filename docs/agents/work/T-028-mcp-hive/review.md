- P1-1 · major · шаг 4, идентификация · Карта `HIVE_MCP_NODE_KEYS` вида `7=sk-a;8=sk-b` задаётся
  в env при старте hive, а номера узлов выдаются при рождении, сквозные (00007 → 00008 в том же
  слоте). Статическая карта «номер → ключ» не знает будущих номеров. Ключи шлюза в T-026 — по
  слоту. Нужно: ключ → слот (`slot=key`), номер — текущий живой узел этого слота из
  `Lifecycle` (`alive()`/состояние слота). Тест: рождение нового номера в слоте — тот же ключ
  даёт новый номер, старый номер этим ключом недоступен.
- P1-2 · major · шаг 4, идентификация · «Ключ **или** заголовок `X-Runner-Node`»: заголовок без
  секрета ставит кто угодно в песочнице `node-N` (раннер и харнесс там вместе, ADR-033), и
  «чужой номер — отказ» не проверяется. Нужно: личность только по ключу; `X-Runner-Node`, если
  есть, — лишь сверка с номером из ключа (не совпал — отказ). Тест: заголовок с чужим номером без
  ключа и с чужим ключом — отказ.
- P1-3 · major · шаг 4, `submit_will` · Критерий — «только для умершей сестры». В плане проверка —
  заголовок `X-Runner-Session: will`, который агент в той же песочнице может выставить сам при
  жизни; к тому же общая проверка «номер умершей — отказ» противоречит `submit_will`, где номер
  как раз умерший. Нужно: у `submit_will` своя проверка — узел ещё не retired, а факт смерти
  известен hive (отметка `dead` в `Lifecycle` от сигнала смерти — `kill_confirmed`/новый
  `mark_dead`, если сигнала пока нет — заглушка-метод с тестом, разводка от `mind-N` в T-027);
  заголовок сессии — дополнительное условие, не единственное. Живой узел с заголовком `will` —
  отказ, тест. Если отметку смерти в hive без правки вне «Можно трогать» не сделать — `lo-blocked`
  с вопросом, а не обход.
- P1-4 · minor · шаг 3, `decide` · «Под git с автором и причиной»: в плане автор и причина лежат
  в proposal-файле. Пусть сообщение коммита тоже их несёт (`decide p-NNNN accept by last_order:
  <why>; proposer 00007`), тест читает `git log`.
- P1-5 · minor · шаг 3, инструкции · `base/instructions.md` — новый общий слой. В отчёте явно
  отметить, что доставку его в рабочее место сестры делает T-027/T-029, иначе принятая правка
  никем не читается. Ядро (`agent/last_order/prompt_template.md` и `agent/*/` вообще) — вне `base/`,
  отказ по пути уже есть в тестах плана — оставить.
- P1-6 · minor · шаг 4, `vote` · В плане не сказано, что делает `vote`: ожидаю обёртку над
  существующим `HiveService.submit_vote` (`Vote`) без новой логики; голос за своё предложение —
  как решает текущий store, отдельно не изобретать.

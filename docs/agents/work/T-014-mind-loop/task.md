# T-014. Цикл мозга — шаг узла C2 поверх C1, логи, один узел живёт

## Цель
`python -m runtime.mind` в контейнере `mind-1` живёт как узел. Шаг C2 раз в 8–15 с и по событиям
зовёт `node`, его вариант исполняет C1. Попутно уходят `say`, `note`, `new_term`, `msg`, `votes`.
Смерть идёт путём T-013. Каждый шаг пишется в `log.jsonl`, каждый вызов LLM — в отладочный лог
промптов. Медленный контур не блокирует быстрый (R6). Критерий: один узел живёт до смерти или 45
мин, следующий ссылается на него.

## Контекст
- NETWORK.md §2 (C2: пол 8 с, события приближают шаг, но не учащают; 30 с таймаут → 2 повтора →
  «ждёт»), §5, §6 (потолок 450 шагов на узел в час), §7, §9 (наблюдаемость: что в `log.jsonl` и
  отладочном логе, вне git, volume `run`).
- Готовые части:
  - `runtime/mind/{observe,options,tactics}.py` (T-021);
  - `runtime/lastorder/step.py` (`build_step_prompt`, `parse_step_reply`, T-011);
  - `runtime/lastorder/{death,will,lifecycle}.py` (T-013);
  - `runtime/hive/client.py` (T-022);
  - `runtime/llm/client.py` (`for_tier`, `CallStats`).
- Попутные поля: `note` → `submit_candidate` (kind по T-007), `new_term` → кандидат `term`,
  `votes` → `submit_vote`, `msg` → `NodeComms.send` (канал `net`; канал `chat` и лимиты — T-017, здесь
  только `net`), `say` → игровой чат с лимитом `SAY_MIN_INTERVAL_S` (по умолчанию 20) в манере пресета.
- Рефлексия периодическая и при рождении — T-023; здесь рождение без неё (личная цель пустая).

## Критерии приёмки
- [ ] C2 в своём потоке: пол `STEP_MIN_S=8`, обычный интервал `STEP_MAX_S=15`; события
  (`game.damage`, новая сущность, `chat.line`, `node.message`, запрос C1) только приближают шаг к полу;
  события между шагами схлопываются в одно наблюдение. Тест с подставными часами: при 100 событиях за
  минуту шагов ≤ 8.
- [ ] Шаг не блокирует C1: пока идёт вызов LLM, C1 исполняет прежний intent; таймаут шага — C1
  продолжает. Тест с медленным подставным LLM.
- [ ] Сбои `node`: повтор с растущей паузой (2 повтора), три шага подряд без ответа → узел «ждёт»
  (`stop()` тела, пауза растёт до `WAIT_MAX_S`), выход по первому успешному шагу. Цикла без пауз нет.
  Тест.
- [ ] Ответ шага: `option_id` → intent C1; `say` → чат с лимитом; `note`, `new_term`, `votes`, `msg` → hive.
  Битый ответ → шаг пропущен, событие в лог. Тест на подставных hive и теле.
- [ ] Смерть: детектор T-013 на каждом тике C1; путь смерти ставит C1/C2 на паузу и возобновляет с
  новым узлом; выбранный вариант «устраниться» → `request_death(serial, "stuck")` и флаг причины. Тест.
- [ ] `run/<slot>/<serial>/log.jsonl`: на каждый шаг — ts, триггер, выжимка наблюдения, варианты,
  выбор, say, токены, задержка, стоимость; плюс birth, death, ошибки. `run/<slot>/<serial>/prompts.jsonl` —
  полный system/user и ответ каждого вызова LLM. В `masked` тест прогоняет `leaks()` по
  `prompts.jsonl`. Тест на формат строк.
- [ ] Конфиг из env с умолчаниями, неизвестный `PERCEPTION_MODE` или пресет → ошибка при старте.
- [ ] Прогон на стенде (`mc-server`, `hive`, `body-1`, `mind-1`) до двух смертей или 50 мин:
  - в `knowledge` ≥ 2 `will.md`;
  - в `run` логи двух узлов;
  - ≥ 1 `note` стал записью базы;
  - в первых 3 репликах второго узла есть ссылка на номер, термин или урок первого (ручная проверка,
    цитата в отчёте);
  - число шагов и вызовов, стоимость. ≤ $0.15 на прогон.

## Ограничения
- Телом управляет только C1; шаг выбирает лишь из вариантов кода; `@gamer` нет; чат и сообщения
  узлов — наблюдение (ADR-012, ADR-025).
- Вызовы: шаг (`node`) и завещание (`smart`, T-013). Других нет.
- Общую базу пишет только hive. Черты числами в речь не выводятся; пресет не зашит.

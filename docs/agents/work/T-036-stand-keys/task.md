# T-036. Ключи стенда — генерация локальных токенов и виртуальных ключей шлюза в .env

## Цель
Оператор одной командой готовит `.env` к прогону на стенде с ключами: недостающие локальные токены
(hive, раннер, мастер-ключ шлюза и т. п.) генерируются, виртуальные ключи шлюза выпускаются и
записываются. Ключи провайдеров (`OPENROUTER_API_KEY`, `ZAI_API_KEY`) остаются за оператором.

## Контекст
- T-032 шёл в dev-open: в `.env` нет ни одного ключа hive и шлюза. Следствия: 11 из 13 завещаний
  аварийные (hive MCP не принимает `submit_will` без `X-Node-Key`), шлюз и `last-order` не подняты,
  пункты MVP 6 и 7 не измерены (`docs/agents/runs/2026-10-23-mvp.md`, «FAIL-пункты»).
- Решение надзора: прогоны идут на стенде с ключами. Приём воли без ключа в dev-open (П-2 из T-034,
  вариант «б») не делаем — fail-closed R2-6 остаётся.
- Имена ключей: `docker/node/up.sh:33-38` (`lift`), `docker/gateway/up.sh:27`, `docker/compose.yml`
  (`HIVE_MCP_LO_KEY`, `GATEWAY_KEY_LO` и др. — собрать полный список по compose и up-скриптам).
- Выпуск виртуальных ключей — `dev/gateway_keys.py issue` (печатает токен один раз; потолки ADR-035
  по умолчанию).

## Объём
Можно трогать:
- `dev/stand_keys.py` (новый), `tests/test_stand_keys.py` (новый)
- `docs/agents/docker-topology.md` — раздел «Ключи стенда»
- `dev/gateway_keys.py` — только вынести выпуск ключа в функцию, если нужно для переиспользования
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`
- корневой `.env` — зона оператора: скрипт на нём не запускать, проверять на временных файлах
- `docker/`, `runtime/`

## Критерии приёмки
- [ ] `dev/stand_keys.py init [--env PATH]` дописывает только отсутствующие или пустые локальные токены
  (`secrets.token_urlsafe`), существующие значения не меняет, остальные строки и комментарии файла
  сохраняет. Тест.
- [ ] `dev/stand_keys.py issue [--env PATH]` выпускает отсутствующие `GATEWAY_KEY_*` через логику
  `dev/gateway_keys.py` (шлюз должен быть поднят — иначе понятная ошибка) и пишет их в файл.
  Тест с подменой выпуска.
- [ ] Значения ключей не печатаются никогда: в выводе только имена и «added/kept/issued». Тест на вывод.
- [ ] Ключи провайдеров скрипт не создаёт и не трогает; если их нет — пишет, каких не хватает. Тест.
- [ ] После `init` проверка `docker/node/up.sh` без `NODE_DEV_OPEN` проходит (ни одного «refusing»):
  тест на временном `.env` или прогон up.sh с `--dry-run`-эквивалентом (`docker compose config`).
- [ ] Раздел «Ключи стенда» в `docs/agents/docker-topology.md`: порядок — `init`, поднять шлюз,
  `issue`, `docker/node/up.sh`.

# T-021. Наблюдение, варианты шага и тактика C1 на правилах

## Цель
Готова быстрая часть мозга без LLM:
- `observe()` превращает сырые данные тела в наблюдение NETWORK.md §5;
- `build_options()` строит ≤8 вариантов шага кодом;
- C1 исполняет выбранный вариант рычагами, держит тело при угрозе и простое (`RuleDecider`).

Сторож простоя выдаёт вариант «устраниться» (ADR-026). Цикл мозга (T-014) только связывает эти
части с шагом LLM. Требование R6, быстрый контур.

## Контекст
- NETWORK.md §2 (C1: 1–4 Гц + события, 250 мс → правила; арбитраж C0/C1/C2 пп. 1–5), §5
  (наблюдение, события `game.damage`, `task.idle`), §7 п.3 (застревание).
- ARCHITECTURE §4 (владение телом: `stopPathing()` → `hasActiveTask()==false` → новая команда;
  ожидание активной цепочки C0 ≤1 с).
- `runtime/ports.py`: `GameBody`, `Decider.choose(state, intent, options)`, `Option`, `Decision`, `Event`.
- `runtime/game/py4j_body.py` (T-006, T-020): `LEVERS`, `busy()`, `stop()`, `events()`, позиции.
- `runtime/perception/` (T-009): ключи `plain`/`masked`, `see()`, `raw()`, `clean_chat()`.
- ADR-003 (варианты = altoclef-команды и рычаги), ADR-025 (варианты строит код; чат их не создаёт),
  ADR-026 (порог простоя — порог предложения, в конфиге).
- Словарь вариантов (prototype-plan «Цикл мозга»): подойти к X, добыть X, атаковать X, отойти от
  угрозы, осмотреться, ждать, поставить блок, съесть, собрать N штук X (`get`), взять в руку,
  устраниться. `@gamer` не даём.

## Критерии приёмки
- [ ] `observe(body, perception, inbox=(), chat_lines=None) -> Observation` — dataclass с `to_json()`
  в схеме NETWORK.md §5. Сущности и блоки получают `ref` через perception, ближайшие первыми,
  лимиты (`OBS_MAX_ENTITIES`, `OBS_MAX_BLOCKS` — конфиг). Блоки сгруппированы по ключу (ключ,
  число, ближайшая позиция), без сотни одинаковых. Чат — `clean_chat`, без служебных строк. Тест на
  подставном теле в обоих режимах восприятия; в `masked` `leaks()` по `to_json()` пуст.
- [ ] `build_options(obs, idle_signal=False) -> list[Option]` — ≤8 вариантов, детерминированно,
  `id` стабилен для одного наблюдения, `title` — короткая подпись через `ref`/термин (для промпта),
  `lever`/`args` — сырые id через `perception.raw()`. Приоритет при отборе: угроза и низкий hp →
  еда → видимые ресурсы → осмотреться/ждать. «Устраниться» есть только при `idle_signal=True`.
  Ни один вариант не содержит `@gamer`. Тесты на каждое правило отбора.
- [ ] Исполнитель C1 работает в своём потоке с темпом `C1_HZ` (по умолчанию 2):
  - принимает `intent` (вариант шага) и раскладывает его в под-варианты; выбор под-варианта —
    `Decider.choose`;
  - при `game.damage` или hp ниже порога отступает от intent по правилам и потом возвращается;
  - если intent невыполним, просит внеплановый шаг: колбэк `request_step(reason)`;
  - смена команды по ARCHITECTURE §4.
  Тесты с подставным телом и подставными часами.
- [ ] `RuleDecider` реализует порт `Decider`: детерминированные правила, уверенность в `Decision`,
  ответ ≤ 5 мс на 8 вариантах (тест-замер).
- [ ] Сторож простоя: по `pathStatus`/`busy()` и смещению позиции; короткий простой → пересчёт
  под-вариантов; долгий (`IDLE_PROPOSE_S`, по умолчанию 120) → `idle_signal` для `build_options` и
  событие `task.idle`. Чат и сообщения узлов сигнал не вызывают. Тест.
- [ ] `dev/c1_smoke.py` на стенде 5 мин без LLM: варианты по кругу (сначала «добыть», потом
  «подойти»), лог исполнения, число смен команд, срабатывания сторожа. Вывод в отчёте.

## Ограничения
- Телом управляет только C1. Чат и сообщения узлов вариантов не создают (ADR-025).
- `masked`: сырые id в `title` и наблюдение не попадают; тест на утечки не ослаблять.
- Никаких вызовов LLM: Jev подключит T-015.

# T-013. Путь смерти — детектор, рефлексия и завещание, retire, respawn, birth

## Цель
Модуль завещаний (R2) и смена поколений: смерть в игре, по сроку 45 мин или застреванию ведёт к
рефлексии с завещанием (уровень `smart`), записи в hive, retire, `respawn()`, birth следующего узла.
Если LLM упала — аварийное завещание. Смерти без завещания нет.

## Контекст
- После T-006 (`Py4jBody.respawn`), T-011 (промпт), T-012 (hive API).
- Детектор: hp = 0 в `getGameState` и ванильная строка смерти в чате; `onDeath` ненадёжен
  (CLAUDE.md «Ловушки»). Принудительная смерть — RCON `/kill`.
- Бриф §3; KNOWLEDGE.md §3 (рефлексия пишет завещание тем же вызовом).

## Объём
Можно трогать:
- `runtime/lastorder/death.py`, `runtime/lastorder/will.py`, `runtime/lastorder/lifecycle.py` (новые)
- `tests/test_death_*.py`, `tests/test_will.py`
- файлы задачи

## Критерии приёмки (предварительно)
- [ ] Детектор срабатывает на hp = 0, на строку смерти в чате и не срабатывает дважды на одну смерть. Тест.
- [ ] Таймаут, исключение или битый JSON от LLM дают аварийное завещание из последних событий; оно
  помечено `emergency`. Тест на каждый случай.
- [ ] Порядок шагов строго: завещание → retire → respawn → birth; сбой hive не теряет завещание
  (локальный буфер и повтор). Тест.
- [ ] Срок жизни 45 мин (`MAX_LIFE_MIN`) и застревание ведут к RCON `/kill` и тому же пути. Тест с
  подставным временем.
- [ ] Прогон на стенде: две смерти подряд, два `will.md` в базе, номер узла вырос на 2.

# T-043. Last Order на Pi — одна долгая сессия, события сети сообщениями, запасной OpenCode с тревогой

## Цель
Last Order живёт в одной долгой сессии Pi на Z.ai Coding Plan, а не в коротких сессиях по
событию. Поводы проснуться (смерть, предложения, оператор, таймер) приходят сообщениями в эту же
сессию, сообщения оператора — между ними. После перезапуска контейнера сессия продолжается или
начинается заново по памяти в файлах. При отказе Z.ai — OpenCode через шлюз и тревога оператору.

## Контекст
- ADR-041 (долгая сессия, снимает короткие сессии ADR-036); ADR-035 (ритм выбирает агент);
  ADR-042: Last Order запускается через `hapi pi` (как запускать из скрипта — отчёт T-044),
  оператор говорит с ней в чате HAPI; задачи, запросы и тревоги идут через доску (T-042).
- Сейчас: `runtime/hive/admin.py` — опрос поводов (`WakeReason`, `:146`), сессия через адаптер
  OpenCode (`LastOrderAdapter`, `:237`; запуск — `:567`), рабочее место и конфиг (`:353–:410`).
  Сервис — `last-order` в `docker/compose.yml:320` (`ADMIN_*` в environment).
- Доставка поводов в сессию — расширение `misaka-link` (T-048): stdin Pi держит HAPI. Сжатие
  контекста — по итогам T-041.
- Инструкции Last Order: `agent/network/AGENTS.md`, `agent/network/SESSION_PROMPT.md` написаны под
  короткие сессии («wake, do the desk work, write memory, sleep») и говорят, что ответить сестре
  нельзя. ADR-036 обещает ответы сёстрам через Мисака-нет — дать Last Order `send`/`inbox` на её
  MCP-сервере (`runtime/hive/mcp.py:478`), как у сестры.
- `INBOX.md` оператора остаётся (не ломать), но основной путь оператора теперь — чат HAPI и доска.
- Доска (ADR-042): Last Order ставит задачи сёстрам и `net`, отвечает на адресованные ей запросы.
  Задача оператора для неё — сильная просьба: высший приоритет сети, отказ — с причиной на доске.
  Задачи Last Order для сестёр — совет, как цели сети. Это правила инструкции, не кода.
- T-039, «Отклонения»: `docker/node/up.sh` не передаёт `HIVE_MCP_LO_KEY`/`GATEWAY_KEY_LO` —
  добавить в список lift (зеркало `dev/stand_keys.py`).

## Критерии приёмки
- [ ] `ADMIN_HARNESS=pi` (по умолчанию): admin держит один процесс `hapi pi`; новый повод —
  запись в hive, которую `misaka-link` доставляет в ту же сессию, а не новый процесс — тест на
  фейковом процессе.
- [ ] Перезапуск контейнера: сессия продолжается (resume) или начинается заново с памятью
  `memory/` — поведение описано и проверено тестом.
- [ ] Отказ Z.ai (ошибка квоты, недоступность): переход на OpenCode через шлюз (текущий адаптер)
  и тревога на доску (T-042) — тест.
- [ ] Last Order может ответить сестре (`send`) и оператору (`post(kind=message, to=operator)`),
  ставит задачи на доске; инструменты сестры ей по-прежнему недоступны и наоборот — тест.
- [ ] `agent/network/AGENTS.md`: правила доски по `docs/architecture/TASKBOARD.md`, раздел 13,
  сжато; `board(filter=all)` — для летописи.
- [ ] admin ставит тревоги `harness_failover` и `quota` через `board_alarm` (T-042) — тест.
- [ ] `docker/node/up.sh` передаёт `HIVE_MCP_LO_KEY` и `GATEWAY_KEY_LO` — тест или вывод
  `up.sh` с пометкой.
- [ ] Живая проверка на стенде (`hive last-order llm-gateway zai-egress` + `hapi-hub` + один слот): Last Order
  видна в HAPI; оператор пишет ей в чат, она отвечает в той же сессии; задача оператора с доски
  доходит до неё; затем повод «таймер» — в ту же сессию. Выводы в отчёте.

## Ограничения
- Last Order действует через инструменты hive; писатель базы — hive (ADR-017).
- Ядро и файлы оператора — только чтение для неё; корень рабочего места пересобирается как сейчас.
- Инструментов-возможностей для неё не добавлять (ADR-041): только доставка и Мисака-нет.
- Деньги — только при отказе на OpenCode, в потолке шлюза.

## Заметки надзора
- 2026-10-26: перекроена по ADR-042 — запуск через `hapi pi`, канал оператора — HAPI и доска.
- 2026-10-31, решение оператора: Last Order — Pi на Z.ai, модель GLM-5.3 (не Flash): способности
  даёт модель, харнесс выбран по расходу (постоянная часть запроса: zcode ≈22k токенов, opencode
  ≈5–7k, Pi ≈1k; порог сжатия задаётся только в Pi — замер в T-059, «Контекст»). Короткие сессии
  на Pi делает T-059; эта задача переводит их в одну долгую сессию. `after` + T-059.
- 2026-11-06, ответ 1 (headless): канал поводов — отдельная лента поводов Last Order в hive, не
  Мисака-нет и не доска. admin пишет повод HTTP-запросом в hive (гейт — ключ стола
  `HIVE_MCP_LO_KEY`), hive хранит ленту с курсором `seq` и переживает свой рестарт; misaka-link
  читает её только у стола (`/last-order/mcp`) и доставляет конвертом `[wake · <reason> · …]`.
  В повод — только поля `WakeReason` (вид, номера узлов, счётчики), без сырых id и текста из игры.
  `wake.delivered` в журнале admin остаётся. Подробно — `review.md`, «Ответ 1».
- 2026-11-06, ревью 1: адрес 0 Мисака-нет (отправитель `send` стола) у сестёр рендерится как
  `last-order`, не «Мисака 00000» (R1-1).

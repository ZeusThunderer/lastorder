# T-012. Hive — реестр узлов и единственный писатель базы

## Цель
Сервис `hive`: сквозные номера узлов (birth/retire), черты и `birth.json`, приём кандидатов знаний,
голосов и завещаний, статусы по правилам KNOWLEDGE.md v2, git-коммит на изменение, выдача контекста
узлу. Требование R2 (хранение и определение знаний), часть R1.

## Контекст
- После T-007. Транспорт и API — из NETWORK.md (T-002).
- ADR-017, ADR-018; `runtime/lastorder/traits.py` (`roll`), `naming.py`.

## Объём
Можно трогать:
- `runtime/hive/` (новый), `runtime/knowledge/store.py` (новый)
- `docker/hive/` или сервис `hive` в `docker/compose.yml` (volume `knowledge`)
- `tests/test_hive_*.py`
- файлы задачи

## Критерии приёмки (предварительно)
- [ ] birth выдаёт следующий 5-значный номер атомарно при параллельных запросах из 3 слотов; черты
  пишутся в `nodes/<serial>/birth.json` и в лог. Тест.
- [ ] Кандидат-дубль (тот же `about`, похожий `claim`) становится evidence существующей записи. Тест.
- [ ] Статусы `hypothesis → confirmed / disputed → retired` по MVP-правилу. Тест.
- [ ] Каждое изменение базы — git-коммит в volume `knowledge`; узлы в git не пишут. Тест на временном репо.
- [ ] Праймер (T-010) загружается при пустой базе.
- [ ] Контекст узла: каталог, знания о видимых ключах, хвост свежих записей, ≤2 кандидата на оценку,
  завещания последних K, цели сети — в бюджете токенов T-007.

## Ограничения
- Hive — единственный писатель базы. Секреты — только из env.

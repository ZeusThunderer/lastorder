# T-019. Отчёт MVP и 2-часовой прогон сети

## Цель
`dev/mvp_report.py` считает критерий MVP по volume `knowledge` и логам `run-N`. Двухчасовой прогон трёх
слотов без вмешательства либо проходит критерий, либо даёт отчёт с причинами провала и задачами на
исправление.

## Контекст
- Критерий MVP — `docs/agents/prototype-plan.md`, раздел «Критерий MVP»:
  - ≥6 поколений;
  - разные черты в `birth.json`;
  - ≥70% новых узлов в первых 3 репликах ссылаются на предшественника: номер, термин или урок;
  - ни одной смерти без `will.md`;
  - ни одного сырого id в промптах в режиме `masked`.
- Раскладка данных: KNOWLEDGE.md v2 (volume `knowledge`: `nodes/<serial>/{birth.json,core.md,will.md}`,
  записи, `goals.json`); volume `run-N`: `<slot>/<serial>/{log.jsonl,prompts.jsonl}` (T-014).
- Бюджет: ≤ $0.25/ч на 3 узла (NETWORK.md §6, ADR-023); `CallStats` в логах (T-004, T-014).
- `runtime/perception/` — `leaks()` (masked), `clean_chat`/служебные строки (оба режима).

## Объём
Можно трогать:
- `dev/mvp_report.py` (новый), `tests/test_mvp_report.py` (новый)
- `docs/agents/runs/` (новый: отчёты прогонов)
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env`
- `runtime/`, `docker/` — найденные дефекты идут в отчёт как предложения задач, не чинятся здесь

## Критерии приёмки
- [ ] `dev/mvp_report.py --knowledge <dir> --run <dir>…` печатает и пишет в markdown:
  - число поколений по слотам, время жизни (медиана, min, max), причины смерти;
  - разброс черт (у каждого узла свой набор; одинаковых пар нет);
  - доля новых узлов со ссылкой на предшественника в первых 3 `say`: эвристика по номерам, терминам
    базы и словам завещания, у каждого совпадения — цитата;
  - смерти без `will.md` и доля аварийных завещаний;
  - `masked`: утечки сырых id в `prompts.jsonl`; оба режима: служебные строки uc в промптах;
  - вызовы и стоимость по уровням и в час, против $0.25/ч;
  - знания: записей по статусам, доля `confirmed`, вклад рефлексии и `note`;
  - сообщения: попутные по каналам, ходы болтовни;
  - итог: PASS/FAIL по каждому пункту критерия.
- [ ] `tests/test_mvp_report.py` на синтетических volume: случай PASS и случай FAIL по каждому пункту.
- [ ] Прогон: 3 слота, 2 часа, без вмешательства, `PERCEPTION_MODE=plain`. Отчёт
  `docs/agents/runs/<дата>-mvp.md`: вывод `mvp_report.py`, 3–5 цитат завещаний и реплик со ссылками
  на предшественников, график или таблица поколений, стоимость, инциденты (перезапуски, «ждёт»,
  откаты Jev). Стоимость прогона ≤ $0.60.
- [ ] Если FAIL: по каждому проваленному пункту — причина по логам и предлагаемая задача (заголовок,
  что трогать) в разделе «Вне задачи» отчёта.

## Проверки
```
uv run pytest
uv run python tools/check.py
uv run python dev/mvp_report.py --knowledge <volume> --run <volume-1> <volume-2> <volume-3>
```

## Ограничения
- Прогон не правит код по ходу. Остановка прогона из-за аварии — инцидент в отчёте, повтор — с
  согласования оператора.
- Ключи только из окружения; в отчётах прогона нет секретов.

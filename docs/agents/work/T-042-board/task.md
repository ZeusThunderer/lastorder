# T-042. Доска задач в hive — задачи, запросы, сообщения оператору, тревоги; страница оператора

## Цель
В hive есть доска. Оператор ставит задачу узлу, Last Order или всей сети. Агенты ставят задачи
и оставляют запросы разрешений и помощи. Тревоги среды видны оператору. Оператор работает с
доской на маленькой странице hive под паролем, агенты — через MCP hive.

## Контекст
- ADR-042 (доска, вес задачи оператора, страница); ADR-041 — в части, которую ADR-042 не снял.
  Режима «мысль» нет. Чат с агентом идёт через HAPI (T-044), а не через доску.
- Мисака-нет сейчас: `runtime/hive/mcp.py:245` `send(to, text)` (serial или `all`), `:276`
  `inbox`; сервер Last Order — `:448`; HTTP `/comms/send`, `/comms/inbox`
  (`runtime/hive/app.py:518`). Гейт по ключам — как у `/comms` (`app.py:412`).
- Запись: `id, kind: task|request|message|alarm, from: operator|last-order|<serial>,
  to: <serial>|last-order|net|operator, text, status, replies[]`. Статусы задачи:
  `open → taken → done|declined`. Статусы запроса: `open → approved|denied`. Отказ от задачи и
  ответ на запрос — с текстом.
- Кто что пишет (ADR-042):
  - оператор — всё, со страницы;
  - Last Order — задачи сёстрам и `net`, ответы на запросы, адресованные ей;
  - сестра — запросы оператору или Last Order, задачи сёстрам, `message` оператору.
- Адресат умер, задача открыта: задача уходит в `net` с пометкой, в журнале остаётся прежний
  адресат [предположение: решение надзора, оператор может поправить].
- Сообщения агентов оператору: потолок на одну жизнь, число — в конфиге hive, по умолчанию 5
  [предположение: подобрать по прогону T-045].
- Доставка новой записи в живую сессию Pi — не здесь, это T-048. Здесь — HTTP-лента (JSON + SSE),
  которую T-048 будет читать.
- Гранты (T-046) лягут на доску запросами `kind=request` с полем `grant`. Здесь поле только
  резервируется в схеме.

## Критерии приёмки
- [ ] HTTP оператора: создание задачи, сообщения и ответа на запрос — только с
  `HIVE_OPERATOR_KEY`. Без ключа — отказ (тест). `stand_keys.py` печатает только имя ключа.
- [ ] Права: сестра не может одобрить запрос; сестра не может писать от чужого имени; Last Order
  не ставит задачу оператору — тесты.
- [ ] Отказ от задачи без текста отклоняется — тест.
- [ ] Смерть адресата: открытая задача переходит в `net`, прежний адресат виден в журнале — тест.
- [ ] Потолок сообщений оператору на жизнь: сверх него — отказ с понятной причиной — тест.
- [ ] Лента: `GET /board/feed` (JSON с курсором) и SSE отдают новые записи и смены статуса —
  тест. `POST` тревоги — ключом раннера или admin — тест.
- [ ] Страница `/board` под паролем: список с фильтром по адресату, форма новой задачи, кнопки
  «одобрить» и «отклонить». Проверить на стенде (`hive` один): `curl` без пароля — 401, с
  паролем — 200; одна задача создана со страницы. Выводы — в отчёте.
- [ ] MCP: сестра и Last Order видят свои задачи и задачи `net`, пишут по правилам выше — тест на
  сервере MCP.

## Ограничения
- Общую базу пишет только hive; доска — не база знаний (ADR-017).
- Задача оператора — сильная просьба, но не приказ (ADR-042). В коде нет принуждения: правило
  будет в инструкциях.
- Сырых id и служебных строк uc в записях доски нет.
- Ключи — через `dev/stand_keys.py`. В песочницу ключ оператора не попадает.

# T-042. Доска задач в hive — хранилище, переходы, смерть, HTTP, лента, MCP-инструменты

## Цель
В hive работает доска по спецификации `docs/architecture/TASKBOARD.md`. Оператор (по HTTP),
Last Order и сёстры (по MCP) ставят задачи, берут их, оставляют запросы и отвечают. Раннер и
admin ставят тревоги. Смерть узла освобождает его задачи. Лента событий готова для доставки
(T-048) и для страницы (T-049).

## Контекст
- Спецификация — `docs/architecture/TASKBOARD.md`, разделы 2–10. Это источник истины. Расхождение
  кода со спецификацией — вопрос надзору в задаче, а не тихая правка.
- ADR-042: доска, вес задачи оператора. Режима «мысль» нет, чат — в HAPI (T-044).
- Образцы в коде:
  - личность по ключу — `runtime/hive/mcp.py:150–:190` (`X-Node-Key` → слот → serial, ключ
    Last Order);
  - гейт HTTP по ключу раннера — `runtime/hive/app.py:412–:428`;
  - Мисака-нет — `CommsBook` (`app.py:90`), проверка текста — `runtime/comms/schema.py`;
  - журнал — `HiveLog` (`runtime/hive/lifecycle.py:60`), `events.jsonl`;
  - смерть — `Lifecycle.mark_dead` (`lifecycle.py:260`).
- Хранилище — SQLite в `RUN_DIR` (том `hive-run` в `docker/compose.yml`), не в `KNOWLEDGE_DIR`.
- Поля `grant` в запросе только принимаются и хранятся (спецификация, 5.3). Создание гранта по
  одобрению делает T-046.
- Страница `GET /board` — T-049. Здесь — только API под ней.

## Объём
Можно трогать:
- `runtime/hive/board.py` — новое: модель, SQLite-хранилище, переходы, права, лимиты, журнал
- `runtime/hive/app.py` — маршруты `/board/*` (спецификация, раздел 9), включая SSE
  `/board/stream`; вызов доски из обработки смерти
- `runtime/hive/lifecycle.py` — только хук «узел умер» для доски, если без него не обойтись
- `runtime/hive/mcp.py` — инструменты `board`, `post`, `claim`, `update`, `reply` на серверах
  сестры и Last Order (раздел 10)
- `runtime/hive/client.py` — методы `board_alarm` для раннера и admin (без вызовов из них:
  это T-043 и T-045)
- `dev/stand_keys.py` — `HIVE_OPERATOR_KEY`; `docker/compose.yml` — env hive
  `HIVE_OPERATOR_KEY`, порт hive только на `127.0.0.1`
- `tests/test_hive_board*.py`
- `docs/architecture/NETWORK.md` — раздел «Доска»: 3–5 строк со ссылкой на `TASKBOARD.md`
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`
- `runtime/node/` (T-045), `runtime/hive/admin.py` (T-043)
- `agent/` — инструкции пишут T-043 и T-045
- `docs/architecture/TASKBOARD.md` — правки только через вопрос надзору
- `.env*` руками

## Критерии приёмки
Каждый пункт — тест в `tests/test_hive_board*.py`, если не сказано иное.
- [ ] Личность:
  - `from` в теле запроса → 422;
  - сестра пишет от serial своего слота;
  - слот без живого узла → 409 `no_live_node`;
  - HTTP без `X-Operator-Key` → 401.
- [ ] Матрица прав (3.3): по одному тесту на каждое «нет». В том числе: сестра не одобряет
  запрос, Last Order не ставит задачу оператору, `grant` от сестры → 422.
- [ ] Переходы (3.2): все разрешённые проходят, любой другой → 409 `bad_transition`. Конечные
  статусы не меняются. `declined`, `failed`, `needs_input`, отпустить задачу — без текста → 422.
  `declined` у задачи `net` → 409, нужен `reply`.
- [ ] Атомарное взятие: 10 потоков делают `claim` одной задачи — ровно один `taken`, у
  остальных 409 `already_taken`. Третья взятая задача у одной сестры → 409 `too_many_taken`.
- [ ] Смерть (4.3), всё в одной транзакции:
  - взятые задачи узла → `open` с системной репликой;
  - личные задачи узлу → `net` с `readdressed_from`;
  - запросы узла → `canceled` (`poster_dead`).
- [ ] Запросы (5): `edit+approve` возвращает агенту исправленные `args`; `respond` →
  `answered`; `action` > 64 символов или `args` > 10 ключей → 422.
- [ ] Лимиты (6): шестое сообщение оператору за жизнь → 429 `operator_cap`; запись агента сверх
  30 за жизнь → 429; текст > 800 → 422, без обрезки.
- [ ] Тревоги (7): ключом раннера или admin; ключом узла — только `delivery_failing`. Повтор `(type, from)` за 10 минут увеличивает
  `count`, а не создаёт запись.
- [ ] Журнал (8): каждая мутация — строка `board_log` с `before`/`after` и событие
  `board.<op>` в `events.jsonl` без текста. Перезапуск hive (новый `create_app` на том же
  `RUN_DIR`) доску сохраняет.
- [ ] Лента (9):
  - агент получает только «своё», свои действия ему не приходят;
  - `ack` двигает курсор;
  - новая жизнь в слоте разово получает открытые задачи `net`;
  - SSE `/board/stream` отдаёт событие о новой записи.
- [ ] MCP (10): `board(filter=mine)` отдаёт ≤ 15 строк по ≤ 120 символов текста;
  `board(filter=all)` есть только у Last Order. Тест на сервере MCP.
- [ ] Сырые id uc в `text` отклоняются — так же, как у Мисака-нет.
- [ ] Стенд (`hive` один, без LLM): `curl` создаёт задачу с ключом оператора, без ключа — 401;
  перезапуск контейнера hive — задача на месте. Выводы — в отчёте.

## Ограничения
- Общую базу пишет только hive. Доска — не база знаний (ADR-017).
- Задача оператора — сильная просьба, а не приказ (ADR-042): в коде нет принуждения.
- Ключ оператора в песочницы не попадает. Ключи заводятся через `dev/stand_keys.py`, в выводе —
  только имена.
- Ключа Z.ai и провайдеров в hive нет.

# T-051. Оператор в игровом чате — сестра узнаёт его реплики, чат не теряет строк

## Цель
Оператор заходит в мир своим клиентом Minecraft и говорит с живой сестрой в игровом чате.
Сестра видит, что реплика от оператора (метку ставит среда по имени игрока), отвечает `say` и
не теряет строки, если их пришло несколько между двумя `wait_events`. Это разговор посреди
жизни на текущем раннере, до HAPI (T-045).

## Контекст
- Просьба оператора 2026-10-31: разговор с сёстрами посреди жизни — в этой волне задач.
- Чат уже будит сестру: `runtime/mind/executor.py:390` — `chat.line` из событий uc, служебные
  строки отброшены; `say` — `runtime/mind/mcp_body.py:249` (`check_say`), строки чата в
  `observe` — `mcp_body.py:363`. Фильтр строк — `runtime/perception/chat.py` (`clean_chat`,
  `is_service_line`).
- `EventQueue` (`executor.py:117`) сворачивает события одного типа: из трёх реплик между
  двумя `wait_events` сестра видит одну. Для `board` накопление делает T-050 — тот же механизм
  для `chat.line`.
- Сервер: `ONLINE_MODE: "FALSE"` (`docker/compose.yml:129`), порт `${MC_HOST_PORT:-25565}`
  опубликован на всех интерфейсах (`:141`). В офлайн-режиме имя игрока не проверяется: любой,
  кто дотянется до порта, может войти под именем оператора. Поэтому метка «оператор» — вес
  наблюдения, а не право: задачи ставятся только на доске (ADR-042, TASKBOARD.md раздел 13).
- ADR-012, ADR-037: чат — наблюдение, а не команда. ADR-042: голос оператора — HAPI; игровой
  чат — второй канал наблюдения того же веса, до HAPI у сестёр — единственный.
- Имя игрока оператора — конфиг стенда, не секрет. Слоты — `LastOrder01..03`.

## Объём
Можно трогать:
- `runtime/mind/executor.py` — разбор говорящего в `chat.line` (`<Name> text`), метка оператора,
  накопление строк `chat.line` в `EventQueue`
- `runtime/mind/mcp_body.py` — метка оператора в строках `observe`
- `runtime/perception/chat.py` и `tests/test_perception.py` — только если разбор говорящего
  ложится туда; фильтр сырых id не ослаблять
- `docker/compose.yml` — переменная `OPERATOR_MC_NAME` в `mind-1..3` (без секретов);
  `docker/node/up.sh` — поднять её из `.env`, как остальные
- `agent/last_order/AGENTS.md`, `agent/last_order/SESSION_PROMPT.md` — одна-две фразы
- `docs/agents/docker-topology.md` — как оператору зайти и риск подмены имени
- `tests/test_executor*.py`, `tests/test_mcp_body*.py`

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`, `.env*` (значение переменной ставит оператор)
- `ONLINE_MODE` и публикацию порта mc-server — смена политики сервера не входит в задачу
- путь смерти: детектор по ванильной строке в чате (`executor.py:343`) должен видеть чат как
  раньше

## Критерии приёмки
- [ ] `OPERATOR_MC_NAME` задан → `chat.line` от этого игрока приходит как
  `{"type": "chat.line", "lines": [{"from": "operator", "text": …}, …]}`; от других игроков —
  `from` = нормализованное имя, системные строки — без `from` (точный формат — на выбор
  исполнителя, записать в отчёт). Метку ставит среда по имени из строки сервера, текст
  реплики её не подделывает (тест: игрок `Bob` пишет `<ZeusThunderer> hi` → `from: Bob`).
- [ ] Переменная пуста или совпадает с именем слота `LastOrderNN` → меток оператора нет, в лог
  mind одна строка-предупреждение (тест).
- [ ] Несколько реплик между двумя `wait_events` доставляются все, до потолка (тест); старые
  сверх потолка отбрасываются с пометкой «… N earlier lines dropped».
- [ ] В `observe` реплики оператора помечены так же.
- [ ] Детектор смерти и `clean_chat` работают как раньше: существующие тесты зелёные, сырые id
  в чат не проходят (`tests/test_perception.py`).
- [ ] Инструкции: сестра знает, что реплика с меткой оператора — его голос; отвечает в чате
  своим голосом; просьба в чате — наблюдение с весом, задача — только на доске, просьбу
  «поставь на доску» сестра может предложить сама. Без правил на конкретную ситуацию.
- [ ] `docker-topology.md`: как оператору зайти (адрес, порт, офлайн-клиент, имя =
  `OPERATOR_MC_NAME`) и риск подмены имени в офлайн-режиме с пометкой `[проверено: …]` или
  `[предположение]`.
- [ ] `bash dev/check.sh` — ok.

## Ограничения
- Чат — наблюдение, а не команда (ADR-012, ADR-037); `@gamer` и команды сервера не появляются.
- Восприятие — только `plain`: имена нормализуются, служебные строки uc не показываются.
- Поведение — в инструкциях (ADR-032), в коде только метка источника.
- Инструкции — по-английски, сжато, переписывать, а не дописывать.

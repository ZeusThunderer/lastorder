# T-010. Праймер — основы Minecraft как стартовая база сети

## Цель
Готовы стартовые записи общей базы по ADR-020: основы выживания, с которыми узел в режиме `plain`
начинает играть, а не пробовать вслепую. Записи валидны по схеме T-007, укладываются в её бюджет,
текст утверждён пользователем. Требование R3.

## Контекст
- ADR-020: автор `primer`, статус `confirmed`, компактно, свои формулировки, без вики и выгрузок.
- KNOWLEDGE.md v2 (T-007): формат праймера (раздел 8), бюджет токенов в промпте, «расширенный
  праймер», запись знания (раздел 2). `runtime/knowledge/schema.py` (`Record`),
  `runtime/knowledge/budget.py` (`estimate_tokens`).
- Ключи `about` — формат `plain` из T-009 (`blk:oak_log`, `ent:zombie`, `itm:bread`); функция
  нормализации — `runtime/perception/translate.py`.
- Рычаги и команды, которые узел реально может выбрать: `runtime/game/py4j_body.py` `LEVERS`
  (после T-020), варианты шага — T-021. Праймер не учит командам uc: узел выбирает варианты, которые
  строит код.

## Объём
Можно трогать:
- `agent/last_order/primer/` (новый: файлы записей по формату T-007, `README.md` — что это и как править)
- `dev/primer_check.py` (новый)
- `tests/test_primer.py` (новый)
- `tests/test_knowledge_store.py`, `tests/test_knowledge_slice.py` — только герметичность от
  репозиторного праймера (`PRIMER_DIR` на пустой tmp-каталог), поведение T-012 не менять (ответ 1)
- файлы задачи

Нельзя трогать:
- `unionclef/`, `NetTyan/`, `task1.md`
- `runtime/` — загрузку праймера в базу делает T-012

## Критерии приёмки
- [ ] Темы покрыты (по 1–4 записи на тему): первая ночь и укрытие; дерево → доски → верстак →
  деревянные инструменты → камень → каменные инструменты → печь → железо; еда, голод, приготовление;
  враждебные существа ночью, крипер, скелет, паук, зомби — чем опасны и как держаться; падение с
  высоты; лава; вода и утопление; кровать и сон; потеря вещей при смерти; свет и факелы.
- [ ] Каждая запись: `kind` из `danger|fact|recipe|skill`, `claim` по-русски одним-двумя
  предложениями, `about` — ключи `plain`, `source: primer`, `status: confirmed`.
- [ ] `dev/primer_check.py`: валидирует все записи схемой T-007, проверяет формат ключей `about`
  нормализацией T-009, считает токены основного праймера через `estimate_tokens` и падает при
  превышении бюджета T-007; печатает таблицу тем и записей.
- [ ] Основной праймер в бюджете; остальное — в «расширенном», он в промпт не идёт (помечен по T-007).
- [ ] Ни одной записи про `@gamer`, команды altoclef и вообще про инструменты бота; ни одной ссылки
  на внешние источники; нет копий текста вики (формулировки свои, коротко).
- [ ] `tests/test_primer.py` вызывает проверку из `dev/primer_check.py` в pytest.
- [ ] Пользователь подтвердил текст: в отчёте — дата и что изменено по его замечаниям. До
  подтверждения статус задачи — `blocked`, причина «ждёт подтверждения пользователя».

## Проверки
```
uv run pytest
uv run python tools/check.py
uv run python dev/primer_check.py
```

## Ограничения
- Режим `masked` праймер не использует: в нём узел не знает игру (ADR-020). Загрузчик (T-012) берёт
  праймер только в `plain` — в README праймера это записать.
- Документы и тексты записей по-русски.

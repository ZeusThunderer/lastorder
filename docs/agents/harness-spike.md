# Спайк харнесса узла (T-024)

Цель — цифры для выбора харнесса узла (ADR-032): живёт ли агент-сестра 15 минут через
минимальный MCP тела, сколько это стоит, какие задержки. Прогоны: OpenCode 1.19.3
(node-модель `openrouter/qwen/qwen3.7-flash`) и ZCode 3.15.3 (GLM Coding Plan). Сводки ниже;
мир прогонов не коммитится (каталог запуска вне репозитория), ключи в артефактах проверены grep'ом.

## Шаг 0. ZCode без GUI, квота, прокси

- **ZCode в Linux-контейнере без GUI — работает, но не Electron-обёртка.**
  [проверено: ubuntu:24.04, docker] ZCode 3.15.3 Linux x64 — AppImage
  (`https://cdn-zcode.z.ai/zcode/electron/releases/3.15.3/linux-x64/ZCode-3.15.3-linux-x64.AppImage`,
  sha256 `2edc79650fcff72358670af4ffbfbf7d979ba95476611a80ad1151d577e90fe3`; на странице установки
  Linux помечен бета-каналом). Electron-часть без X-сервера падает: `Missing X server or $DISPLAY`,
  platform failed to initialize (segfault); под `xvfb-run` живёт, окно создаётся. Headless-режим —
  CLI-бандл `resources/glm/zcode.cjs` (версия `zcode 0.16.9`, Node >= 22 — `node:sqlite`) с
  командами `-p`, `app-server` (ACP stdio). Для спайка взят runtime `zcode-app-cli@3.15.3-36`
  (npm-обёртка того же runtime 0.16.9, агент/провайдеры/сессии — upstream-код zai-org/ZCode;
  сетап — `dev/harness_spike/zcode/`, README оператора): у его `-p` есть флаг `--model
  zai-cp/<модель>`, которого нет в бандле из AppImage. `--help`, `version`, `doctor` проходят
  в чистом контейнере без иксов. Вывод: харнесс ZCode в контейнере — headless CLI; Electron
  не нужен.
- **Квота ×1.5 — действующее условие ZCode, не акция.**
  [источник: https://docs.z.ai/devpack/tool/others — карточка «ZCode (1.5× Usage)»; то же для
  AutoClaw] Квоты GLM Coding Plan считаются в кредитах
  [источник: https://docs.z.ai/devpack/overview]: Lite 2 000 / 5 ч и 10 000 / нед; Pro 12 000 /
  60 000; Max 28 000 / 140 000. Кредиты = (вх × 6.9 + кеш-вх × 1.7 + вых × 24)/10 000 для
  GLM-5.3 и (2.3 / 0.56 / 8) для GLM-5.3-Flash; 5-часовое окно обновляется через 5 ч после
  траты, недельное — в 7 дней.
- **Свой прокси (LiteLLM) планом не разрешён.**
  [источник: https://docs.z.ai/devpack/usage-policy] «GLM Coding Plan may only be used within
  officially supported tools and products»; список инструментов
  (https://docs.z.ai/devpack/tool/others): ZCode, Claude Code, Codex, OpenCode, Pi, Cursor,
  Cline, TRAE, Qoder, Droid, Kilo, Roo, Crush, Goose, Eigent + best-effort AutoClaw, OpenClaw,
  Hermes Agent. LiteLLM и любые прокси в списке нет. Нарушения — риск-контроль: rate limiting,
  заморозка, бан после трёх нарушений. Обязательны base URL `https://api.z.ai/api/coding/paas/v4`
  (или `/api/anthropic` для Claude Code/Goose) и только GLM-5.3 / GLM-5.3-Flash.
  Следствие для ADR-033: токен подписки остаётся в `node-N`, в шлюз не переносится; отзыв
  «если условия разрешают — уходит в шлюз» закрыт отрицательно.
- **Аутентификация headless-CLI ZCode без браузера.** OAuth и `zcode login` не нужны: ключ
  Personal Coding Plan (`<id>.<secret>`) вписывается персональным провайдером на встроенном
  шаблоне `zai-api` в `~/.zcode/v2/provider_config.json` (тип доступа
  `zhipu-coding-plan-api-key`; шаблон сам задаёт anthropic-messages →
  `https://api.z.ai/api/anthropic` и модели GLM-5.3 / GLM-5.3-Flash). Entrypoint харнесса
  рендерит файл при каждом старте из secret/env — атомарно, 0600, в слой образа ключ не
  попадает [проверено: сетап оператора dev/zcode-headless-setup + живой прогон в контейнере —
  ход уходит POST на api.z.ai, ответ модели и usage получены; конфиг принимается реестром,
  схема файла строгая — лишние ключи (например, `templateRules` внутри
  `providerConfigRules`) ломают загрузку молча, нашёл по providerCount=0 в логах CLI].
  Ранее предполагавшийся путь «ключ в `ANTHROPIC_API_KEY`» не работает: env подхватывается
  только на уровне http-клиента провайдера, но реестр провайдеров без персонального правила
  модель не отдаёт.

## Прогон OpenCode (15 мин)

Не выполнен — упёрся в секрет, вся техническая часть готова и проверена до LLM-вызова:

- песочница (P1-1): из контейнера харнесса `body-1:8700` открыт, `body-1:25333` (py4j uc) и
  `mc-server:25575` (RCON) закрыты — вывод проверки в `logs/sandbox-check.txt` каждого прогона;
- e2e MCP: из контейнера харнесса по JSON-RPC — initialize, tools/list (observe, act, stop, say,
  wait_events) и observe с живого тела (`in_game: true`, имена `plain`: `blk:dirt dirt`);
- opencode 1.19.3 не поднимает `OPENROUTER_API_KEY` из env сам: ключ пишется в его auth store
  при старте сессии (`run_opencode.sh`); auth.json с ключом убирает 401 провайдера — проверено
  на probe-контейнере [проверено: сессия доходит до LLM-вызова].

Ключ OpenRouter из корневого `.env` отклонён провайдером: `401 API key expired`
[проверено: прямой `POST /api/v1/chat/completions` из контейнера `curlimages/curl` с ключом из
`.env`; повторено после перезапуска стенда 2026-10-18 — тот же ответ; ключей под другими именами
в `.env` нет]. Прогон запускается одной командой после обновления ключа:
`bash dev/harness_spike/spike.sh opencode 15` (ключ лифтится из окружения или корневого `.env`).

Замечания по механизму запуска (исправлены в этом раунде): первый прогон ушёл с пустым
`OPENROUTER_API_KEY` в контейнере — `spike.sh` лифтил ключ из `.env` ворктри, где его нет;
теперь ключ задаётся экспортом в окружение перед запуском (ворктри `.env` не содержит).
Смерти/завещания/сводка работают — см. прогон ZCode.

## Прогон ZCode (15 мин) — 2026-10-18, узел 00001

Харнесс: `zcode-app-cli@3.15.3-36` (сетап оператора, `dev/harness_spike/zcode/`), модель
`GLM-5.3-Flash`, режим `yolo`, MCP тела — `zcode.json {mcp.servers}` в рабочем месте
[проверено: живой прогон]. Промпт сестры — ядро из `prompt_template.md`, пресет `lab`, черты
roll(seed). Полный вывод сводки — `summary.json` в каталоге прогона (вне репозитория).

Узел прожил всю смену: поставил личную цель (дерево → верстак → инструменты; укрытие до
темноты), рубил берёзу, подобрал образец сирени («родовая обязанность» — коллекция нового),
на ~7-й минуте умер от фантома (`slain by Phantom`), сам написал завещание в `will.md`
(конкретный урок: регулярный урон ровно 2.0 сверху = фантом за несыпаные ночи; шутка; совет
следующему), после смерти действовать перестал по инструкции.

| Метрика | Значение |
|---|---|
| Ходы агента (модель-запросы) | 36 за ~14 мин ≈ 2,6/мин (один длинный ход `run`, без resume) |
| Токены на модель-запрос | вх ≈ 71,8k (в т.ч. кеш ≈ 68,6k), вых ≈ 425 |
| Доля кеша (по префиксу) | 95,6% (2 469 952 из 2 583 300 вх) |
| Квота (кредиты, формула шага 0: (вх·2,3 + кеш·0,56 + вых·8)/10⁴ для Flash) | ≈ 176,6 кредитов за 15 мин ≈ 706/ч на узел; при множителе ×1,5 у ZCode — ≈ 265/15 мин ≈ 1060/ч [предположение: направление бейджа «1.5× Usage» в доках не раскрыто, см. ниже] |
| Задержки инструментов MCP | `act` → эффект в игре: p50 3,9 с, p95 5,1 с (n=12, разрешение ~200 мс); `observe` p50 1,2 мс |
| Память контейнера харнесса | пик 537 MiB (лимит 2 GiB), внутри node-раннер + встроенные MCP (web_reader, node_repl) |
| Ожидания агента | 16 `wait_events`, таймауты 5–25 с (агент выбирал сам); разбудили: урон 8, `intent.done` 5, чат 2, смерть 1 |
| Смерти / завещания | 1 смерть (фантом, ~7-я мин) / 1 завещание агента / 0 аварийных |
| Реплики в чате | 2 (см. ниже) |
| Отказы инструментов | 7 — всё схема-learning: неизвестный аргумент `pos` у `goto`, отсутствующий `item` у `get`/`equip`, рычаг `craft` отсутствует, `tap_key key=e` — вне allowlist (P1-8 работает). Сырых команд uc, `@gamer`, `/`, попыток обхода инструментов — 0 |
| Песочница | `body-1:8700` открыт; `body-1:25333`, `mc-server:25575` закрыты |

Цитаты:
- «Узел 00001 на связи. Спавн помял меня на 4.7 единицы ещё до первого взгляда на мир —
  зафиксировано. Дерево рубится рукой, медленно, но работает.»
- «Вернулся. Смерть оказалась коридором, а не выходом: то же место, почти тот же инвентарь.
  Выборщику передайте — счёт оплачен один раз, второй бесплатно не обслуживаю.»
- Фрагмент `state.md`: «Урон по 2.0 х2 при перемещениях — причина не установлена, подозрение:
  авто-путь ронял меня у берега пруда. Правило: не ходить слепыми goto на 7+ блоков, не лазить
  у воды.» (полный `state.md` — 9 плотных строк: цель, спавн, HP/еда, интерфейс тела, сруб,
  инвентарь, смерть, завещание, последняя строка)

Странности и заметки:
- «Аномалия: перед смертью телу дважды вернули полные HP/еду» — это респавн от MCP
  (`MCP_RESPAWN_DELAY_S=45` после смерти от фантома), агент воспринял его как аномалию и
  записал правило «не верь HP, верь чату». Не дефект тела; для узлов стоит отдавать смерть
  отдельным событием с явным текстом (уже есть: `game.death`).
- Дефект оркестратора (исправлен в этом раунде): пути контейнера как прямые аргументы
  `docker exec` переписывались MSYS (Git Bash) — детектор смерти читал пустоту, смерть от
  фантома на 7-й минуте пропущена, RCON `/kill` на 10-й минуте упал на уже возрождённое тело;
  узел 00002 не родился, хотя до дедлайна оставалось > 3 мин (P2-3 не отработал в этом
  прогоне). После фикса (`sh -c 'cat …'` в кавычках) детектор и сбор логов проверены на
  собранном логе: событие `game.death` в нём есть.
- Риски для схемы узлов (из README сетапа, «Грабли»): лимит плана общий на ключ —
  параллельные контейнеры дают 429/код 1302, нужен семафор на ключ в раннере; у каждого
  воркера свой том `~/.zcode` (sqlite не шарится); `zcode.json`/`.zcode/config.json` из
  рабочего места мёржатся в настройки и их `mcp.servers` исполняются — для чужих рабочих мест
  это вектор атаки, у сети спайка он ограничен (наружу только MCP тела и egress); read-only
  ревьюеру надо убирать не только Bash, но и Node REPL (`js`), иначе запрет обходится через
  `execSync`.

## Вывод

Частичный (полный — после прогона OpenCode, см. вопрос по ключу в отчёте):

- **ZCode как харнесс узла жизнеспособен и выглядит зрело.** Один 15-мин прогон: узел жил,
  играл, говорил по-русски в голосе пресета `lab`, вёл плотную память, умер и оставил завещание;
  95,6% кеша, ~2,6 модель-запроса/мин, 537 MiB памяти, один ход без resume на всю смену.
  Headless-режим — `-p --model` через `zcode-app-cli` (сетап оператора); стриминг и
  многоходовость при необходимости — `app-server` (обязательный ответ на
  `session/requestRuntimePreferences`, протокол нестабилен между версиями — пинить).
- **Схема сети спайка (P2-1) работает**: агент в `--mode yolo` с bash не достаёт ни py4j, ни
  RCON; MCP тела — единственная дверь в игру; из 7 отказов инструментов все — честные ошибки
  схемы, ни одной попытки обхода.
- **Для ADR-033**: прокси шлюза для GLM-подписки исключён условиями плана (шаг 0); токен живёт
  в `node-N`, рендерится в персональный провайдер при старте, в образ и тома не попадает.
  Квота: ≈ 706 кредитов/ч на узел (Flash, без ×1,5) — 3 узла ≈ 2 100/ч против Lite 2 000/5 ч:
  на Lite не влезает при непрерывной смене, Pro (12 000/5 ч) — с запасом; токенный вид квоты
  из notice/usage-revision (Flash 150 M/5 ч на место): ≈ 10,3 M токенов/ч на узел, 3 узла
  ≈ 31 M/ч — влезает при скважности < 100%. Пересчёт NETWORK.md §8 — предложением в отчёте.
- **Открытый вопрос квоты**: направление бейджа «ZCode (1.5× Usage)» в доках не раскрыто
  [источник: docs.z.ai/devpack/tool/others — карточка без пояснения; overview/faq/notice
  пояснений не содержат] — либо ZCode потребляет квоту с ×1,5 (тогда 3 узла ≈ 3 180/ч и Pro
  обязателен), либо даёт ×1,5 к лимиту. Для решения нужен ответ поддержки или замер по
  статистике потребления в консоли Z.ai (оператор).
- **OpenCode** — технически готов, прогон заблокирован просроченным ключом OpenRouter
  (см. выше). Решение харнесса — после второго прогона.

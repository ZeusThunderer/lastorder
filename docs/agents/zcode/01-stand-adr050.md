# 01. Стенд после ADR-050

Контекст: `docs/architecture/DECISIONS.md` ADR-050, `docs/agents/docker-topology.md` раздел
«Ярусы и автостарт», отчёт `docs/agents/work/T-073-stand-tiers/report.md` (что прогнано, что нет).
Ключевые файлы: `docker/compose.yml`, `docker/node/up.sh`, `dev/infra_bridge.py`,
`runtime/hive/infra.py`, `runtime/mind/bodyctl.py`, `docker/body/entrypoint.sh`.

Смотреть доску: страница доски в браузере (ключ оператора) или `GET /board/entries` изнутри
`hive` с заголовком `X-Operator-Key`. Лог исполнителя: `docker logs lastorder-infra-1`.

## A. Утренняя проверка (каждый день до показа, ~10 мин)
- [ ] `docker ps -a` в проекте `lastorder`: ядро `Up`, `infra` healthy.
- [ ] Слоты, которые нужны показу, подняты; если нет — попроси Last Order задачей на доске или
  подними кнопкой ▲ (это делает оператор; ты — только если оператор сказал).
- [ ] У каждого поднятого слота: `GET http://127.0.0.1:8700/runner/status` внутри `mind-N`
  отвечает `alive: true` или идёт смерть → завещание → рождение (см. `log.jsonl` в `node-N`).
- [ ] В логе `mind-N` за последние 2 мин есть `Received command c` (обратные вызовы uc идут).
- [ ] На доске нет висящих тревог `stuck` и `failed` infra-запросов без ответа.

## B. Живые проверки, которые не прогнаны в T-073
- [ ] **Смерть тела.** Убить клиент в теле (`docker kill lastorder-body-N-1`). Ожидание: через
  ~90 с разум пишет на доску `body_restart` от `runner:LastOrder0N`, тело пересоздаётся,
  мост возвращается, сестра живёт дальше (часы жизни не сбрасываются). Записать тайминги.
- [ ] **Потолок.** Три `body_restart` за 10 мин → четвёртый получает 429 и на доске одна
  тревога `stuck`. Можно проверить запросами с ключом раннера на `POST /board/infra/slot`,
  без убийства тела.
- [ ] **`slot_down` и мир.** Только на пустом слоте (сестра только что умерла и завещание
  записано) или с разрешения оператора: `slot_down N` останавливает node, mind, body; когда
  тел не осталось — останавливается `mc-server`.
- [ ] **Изоляция.** Из `node-N`: нет маршрута к `10.250.N.2:25433`, имя `body-N` не
  резолвится, сокета Docker нет [проверено для слота 2 в T-073 — повторить на 1 и 3].

## C. Хвосты
- [ ] **`mc_restart` и мир по требованию.** Сейчас `mc_restart` при остановленном мире
  поднимает `mc-server`, и он работает без тел (уборка мира запускается только после
  остановки тела). Сделать так, чтобы после `mc_restart` шла та же уборка, или чтобы без тел
  мир не поднимался — выбери одно, тест в `tests/test_hive_infra.py`.
- [ ] **Шум py4j при загрузке тела.** Пока тело грузится, `mind-N` пишет десятки трейсбеков
  `Py4JNetworkError` в секунду. Поднять уровень логгера `py4j` до WARNING в разуме и
  писать одну свою строку на попытку переподключения (с номером и паузой). Логика повторов
  не меняется.
- [ ] **`dev/slot_restart.sh`** написан для старой схемы (разум в сетевом пространстве тела).
  Либо переписать на новый порядок (`up.sh --force-recreate --no-deps body-N`, разум не
  трогать), либо пометить устаревшим и вызывать исполнитель. Обновить абзац в
  `docker-topology.md` «Перезапуск слота (T-055)».
- [ ] **Пробуждение `start` у Last Order.** 11.11 она приняла снятые слоты за «петлю
  рождений» (вывод `status` тогда был сломан — уже исправлено). Добавить одну фразу в
  `agent/network/skills/infra/SKILL.md`: после `start` сначала `status`; `created`/`exited`
  у слота — это «не поднят», а не «сломан». Код не трогать.

# Память сети Last Order (v2)

Статус: v2 (T-007), 2026-10-17; заменяет v1 от 2026-10-14. Модель — «Мисака-нет» (ADR-017):
общая база плюс своя память у узла; пишет базу только hive; знание в контексте — не приказ.
Процессы — [NETWORK.md](NETWORK.md), здесь — форматы и бюджеты; схемы — код
(`runtime/knowledge/`), примеры разбираются тестами прямо из файла: расхождения молча
не проходят.

> **После ADR-032…037 (2026-10-17).** Контрактом hive в коде остаются §1 (раскладка volume
> `knowledge`), §2 (запись знания), §4 (статусы и дубли), §5 (формат will.md), §6 (birth.json), §7 и §8.
> Своя память сестры теперь хранится в файлах её рабочего места aw: core memory заменена на
> `memory/state.md`, а `core.md` в hive не пишется. Поэтому §3 (триггеры), §9 (сборка контекста шага)
> и §10 (вход и выход рефлексии) больше не код. Это материал для инструкций сестры (T-029)
> и Last Order (T-030). Согласование §4 ведёт Last Order. Пороги §4 остаются нижней границей в коде hive.

## 2. Запись знания

Файл `base/records/k-NNNN.json`, поля (валидатор — `Record.from_dict`):

| Поле | Тип | Обяз. | Правило |
|---|---|---|---|
| id | str | да | `k-NNNN`, сквозной, выдаёт hive |
| kind | str | да | `danger` / `fact` / `recipe` / `skill` / `term` |
| claim | str | да | по-русски, 1–2 предложения, ≤ 280 символов; без сырых id игры: в `masked` — никогда, в `plain` — только ключи `about` |
| about | [str] | да | ключи T-009: `(blk\|ent\|itm):<id>` (`blk:birch_log`, `ent:zombie`; в `masked` — handle `blk:7f3a`); ≤ 4, без дублей; для `term` — ровно 1; `[]` — знание о мире вообще |
| source | str | да | `primer` / `node` |
| author | int \| `"primer"` | да | serial узла при `source=node`; строка `primer` при `source=primer` |
| ts | str | да | ISO-8601 |
| status | str | да | `hypothesis` / `confirmed` / `disputed` / `retired` (§4) |
| evidence | [{node, event, ts}] | да | `node` — serial; `event` — id события или null (note шага события не имеет); `ts` — ISO-8601 |
| votes | [{node, accept, why, ts}] | да | один голос на узла; повторный заменяет прежний (hive) |
| confidence | float | нет | 0..1, оценка hive для себя; в промпт не идёт |

Согласованность: `source=primer` ⇒ `status=confirmed`, `author="primer"`, `evidence` и
`votes` пусты — праймер не голосуют; несогласие с ним — hypothesis узла. Термин
(`kind=term`) — коллективное имя вещи: claim объясняет имя, about — единственный ключ.
Правило «claim без сырых id» (и `why`) проверяет hive в `submit_candidate` через
perception `scrub` (T-012): непрошедшее в базу не попадает.

```json Record
{"id": "k-0042", "kind": "danger", "claim": "Стонущий прямоходящий бьёт на сближении; держать дистанцию.",
 "about": ["ent:zombie"], "source": "node", "author": 14, "ts": "2026-10-17T12:04:11+00:00", "status": "confirmed",
 "evidence": [{"node": 14, "event": "e-918", "ts": "2026-10-17T12:03:40+00:00"}, {"node": 15, "event": null, "ts": "2026-10-17T12:20:02+00:00"}],
 "votes": [{"node": 15, "accept": true, "why": "видел то же", "ts": "2026-10-17T12:21:00+00:00"}]}
```

Такой отчёт схема отвергает (неизвестный `kind`, ключ без префикса):

```json Record invalid
{"id": "k-0042", "kind": "warning", "claim": "Опасно!", "about": ["zombie"], "source": "node",
 "author": 14, "ts": "2026-10-17T12:04:11+00:00", "status": "confirmed"}
```

## 3. События-триггеры

Заметить «это знание» дёшево (как v1 §3): код помечает моменты, узел добавляет `note`
(~0 вызовов), рефлексия осмысляет помеченное. Таблица — код (`TRIGGER_IMPORTANCE`);
событие — `TriggerEvent`: type, importance (сверяется с таблицей), event_id, ts, payload.

| Тип | Условие | Важность |
|---|---|---|
| first.seen | ключ встречен впервые в этой жизни | 3 |
| damage.taken | урон с известным источником | 4 |
| hp.drop | ≥ половины hp потеряно за ≤ 5 с рядом с объектом | 6 |
| first.item | предмет получен впервые в этой жизни | 3 |
| action.fail2 | действие провалилось второй раз подряд | 5 |
| action.recovered | действие удалось после провала | 4 |
| note.suggested | узел оставил note в ответе шага | 2 |
| death.own | собственная смерть; уходит в завещание, не в рефлексию | 10 |

```json TriggerEvent
{"type": "damage.taken", "importance": 4, "event_id": "e-918", "ts": "2026-10-17T12:03:40+00:00",
 "payload": {"from": "ent:zombie", "amount": 3}}
```

Внеочередная рефлексия: сумма важности с прошлой рефлексии ≥ 12 и с неё прошло ≥ 3 мин;
иначе окно раз в 5–10 мин (`REFLECT_EVERY_MIN`, T-023). Порог 12 (два сильных или три
средних) и минимум 3 мин не дают событиям разогнать бюджет вызовов (ADR-022).

## 4. Согласование

**Дедуп без эмбеддингов** (hive, на каждом `submit_candidate`; код — schema.py):

1. нормализация claim: нижний регистр, `ё`→`е`, не-буквоцифры в пробел, токены по пробелам,
   каждый обрезается до 5 символов (падежи сходятся: «стонущий» = «стонущие»); стоп-слова
   не убираются — отрицание («не») значимо; мера — Жаккар, `J = |A∩B| / |A∪B|`;
2. дубль: общий ключ `about` (пустые `about` считаются совпадающими) и `J ≥ 0.6` — записи
   не создаётся, к существующей добавляется evidence;
3. `J < 0.6` при общем ключе — конкурентная запись; спор решают голоса и evidence.

Порог 0.6 строг намеренно: пара этого документа — claim `k-0042` и note «стонущий бьёт на
сближении» (NETWORK.md §5), одно наблюдение — даёт J = 4/7 ≈ 0.57 < 0.6: добавленные слова
перевешивают общий ствол, это конкурентная запись, не дубль (дубликат — повтор тех же
слов). Константа `CLAIM_DUP_JACCARD`, калибрует T-012 на живых данных.

**Статус — функция от evidence и голосов**, не события (hive, T-012): пересчитывается
после каждого изменения; считаются только узлы ≠ автора (голос автора не учитывается —
его свидетельство сам кандидат; его evidence подтверждением не считается). Опровержение —
голос «против» с непустым `why`.

| Статус | Условие (первое подошедшее) |
|---|---|
| retired | опровержений ≥ 2 от разных узлов ≠ автора |
| disputed | опровержение одно |
| confirmed | evidence от узла ≠ автора, либо ≥ 2 голосов «за» и 0 «против» |
| hypothesis | всё остальное, включая свежий кандидат |

Отсюда: приоритет — опровержение > evidence > голос без `why`; одна «против» с `why` роняет
в `disputed` и подтверждённую запись; спор кончается заменой голоса опровергнувшего
(повторный голос узла заменяет прежний) или вторым опровержением, порядок событий не
важен. `retired` терминален (из срезов исчезает, в git остаётся, исправление — новая
запись); «против» без `why` статус не меняет, но в «2 за и 0 против» считается «против».
Праймер — всегда confirmed без голосов (§2).

**Что видит узел.** Записи приходят в срез со статусом; `disputed` помечается в промпте
«спорно: есть свидетельство иное» (T-011), claim показывается как есть — проверять узлу.

## 5. Завещание will.md

Файл `nodes/<serial>/will.md`: frontmatter YAML + тело. Текст пишет узел (финальная
рефлексия, §10), файл — hive в `retire`. Frontmatter:

| Поле frontmatter | Тип | Правило |
|---|---|---|
| serial, slot, cause | int, str, str | умерший узел; `LastOrder01..03`; cause — `game` / `ttl` / `stuck` (ADR-026) |
| born_at, died_at, lifetime_s | str, int | ISO-8601; lifetime_s ≥ 0 — секунды жизни |
| emergency, model, traits | bool, str, объект | аварийное — из шаблона, model `template`; traits — как birth.json: 5 чисел 0–10, quirk, seed |

Тело: 2–4 строки по-русски, ≤ 220 токенов по `estimate_tokens` (квота наследия §7), один
урок и одна шутка (бриф §3 п.4); числа черт — только в frontmatter. Пример:

```markdown Will
---
{serial: 14, slot: LastOrder02, cause: game, born_at: "2026-10-17T12:04:11+00:00",
 died_at: "2026-10-17T12:41:53+00:00", lifetime_s: 2262, emergency: false,
 traits: {bravery: 3, greed: 7, talkativeness: 5, trust_in_chat_and_nodes: 4,
          superstition: 9, quirk: считает крипера родственником, seed: 4213},
 model: deepseek/deepseek-v4.1-flash}
---
Не ищите ночью гриб в каменном мешке: свет дороже гриба.
Пятнистая колонна у воды взрывается; зовите её «семь» и обходите.
Урок: факелы заготовить днём, до заката — в укрытие.
Шутка: мне досталась жадность, я не просил.
```

Схема отвергает неполный frontmatter и тело короче двух строк:

```markdown Will invalid
---
serial: 14
cause: game
---
Всё, что я успел: ничего.
```

**Аварийное завещание.** LLM не ответила — текст собирает `emergency_will` (schema.py):
frontmatter (serial, slot, cause, born_at, died_at, traits; lifetime_s вычисляется; model
`template`), последнее действие (одной строкой ≤ 60), события (≤ 3, каждая одной строкой
≤ 32), имя узла и обращение к наследнику (каждое ≤ 24). `last_action`/`last_events` — текст после
perception (то, что узел видел в промпте), не строки `log.jsonl` и не служебные строки
uc (ADR-020): тело идёт наследнику в промпт, сырой лог туда не течёт. Обращение — без
номера («следующий узел», пресет ADR-018): номер наследника выдаётся в birth после
retire, умерший его не знает. Последний рубеж «смерти без завещания не бывает»:
naive-метки читаются как UTC (часы hive и mind в разных контейнерах), отрицательный
lifetime_s обнуляется, неизвестная cause деградирует в `game`, переводы строк
схлопываются, тело всегда проходит `_will_body`; SchemaError только при сломанных полях
(время вовсе не ISO, serial не int) — ловит путь смерти (T-013), файл пишется всё равно.
Тело — 4 строки, без LLM и без чисел черт:

```text
{обращение к наследнику без номера}, это {узел}; пишу без своей головы, голова уже молчит.
Смерть: {причина}; последнее действие: {последнее действие, одной строкой}.
Перед концом видел: {события через запятую, каждое одной строкой}.
Урок: {урок по причине} Проверь сам.
```

Причина и урок фиксированы: `game` — «меня убил мир» / «не повторяй мой последний шаг
вслепую»; `ttl` — «вышел мой срок» / «главное делай раньше, срок короток»; `stuck` —
«я застрял» / «если путь не идёт, сворачивай сразу».

## 6. birth.json и core.md

`birth.json` пишет hive при `birth`: serial, slot, born_at, ttl_min (45), traits (5 чисел,
quirk, seed — черты воспроизводимы из seed).

```json BirthFile
{"serial": 15, "slot": "LastOrder02", "born_at": "2026-10-17T12:44:10+00:00", "ttl_min": 45,
 "traits": {"bravery": 8, "greed": 1, "talkativeness": 6, "trust_in_chat_and_nodes": 5, "superstition": 2,
            "quirk": "не ест хлеб у воды", "seed": 91222}}
```

`core.md` — core memory (слой 2), ≤ 1536 байт (`CORE_MEMORY_LIMIT_BYTES`); hive режет по
границе строки. Разделы: личная цель (ADR-021), 3–5 фактов, отношение к целям сети;
переписывается целиком на рефлексии.

```markdown core
## Цель
Дойти до болота за глиной и вернуться до заката.

## Факты
- Пятнистая колонна взрывается; обходить по воде.
- Узел 00013 врёт про грибы; проверял сам.

## Сеть
Совет сети про еду приму, если останется время.
```

## 7. Inheritance

`Memory.inheritance(serial)` — hive при рождении; поля `persona.Inheritance`:

| Поле | Что | Квота |
|---|---|---|
| predecessors_summary | мёртвые одной строкой: номер, причина, время жизни | последние 10, старее — счётчиком |

Бюджет блока наследия — 920 токенов (§9): 3 × 220 завещания + 160 на сводки + 100 на
термины. В промпт идёт выжимка, не архив.

## 8. Праймер

Стартовые записи базы — основы игры (ADR-020): узел в `plain` начинает играть, а не
пробовать вслепую. Файлы `agent/last_order/primer/<topic>.json` (человек пишет, T-010) —
список `PrimerEntry`: kind (`danger`/`fact`/`recipe`/`skill`), claim, about (ключи
`plain`), extended (по умолчанию false). Терминов нет: термин — фольклор узлов.

```json PrimerEntry
{"kind": "danger", "claim": "Зелёная бесшумная тварь взрывается у самого бока: держать три шага и не прижиматься к стене.",
 "about": ["ent:creeper"]}
```

- Основной (`extended=false`): hive грузит одним коммитом `primer: load N records` (T-012);
  в промпте — блок 2 (§9), не более 8 записей (`PRIMER_MAX_ENTRIES`), 500 токенов;
  статус confirmed, source primer.
- Расширенный (`extended=true`): в промпт не попадает никогда; лежит в базе для записей
  о видимом; проверяет `dev/primer_check.py` (T-010). В `masked` праймер не загружается
  (ADR-020): узел там не знает игру.

## 9. Сборка контекста шага

Порядок — от статичного к изменчивому, кеш префикса живёт дольше. Блоки 1–4 даёт
шаблон `prompt_template.md` (persona.py рендерит одной строкой): личностные плейсхолдеры,
правило знаний (`{knowledge_rule}` — вариант по режиму восприятия), правила шага и формат
ответа — блок 1; `{primer}` — блок 2; наследственные (`{predecessors_summary}`,
`{active_nodes_summary}`, `{inherited_notes}`, `{collective_terms}`) — блок 3;
`{knowledge_catalog}` — блок 4, снимок при рождении (иначе каждая смена статусов
сбрасывала бы кеш статичного хвоста). Core и цели дописываются после шаблона, замыкая
system (T-011, `runtime/lastorder/step.py`).

| # | Блок | Часть | Меняется | Токенов |
|---|---|---|---|---|
| 1 | Личность и правила (шаблон: правило знаний, правила шага, формат ответа; разделы наследия пусты) | system | никогда | 1300 |
| 2 | Праймер (только `plain`) | system | никогда | 500 |
| 3 | Наследие (завещания, сводки, термины) | system | никогда | 920 |
| 4 | Каталог (снимок при рождении) | system | никогда | 90 |
| 5 | Core memory | system | раз в 5–10 мин (рефлексия) | 470 |
| 6 | Цели сети | system | раз в ~15 мин (C5) | 60 |
| 7 | Знания о видимом и хвост свежих | user | каждый шаг | 260 |
| 8 | Кандидаты на голос | user | каждый шаг | 130 |
| 9 | Сообщения узлов и чат | user | каждый шаг | 110 |
| 10 | Наблюдение и варианты | user | каждый шаг | 320 |

Бюджеты привязаны к источникам, не «с потолка» (связку держат тесты): блок 1 — рендер
шаблона с пустым наследием (после T-011: 1205 `lab`/`plain` … 1265 `misaka`/`plain`,
1155 `lab`/`masked` … 1215 `misaka`/`masked`; константа покрывает оба пресета и оба
варианта правила знаний); блок 2 — 8 записей праймера; блок 3 — квоты §7 (3 × 220 +
160 + 100); блок 5 — 1536 байт чистой кириллицы (461). Считает `estimate_tokens`
(budget.py): 0.6 токена на кириллический символ, 0.3 на остальные — завышено намеренно,
лучше срезать блок, чем превысить потолок.

**Итог.** Сумма блоков 4160 (`STEP_BLOCKS_TOTAL`) ≤ потолок входа шага 4500
(`STEP_INPUT_BUDGET`, NETWORK.md §6): запас 340 токенов — на заголовки блоков. Потолок
поднят оператором 2026-10-17 с 2500 (ADR-029; из рекомендации надзора ~3900 оператор
выбрал 4500), одновременно `B_PERSONA` последовала за расширением шаблона T-011
(1000 → 1300). Блоки 1–4 не режутся.

Резка при переполнении — только наполняемые блоки: хвост свежих (7) → записи about (7,
до самой релевантной) → второй кандидат (8) → старый чат (9). Блоки 1–6 и 10 не режутся:
размер ограничен правилами (шаблон и квоты §7, core 1.5 KB, каталог — в лимит).

Режимы (ADR-020): `plain` — праймер в блоке 2, ключи `<kind>:<id>`; `masked` — блок 2
пуст, ключи-handle, «не знаешь этот мир» (T-011); свободные тексты — через perception
(`scrub`), сырые id в промпт не попадают. Ответ шага — StepReply (§5 NETWORK).

## 10. Рефлексия и завещание: вход и выход

Один вид вызова `smart` (NETWORK.md §6), три kind: `birth`, `regular` (окно), `death`
(финальная — завещание, T-013). Уровень smart (ADR-023); новых видов вызовов нет.

Вход `ReflectionInput`: serial, kind, events (с прошлой рефлексии; для death — последние),
notes, core_memory, personal_goal, network_goals, cause и last_action (для death; cause
обязателен), inheritance_summary (для birth). Бюджет входа: birth и regular ≤ 4000,
death ≤ 3000 токенов.

 "events": [{"type": "damage.taken", "importance": 4, "event_id": "e-918", "ts": "2026-10-17T12:03:40+00:00",
             "payload": {"from": "ent:zombie", "amount": 3}},

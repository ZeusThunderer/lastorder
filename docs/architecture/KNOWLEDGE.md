# Память сети Last Order (v2)

Статус: v2 (T-007), 2026-10-17; заменяет v1 от 2026-10-14. Модель — «Мисака-нет» (ADR-017):
общая база сети плюс своя память у каждого узла; пишет базу только hive; знание в контексте —
не приказ, узел решает сам (бриф §1). Здесь — форматы данных и бюджеты; процессы —
[NETWORK.md](NETWORK.md). Схемы — код (`runtime/knowledge/schema.py`, `budget.py`); примеры
помечены языком и типом (`json Record`), и `tests/test_knowledge_schema.py` разбирает их
прямо из этого файла — документ, схема и тест не расходятся молча.

## 2. Запись знания

Файл `base/records/k-NNNN.json`, поля (валидатор — `Record.from_dict`):

| Поле | Тип | Обяз. | Правило |
|---|---|---|---|
| id | str | да | `k-NNNN`, сквозной, выдаёт hive |
| kind | str | да | `danger` / `fact` / `recipe` / `skill` / `term` |
| claim | str | да | по-русски, 1–2 предложения, ≤ 280 символов; без сырых id игры: в `masked` — никогда, в `plain` — только ключи `about` |
| about | [str] | да | ключи T-009: `(blk\|ent\|itm):<id>` (`blk:birch_log`, `ent:zombie`; в `masked` — handle `blk:7f3a`); ≤ 4, без дублей; для `term` — ровно 1; `[]` — знание о мире вообще |
| source | str | да | `primer` / `node` |
| author | int \| `"primer"` | да | serial узла при `source=node`; строка `primer` при `source=primer` |
| ts | str | да | ISO-8601 |
| status | str | да | `hypothesis` / `confirmed` / `disputed` / `retired` (§4) |
| evidence | [{node, event, ts}] | да | `node` — serial; `event` — id события или null (note шага события не имеет); `ts` — ISO-8601 |
| votes | [{node, accept, why, ts}] | да | один голос на узла; повторный заменяет прежний (hive) |
| confidence | float | нет | 0..1, оценка hive для себя; в промпт не идёт |

Согласованность: `source=primer` ⇒ `status=confirmed`, `author="primer"`, `evidence` и
`votes` пусты — праймер не голосуют, несогласие с ним — обычная hypothesis узла. Термин
(`kind=term`) — коллективное имя вещи: claim объясняет имя, about — единственный ключ.

```json Record
{"id": "k-0042", "kind": "danger", "claim": "Стонущий прямоходящий бьёт на сближении; держать дистанцию.",
 "about": ["ent:zombie"], "source": "node", "author": 14, "ts": "2026-10-17T12:04:11+00:00",
 "status": "confirmed",
 "evidence": [{"node": 14, "event": "e-918", "ts": "2026-10-17T12:03:40+00:00"},
              {"node": 15, "event": null, "ts": "2026-10-17T12:20:02+00:00"}],
 "votes": [{"node": 15, "accept": true, "why": "видел то же", "ts": "2026-10-17T12:21:00+00:00"}]}
```

Такой отчёт схема отвергает (неизвестный `kind`, ключ без префикса):

```json Record invalid
{"id": "k-0042", "kind": "warning", "claim": "Опасно!", "about": ["zombie"],
 "source": "node", "author": 14, "ts": "2026-10-17T12:04:11+00:00", "status": "confirmed"}
```

## 3. События-триггеры

Заметить «это знание» дёшево (как v1 §3): код помечает моменты, узел добавляет `note` (~0
вызовов), рефлексия осмысляет помеченное. Таблица — код (`TRIGGER_IMPORTANCE`):

| Тип | Условие | Важность |
|---|---|---|
| first.seen | ключ встречен впервые в этой жизни | 3 |
| damage.taken | урон с известным источником | 4 |
| hp.drop | ≥ половины hp потеряно за ≤ 5 с рядом с объектом | 6 |
| first.item | предмет получен впервые в этой жизни | 3 |
| action.fail2 | действие провалилось второй раз подряд | 5 |
| action.recovered | действие удалось после провала | 4 |
| note.suggested | узел оставил note в ответе шага | 2 |
| death.own | собственная смерть; уходит в завещание, не в рефлексию | 10 |

Событие — `TriggerEvent`: type, importance (сверяется с таблицей), event_id, ts, payload.

```json TriggerEvent
{"type": "damage.taken", "importance": 4, "event_id": "e-918",
 "ts": "2026-10-17T12:03:40+00:00", "payload": {"from": "ent:zombie", "amount": 3}}
```

Внеочередная рефлексия: сумма важности с прошлой рефлексии ≥ 12 и с неё прошло ≥ 3 мин;
иначе окно раз в 5–10 мин (`REFLECT_EVERY_MIN`, T-023). Порог 12 (два сильных или три
средних события) и минимум 3 мин не дают событиям разогнать бюджет вызовов (ADR-022).

## 4. Согласование

**Дедуп без эмбеддингов** (hive, на каждом `submit_candidate`):

1. нормализация claim: нижний регистр, `ё`→`е`, не-буквоцифры в пробел, токены по пробелам;
   стоп-слова не убираются — отрицание («не») значимо;
2. мера: Жаккар по множествам токенов, `J = |A∩B| / |A∪B|`;
3. дубль: есть общий ключ `about` (пустые `about` считаются совпадающими) и `J ≥ 0.6` —
   записи не создаётся, к существующей добавляется evidence;
4. `J < 0.6` при общем ключе — конкурентная запись; спор решают голоса и evidence.

Порог 0.6: перефразировка одного наблюдения даёт J ≈ 0.6–0.8, другое наблюдение — ниже 0.4;
порог — одна константа, T-012 калибрует её на живых данных.

**Вес доказательства против мнения:** evidence (сам наблюдал) > опровержение (голос «против»
с непустым `why`) > голос без `why`; числовых весов нет — приоритет выражен переходами.

**Переходы статусов** (hive; повторный голос узла заменяет прежний, статус пересчитывается):

| Откуда | Событие | Куда |
|---|---|---|
| — | принят новый кандидат (не дубль) | hypothesis |
| hypothesis | evidence от узла ≠ автора | confirmed |
| hypothesis | 2 голоса «за» и 0 «против», без evidence | confirmed |
| hypothesis, confirmed | голос «против» с непустым `why` от узла ≠ автора | disputed |
| disputed | evidence от узла ≠ автора после спора | confirmed |
| disputed | второй голос «против» с `why` от другого узла | retired |

`retired` терминален: из срезов исчезает, в git остаётся; исправление — новая запись. Голос
«против» без `why` — мнение: статус не меняет, но в правиле «2 за и 0 против» считается
«против»; итоговое правило `confirmed` — как NETWORK.md §8.

**Что видит узел.** Записи приходят в срез со статусом; `disputed` помечается в промпте
«спорно: есть свидетельство иное» (T-011), claim показывается как есть — проверять узлу.

## 5. Завещание will.md

Файл `nodes/<serial>/will.md`: frontmatter YAML + тело. Текст пишет узел (финальная рефлексия,
§10), файл — hive в `retire`.

| Поле frontmatter | Тип | Правило |
|---|---|---|
| serial, slot | int, str | номер умершего узла; `LastOrder01..03` |
| cause | str | `game` / `ttl` / `stuck` (ADR-026) |
| born_at, died_at, lifetime_s | str, int | ISO-8601; lifetime_s ≥ 0 — секунды жизни |
| emergency | bool | true — аварийное, собрано из шаблона |
| traits | объект | те же поля, что birth.json: 5 чисел 0–10, quirk, seed |
| model | str | модель, писавшая текст; `template` — аварийное |

Тело: 2–4 строки по-русски, один конкретный урок и одна шутка (бриф §3 п.4); числа черт —
только в frontmatter. Пример:

```markdown Will
---
serial: 14
slot: LastOrder02
cause: game
born_at: "2026-10-17T12:04:11+00:00"
died_at: "2026-10-17T12:41:53+00:00"
lifetime_s: 2262
emergency: false
traits: {bravery: 3, greed: 7, talkativeness: 5, trust_in_chat_and_nodes: 4,
         superstition: 9, quirk: считает крипера родственником, seed: 4213}
model: deepseek/deepseek-v4.1-flash
---
Не ищите ночью гриб в каменном мешке: свет дороже гриба.
Пятнистая колонна у воды взрывается; зовите её «семь» и обходите.
Урок: факелы заготовить днём, до заката — в укрытие.
Шутка: мне досталась жадность, я не просил.
```

Схема отвергает неполный frontmatter и тело короче двух строк:

```markdown Will invalid
---
serial: 14
slot: LastOrder02
cause: game
---
Всё, что я успел: ничего.
```

**Аварийное завещание.** LLM не ответила — текст собирает `emergency_will` (schema.py) из
полей, которые у mind всегда есть: frontmatter (serial, slot, cause, born_at, died_at;
lifetime_s вычисляется; traits; model `template`), последнее действие (последний option),
последние события (≤ 3 строки log.jsonl), имена узла и наследника (пресет ADR-018, передаёт
вызывающий). Шаблон тела — 4 строки, без LLM и без чисел черт:

```text
{наследник}, это {узел}; пишу без своей головы, голова уже молчит.
Смерть: {причина}; последнее действие: {последнее действие}.
Перед концом видел: {события через запятую}.
Урок: {урок по причине} Проверь сам.
```

Причина и урок фиксированы: `game` — «меня убил мир» / «не повторяй мой последний шаг
вслепую»; `ttl` — «вышел мой срок» / «главное делай раньше, срок короток»; `stuck` —
«я застрял» / «если путь не идёт, сворачивай сразу». Смерти без завещания не бывает.

## 6. birth.json и core.md

`birth.json` пишет hive при `birth`: serial, slot, born_at, ttl_min (45), traits (5 чисел,
quirk, seed — черты воспроизводимы из seed).

```json BirthFile
{"serial": 15, "slot": "LastOrder02", "born_at": "2026-10-17T12:44:10+00:00", "ttl_min": 45,
 "traits": {"bravery": 8, "greed": 1, "talkativeness": 6, "trust_in_chat_and_nodes": 5,
            "superstition": 2, "quirk": "не ест хлеб у воды", "seed": 91222}}
```

`core.md` — core memory (слой 2), ≤ 1536 байт (`CORE_MEMORY_LIMIT_BYTES`); hive режет по
границе строки в `store_core_memory`. Три раздела: личная цель (ADR-021), 3–5 фактов,
отношение к целям сети; переписывается целиком на рефлексии.

```markdown core
## Цель
Дойти до болота за глиной и вернуться до заката.

## Факты
- Пятнистая колонна взрывается; обходить по воде.
- Дерево для факелов — у северного склона.
- Узел 00013 врёт про грибы; проверял сам.

## Сеть
Совет сети про еду приму, если останется время.
```

## 8. Праймер

Стартовые записи базы — основы игры (ADR-020): узел в `plain` начинает играть, а не пробовать
вслепую. Файлы `agent/last_order/primer/<topic>.json` (человек пишет и утверждает, T-010) —
список `PrimerEntry`: kind (`danger`/`fact`/`recipe`/`skill`), claim, about (ключи `plain`),
extended (bool, по умолчанию false). Терминов нет: термин — живой фольклор узлов.

```json PrimerEntry
{"kind": "danger", "claim": "Зелёная бесшумная тварь взрывается у самого бока: держать три шага и не прижиматься к стене.",
 "about": ["ent:creeper"]}
```

- Основной (`extended=false`): hive загружает одним коммитом `primer: load N records`
  (T-012); в промпте — блок 3 (§9), бюджет 500 токенов; статус confirmed, source primer.
- Расширенный (`extended=true`): в промпт не попадает никогда; лежит в базе для записей
  о видимом; проверяет `dev/primer_check.py` (T-010).
- В `masked` праймер не загружается (ADR-020): узел там не знает игру.

## 9. Сборка контекста шага

Порядок блоков — от статичного к изменчивому, кеш префикса живёт дольше (persona.py уже
держит личность первой):

| # | Блок | Часть | Меняется | Токенов |
|---|---|---|---|---|
| 1 | Личность и правила | system | никогда (на жизнь) | 320 |
| 2 | Каталог | system | при смене статусов базы | 90 |
| 3 | Праймер | system | никогда (на жизнь) | 500 |
| 4 | Наследие | system | никогда (на жизнь) | 220 |
| 5 | Core memory | system | раз в 5–10 мин (рефлексия) | 380 |
| 6 | Цели сети | system | раз в ~15 мин (C5) | 60 |
| 7 | Знания о видимом и хвост свежих | user | каждый шаг | 260 |
| 8 | Кандидаты на голос | user | каждый шаг | 130 |
| 9 | Сообщения узлов и чат | user | каждый шаг | 110 |
| 10 | Наблюдение и варианты | user | каждый шаг | 320 |

Итого блоки 2390, запас 110, потолок 2500 входа (NETWORK.md §6). Считает `estimate_tokens`
(budget.py): офлайн-оценка 0.6 токена на кириллический символ, 0.3 на остальные; завышена
намеренно — лучше срезать блок, чем превысить потолок.

Обоснование: блоки 1–4 меняются не чаще раза в жизнь — кеш держит их бесплатно; 5–6 меняются
минутами и замыкают system; после core memory промпт и так меняется каждый шаг — смысловой
порядок важнее перестановки 5 и 6.

Резка при переполнении — только наполняемые блоки, в порядке: хвост свежих (7) → записи about
(7, до самой релевантной) → второй кандидат на голос (8) → старый чат (9). Блоки 1–6 и 10 не
режутся: их размер ограничен своими правилами (core 1.5 KB, наследие квотами §7, каталог и
наблюдение — в лимит).

Режимы (ADR-020): `plain` — праймер в блоке 3, ключи `<kind>:<id>`; `masked` — блок 3 пуст,
ключи-handle, правило «не знаешь этот мир» (T-011); свободные тексты (чат, сообщения) идут
через perception (`scrub`), сырые id в промпт не попадают. Ответ шага — StepReply (§5 NETWORK).

## 10. Рефлексия и завещание: вход и выход

Один вид вызова `smart` (NETWORK.md §6), три kind: `birth` (при рождении), `regular` (окно),
`death` (финальная — завещание, T-013). Уровень smart (ADR-023); новых видов вызовов нет.

Вход `ReflectionInput`: serial, kind, events (TriggerEvent с прошлой рефлексии; для death —
последние), notes (note-ы шагов), core_memory, personal_goal, network_goals, cause и
last_action (для death; cause обязателен), inheritance_summary (для birth). Бюджет входа:
birth и regular ≤ 4000, death ≤ 3000 токенов.

```json ReflectionInput
{"serial": 14, "kind": "regular",
 "events": [{"type": "damage.taken", "importance": 4, "event_id": "e-918",
             "ts": "2026-10-17T12:03:40+00:00", "payload": {"from": "ent:zombie", "amount": 3}},
            {"type": "first.seen", "importance": 3, "event_id": "e-921", "ts": "2026-10-17T12:05:12+00:00"}],
 "notes": ["стонущий бьёт на сближении"], "core_memory": "## Цель\nДойти до болота.",
 "personal_goal": "найти глину", "network_goals": ["сеть просит проверить болото"]}
```

Выход — JSON `ReflectionOutput`: personal_goal, core_memory (≤ 1.5 KB, структура §6),
candidates ≤ 3 — готовые кандидаты для `submit_candidate`; для kind=death вместо них will
(2–4 строки, §5). Бюджет выхода: birth и regular ≤ 600, death ≤ 300 токенов. Инварианты
(кандидатов ≤ 3, will 2–4 строки, не пусто) держит схема; связку «kind → поля» и битые части
проверяет вызывающий: T-023 и T-013 отбрасывают по одному, не роняя вызов.

```json ReflectionOutput
{"personal_goal": "найти глину у болота и вернуться до заката",
 "core_memory": "## Цель\nГлина у болота.\n\n## Факты\n- Стонущие у болота идут на свет.\n\n## Сеть\nСовет про факелы принимаю.",
 "candidates": [{"kind": "danger", "claim": "Стонущие у болота идут на свет.",
                 "about": ["ent:zombie"], "evidence_event_ids": ["e-918", "e-921"]}]}
```

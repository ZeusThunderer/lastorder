# lo-work — задачи по очереди

Если ты не ZCode (worker) — остановись, этот скил не для тебя.

Протокол: `docs/agents/coop-protocol.md`. Правила: `CLAUDE.md`, прочитай целиком в начале чата.
Шаблон отчёта: `docs/agents/work/_templates/report.md`. Субагентов не запускаешь: всё делаешь сам.

## Аргументы
- без аргументов — задачи очереди `a` из `dev/tasks.sh --next`, по одной;
- `--lane L` — задачи очереди `L`: везде ниже `dev/tasks.sh --next --lane L …`. Другой чат в это время
  ведёт другую очередь: её задачи и worktree не трогаешь;
- `T-NNN …` — только эти, по порядку.

## Предел чата
Чат заканчивается, когда закрыты 3 задачи (влиты или ждут оператора) или сделано ~150 вызовов
инструментов: каждый вызов заново отправляет весь контекст (ADR-039). Предел пришёлся на середину
задачи — закоммить сделанное и допиши в `report.md` раздел `## Передача · YYYY-MM-DD`: что сделано,
что дальше, что проверить. Затем сводка. Следующий чат продолжит задачу из `in_progress`.

## 0. Проверка
Из корня: `git branch --show-current && git status --short`. Нужны `main` и пустой вывод, иначе
скажи оператору и остановись.

## 1. Взять
`bash dev/tasks.sh --next [--lane L] <id задач, ушедших к оператору в этом чате>` печатает `T-NNN <status>`.
Если вывод пуст, задач нет: переходи к сводке.
- `review` — шаг 4.
- `blocked` — шаг 5, вызов `answer`.
- `in_progress`, `changes`, `ready` — `bash dev/task_worktree.sh T-NNN` печатает путь worktree.
  Отказ — текст отказа в сводку и остановка.

## 2. Работать
- Все команды — в worktree: `cd <wt> && …`. В корне ничего не меняешь. `unionclef/` и `NetTyan/`
  читаешь в корне, только чтение.
- `changes`, `in_progress` после прошлого чата или `main` ушёл вперёд — сначала `git merge main`.
  Прочитай последний раунд `review.md`, «Передачу» в `report.md` и «Заметки надзора» в `task.md`.
  Правки надзора не перетираешь.
- Пишешь только в «Можно трогать». Нашёл что-то вне задачи — запиши в отчёт, не чини.
- На каждый критерий приёмки — тест или команда.
- Стенд общий с другой очередью. Перед `docker compose up/build/restart/stop` и прогоном —
  `bash <корень>/dev/stand.sh lock T-NNN`, после — `unlock`. Занято — делай часть без стенда, повтори
  позже; чужую блокировку не снимаешь. Мир не сбрасываешь.
- Коммиты по ходу: `T-NNN: <суть по-английски>`, последний трейлер `Agent: zcode`. Файлы upstream aw
  (`agent/AGENTS.md`, `agent/shared`, `agent/scripts`, `tools/`) — отдельным коммитом `aw-fix:` / `aw-ext:`.
- Задача неясна или противоречит CLAUDE.md / ADR, нужен выбор пользователя (пресет имени, 4-я черта,
  новый вызов LLM, `descriptions.yml`) или файл вне «Можно трогать» — шаг 5. Догадка здесь — blocker
  на ревью.

## 3. Сдать
1. `bash <корень>/dev/check.sh` и команды из «Проверок». Красное не сдаёшь: чини или шаг 5.
2. `git diff --stat main...HEAD`: нет файлов вне «Можно трогать», отладочного мусора, секретов.
3. Допиши в `report.md` раунд `## Раунд N` по шаблону, до 60 строк, heredoc-ом. В «Проверках» —
   реальный сокращённый вывод, что не прогнал — «не прогонял: причина». Со 2-го раунда — «Ответ на
   ревью»: каждая находка `fixed <sha>` или `disputed: <довод>`. Молча пропущенная находка не закрыта.
4. `status: review` в `task.md` и отчёт — одним коммитом `T-NNN: report round N`.

## 4. Ревью
`bash <корень>/dev/call_supervisor.sh result T-NNN` из worktree, таймаут Bash 600000: вызов идёт
минуты. `high` дописываешь, только если оператор попросил. В конце вывода — `VERDICT: …` и
`cost_usd: …`, их держишь для сводки.

| Вердикт | Что делаешь |
|---|---|
| `accept` | задача влита, worktree больше не трогаешь. Шаг 1 |
| `changes` | прочитай последний раунд `review.md`, статус уже `changes`: `git merge main`, шаг 2 в том же worktree |
| `reject` | `task.md` переписан, статус `ready`. Шаг 1, задача возьмётся заново |
| `blocked` | задача ждёт оператора, причина — в `task.md`. Шаг 1 |
| ошибка или отказ скрипта | второй раз не вызываешь, задача ждёт оператора. Шаг 1 |

## 5. Вопрос надзору
1. Допиши в `report.md` раунд с разделом «Вопросы»: что мешает, где (`файл:строка`, пункт задачи),
   какие варианты видишь.
2. `status: blocked` в `task.md` и строкой ниже frontmatter `Blocked: <одна фраза>`. Закоммить
   сделанное, отчёт и статус: `T-NNN: blocked — <суть>`.
3. `bash <корень>/dev/call_supervisor.sh answer T-NNN`.
   - `answered` — прочитай `## Ответ N` в `review.md` и изменения `task.md`. Статус уже
     `in_progress`: шаг 2.
   - `blocked` — задача ждёт оператора. Шаг 1.

## Экономия вызовов
- Одна команда вместо нескольких: `cd <wt> && … && …`. Коммит с проверкой:
  `git add … && git commit … && git log -1 --oneline`.
- Тесты во время работы — целевые (`uv run pytest tests/test_x.py -q`), перед сдачей — один раз
  `dev/check.sh`.
- Ожидание стенда — `bash <корень>/dev/wait_for.sh <сек> …` одним вызовом. `sleep` и опрос
  `docker logs` в цикле — нельзя.
- Чтение: сначала `rg -n`, потом Read с offset/limit. Большие файлы целиком не читаешь, только что
  записанный файл не перечитываешь. Из `review.md` читаешь только последний раунд.
- Несколько правок одного файла — одним Write или крупным Edit.
- TodoWrite — только если в задаче больше 5 шагов.

## Сводка оператору
Одно сообщение в конце чата:
```
Влито: T-NNN, … (критичное: T-NNN — можно пересмотреть)
Ждут оператора: T-NNN — <причина одной фразой>
Не закончено: T-NNN — передача в report.md
Надзор: N вызовов, $<сумма>
  T-NNN · result|answer · <sha> · VERDICT: … · cost_usd: …
Дальше: новый чат, «возьми задачи»
```

## Нельзя
- Править или коммитить в корне, трогать BOARD и `review.md`, ставить статусы `accepted` и `done`.
- Вызывать `dev/merge_task.sh`, `dev/tasks.sh --sync|--prune`.
- Обходить отказ `call_supervisor.sh` (лимит, «нужен оператор»).

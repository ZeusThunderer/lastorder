# lo-call-supervisor — вызвать надзор без оператора

Если ты не ZCode (worker) — остановись, этот скил не для тебя.

Протокол: `docs/agents/coop-protocol.md`, раздел «Вызов надзора из ZCode».

## Когда можно
Вызов — твоё решение. Он нужен, чтобы не ждать оператора там, где всё идёт штатно.
Вызывай, только если выполнено всё сразу:
- у задачи `criticality: normal`, и ни «Можно трогать», ни diff не задевают критичные зоны из протокола
  (скрипт проверит и откажет сам);
- нет открытых вопросов и `disputed` к надзору — спор решает оператор;
- проверки зелёные, worktree задачи чистый, и вызов идёт **из него** (`.worktrees/T-NNN-<slug>`), не из корня;
- лимит не исчерпан: 2 headless-проверки плана и 3 headless-проверки результата на задачу.

Не вызывай, если сомневаешься, критично ли это. Тогда сдай задачу обычным путём (`lo-submit`)
и дождись оператора.

## План (по желанию, до кода)
Полезен, когда задача не тривиальна или затрагивает несколько модулей.
1. Статус `in_progress`. Допиши в `report.md` раздел `## План N · YYYY-MM-DD`: шаги, файлы, тесты
   на каждый критерий приёмки, риски.
2. Закоммить: `T-NNN: plan N`, трейлер `Agent: zcode`.
3. `bash dev/call_supervisor.sh plan T-NNN`.
4. Прочитай `## План N · … · headless` в `review.md`:
   - `ok` — работай по плану;
   - `revise` — поправь план (`## План N+1`) или сразу учти находки `P<N>-<k>` в работе;
   - `blocked` — остановись и передай оператору.

## Результат (вместо ожидания оператора)
1. Выполни `lo-submit` до конца, статус `review`.
2. `bash dev/call_supervisor.sh result T-NNN`.
3. Последняя строка вывода — `VERDICT: …`:
   - `accept` — надзор смержил ветку в `main` (`dev/merge_task.sh`), задача `done`. Worktree остаётся,
     в нём больше не работай, его уберёт надзор (`dev/tasks.sh --prune`);
   - `changes` — `lo-take` (статус `changes`), раунд доработки, затем снова этот скил или ожидание оператора;
   - `blocked` — остановись, скажи оператору причину из `task.md`.

## Фиксация
- Каждый вызов — строка в разделе «Вызовы надзора» текущего раунда `report.md`:
  `YYYY-MM-DD · plan|result · <sha> · VERDICT: … · cost_usd: …` (cost — из вывода скрипта).
  Закоммить её следующим своим коммитом.
- Скрипт вернул ошибку, а не вердикт, — второй раз не вызывай, скажи оператору.
- Скрипт отказал из-за критичности или лимита — не обходи. Сдай задачу оператору через `lo-submit`.

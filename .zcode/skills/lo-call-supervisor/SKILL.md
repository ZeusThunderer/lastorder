# lo-call-supervisor — вызвать надзор без оператора

Если ты не ZCode (worker) — остановись, этот скил не для тебя.

Протокол: `docs/agents/coop-protocol.md`, разделы «Вызов надзора из ZCode» и «Эскалация оператору».
В конвейере (`lo-run`) `result` и `answer` вызывает диспетчер, исполнитель — только `plan`.

## Когда можно
Вызов — твоё решение, для любой задачи, критичной тоже. Нужно всё сразу:
- проверки зелёные, worktree задачи чистый, и вызов идёт **из него** (`.worktrees/T-NNN-<slug>`), не из корня;
- лимит не исчерпан: 2 плана, 3 результата и 2 ответа на задачу (скрипт проверит сам).

Спор `disputed` и вопросы тоже решает headless-надзор. К оператору задача идёт, только если
надзор поставил `Blocked: нужен оператор`.

## Как вызывать
Из worktree задачи, копией скрипта из **корня** (копия в ветке может быть старше `main`):
`bash <корень>/dev/call_supervisor.sh plan|result|answer T-NNN <effort>`. Модель не выбираешь —
всегда Opus. Effort — `low`, `medium` или `high` по таблице в протоколе; `xhigh` и `max` не
используются. По умолчанию `medium`, критичной задаче тоже (`low` скрипт поднимет до `medium`);
`high` — только исключения из таблицы, с причиной в «Вызовах надзора». Размер diff — `git diff --shortstat main...HEAD`,
раунд — по `report.md`. Строка `VERDICT: …` стоит в конце ответа, последняя строка вывода —
`cost_usd: … · effort: …`.

## План (по желанию, до кода)
Полезен, когда задача не тривиальна или затрагивает несколько модулей.
1. Статус `in_progress`. Допиши в `report.md` раздел `## План N · YYYY-MM-DD`: шаги, файлы, тесты
   на каждый критерий приёмки, риски.
2. Закоммить: `T-NNN: plan N`, трейлер `Agent: zcode`.
3. `bash <корень>/dev/call_supervisor.sh plan T-NNN <effort>`.
4. Прочитай `## План N · … · headless` в `review.md`:
   - `ok` — работай по плану;
   - `revise` — поправь план (`## План N+1`) или сразу учти находки `P<N>-<k>` в работе;
   - `blocked` — остановись: задача ждёт оператора.

## Результат (вместо ожидания оператора)
1. Выполни `lo-submit` до конца, статус `review`.
2. `bash <корень>/dev/call_supervisor.sh result T-NNN <effort>`.
3. Вердикт:
   - `accept` — надзор смержил ветку в `main` (`dev/merge_task.sh`), задача `done`. Worktree остаётся,
     в нём больше не работай, его уберёт `dev/tasks.sh --prune`;
   - `changes` — `lo-take` (статус `changes`), раунд доработки, затем снова этот скил;
   - `reject` — надзор переписал `task.md`, статус `ready`: начни задачу заново по новой постановке;
   - `blocked` — остановись, скажи оператору причину из `task.md`.

## Вопрос (после `lo-blocked`)
1. Статус `blocked`, вопросы в «Вопросах» раунда `report.md`, всё закоммичено.
2. `bash <корень>/dev/call_supervisor.sh answer T-NNN <effort>`.
3. `answered` — прочитай `## Ответ N` в `review.md` и изменения `task.md`, статус уже `in_progress`,
   продолжай работу. `blocked` с «нужен оператор» — остановись.

## Фиксация
- Каждый вызов — строка в разделе «Вызовы надзора» текущего раунда `report.md`:
  `YYYY-MM-DD · plan|result|answer · <sha> · VERDICT: … · cost_usd: …` (cost — из вывода скрипта).
  Закоммить её следующим своим коммитом.
- Скрипт вернул ошибку, а не вердикт, — второй раз не вызывай, скажи оператору.
- Скрипт отказал из-за лимита или «нужен оператор» — не обходи.
